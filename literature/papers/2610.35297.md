## Question

Within the same repository and at equal change size, do pull requests that a developer and a coding agent
work on differ from other pull requests in how often and how they change tests, in the structure and
smells of the tests, and in code coverage (Abstract, §1)?

## Findings

### F1 · observation · agent-pr-test-inclusion · E3
- practice: agent-supported PRs (a branch prefix, label, author or commit author of one of five agents) compared with PRs without such a trace, inside the same repository, with a mixed-effects model with a random intercept and slope per repository and the PR's changed Java lines as control (§4.2.3, §4.3).
- claim: "within the same repository and at equal size, the odds that an agent-supported PR changes test code are 1.65 times those of a human-authored one" (§1).
- evidence: in a typical repository 55.0% of agent-supported PRs change test code against 45.8% (+9.2 pp, OR 1.65). Among PRs that change both test and production code, tests take +5.8 pp of changed lines (OR 1.26) and +2.5 pp of changed files (OR 1.12). Among test PRs, +2.9 pp more are test-only (OR 1.35). All four ORs significant after Holm-Bonferroni (§5.1). At 50 lines the gap is 56.4% against 43.8% (§5.1). Raw share higher for agents in 272 of 391 repositories, lower in 114 (§5.1).
- effect: helps
- reader: observational; nobody assigned the agent. The paper says developers may delegate "well-scoped, easily testable, or greenfield tasks" and the models do not adjust for task type (§6.5). Human-authored is "primarily human": agent use without a trace is in that group (§4.1). The unit is a PR in which developer and agent both took part, so the effect is the pair's, not the agent's (§6).

### F2 · observation · project-composition-confounds-pooled-comparison · E3
- practice: the same PRs compared pooled across all repositories with no size or repository control, against within each repository (§5.1, Table 4).
- claim: "how the comparison is made determines what it shows"; pooled comparisons "conflate agent behavior with agent adoption" (§1, §6.4).
- evidence: pooled, 60.1% of agent-supported and 59.4% of human-authored PRs change test code; test-only share of test PRs 15.2% against 16.6%; RF 37.3% against 39.3%; RLOC 51.7% against 52.7% (Table 4). Within repositories the same outcomes favour agents (F1). Agent-supported PRs are concentrated in repositories where PRs change test code less often (§5.1). Agent PRs are larger (median 93 against 52 changed Java lines, §4.2.7) and test-only agent PRs larger (161 against 104 lines, §5.1).
- effect: mixed
- reader: the contrast is between two analyses of one data set, not between conditions, so E3. It shows that this study's own earlier pooled design (6,582 agent against 3,122 human PRs, §1) would have missed the difference. Which of the two analyses is closer to the truth is not testable here; the within-repository one has the stronger argument.

### F3 · observation · agent-pr-adds-rather-than-maintains-tests · E3
- practice: the same within-repository comparison, for the type of test change in PRs that change tests: add a test, modify an existing one, delete one, by whether the test is linked to the PR's production changes (§4.3.2, §5.2).
- claim: "agent-supported PRs add new tests more often, while human-authored PRs more often modify and delete existing ones" (§5.2).
- evidence: Table 5, odds ratios for agent against human. Add 1.50, 1.56, 1.58; modify 0.70, 0.76, 0.73; delete 0.51, 0.77, 0.61 (linked tests, unlinked tests in mixed PRs, test-only PRs). All nine significant after Holm. In a typical repository: +7 to 10 adds, 5 to 8 fewer modifications, 1 to 4 fewer deletions per 100 PRs (§5.2). Co-evolution with production code differs little: 57.5% against 55.1%, OR 1.12, padj = 0.034 (§5.2). Agents add more in an estimated 81-83% of repositories and modify more in 26-31% (§5.2). No evidence that additions and modifications depend on context (chi2 0.21 and 1.16, padj = 1.000); the deletion gap is smallest for linked tests (chi2 10.88, padj = 0.013).
- effect: mixed
- reader: observational, no task-type control. The explanations (adding is self-contained, agents instructed to add tests, developers delegate test-adding work) are "plausible but untested" (§6.2). The paper did not check whether linked deletions removed the tested method (§5.2). Merged PRs only, so changes made in review are credited to the PR (§6.5).

### F4 · observation · agent-test-structure-matches-project · E3
- practice: structure of the test methods added by agent-supported PRs, measured with Hamster, compared with human-authored ones of the same length in the same repository (§5.3, Table 6).
- claim: "the tests that agent-supported PRs add differ little in structure from those that developers write" (§5.3).
- evidence: no difference on 8 of 9 outcomes (padj = 1.000). Assertions 2.39 against 2.36; call-assertion sequences 2.24 against 2.19; focal classes 1.35 against 1.36; focal methods 1.48 in both; conditional logic OR 0.98; mocks OR 0.85 (CI 0.61-1.19). Methods slightly shorter, 12.1 against 12.5 lines (GMR 0.97, CI 0.95-0.99, not adjusted). Count intervals lie within about 6% of the human mean (§5.3). In test-only PRs agent tests have more call-assertion sequences (RR 1.32, CI 1.15-1.52). Repository variation is larger than the group difference; tau is 0.09 to 0.28 for counts (§5.3).
- effect: none
- reader: "no difference detected" is not equivalence; the authors set no equivalence margin in advance and say so (§5.3). Dispersion is misspecified for FocalMethods and the mock model lacks the PR term, so those intervals may be too narrow (Model fit, §5.3). The authors' reading that agents follow each project's conventions is one of several they list, including developers steering and reviewers enforcing.

### F5 · observation · agent-test-oracle-presence · E3
- practice: whether an added test method has an assertion in its own body (an oracle), agent-supported against human-authored PRs in the same repository (§5.3).
- claim: it is "the only structural characteristic on which the two groups differ significantly" (§5.3).
- evidence: OR 1.71 (CI 1.29-2.26, padj = 0.001), by context OR 1.82, 1.61, 2.42. Predicted share with an oracle 99.77% against 99.60%; in the raw sample 6.4% of agent-added methods lack one against 10.6% of human-added (§5.3). Direction holds in an estimated 68% of repositories, with 12 repository intervals entirely above 1 and none below (§5.3).
- effect: helps
- reader: the gap sits in a few PRs that add many oracle-free tests; repositories and PRs explain 84% of the variation. A method that delegates checks to helpers counts as having no oracle, and humans do that more often (24.8% against 20.6%), so part of the gap may be a helper-style difference (§5.3).

### F6 · observation · agent-test-modification-assertion-changes · E3
- practice: assertions added or removed when a PR modifies an existing test method, agent-supported against human-authored, same repository and edit size (§5.3, Table 6).
- claim: when agents modify tests "they more often add at least one assertion" and the paper detects no difference in removing one (§5.3).
- evidence: AddsAssertions 23.5% against 19.6% (OR 1.31, CI 1.09-1.57, padj = 0.007); RemovesAssertions 14.0% against 13.9% (OR 1.01, CI 0.85-1.20, padj = 0.941). Agents add assertions more often in an estimated 64% of repositories and remove them more often in 50% (§5.3).
- effect: helps
- reader: an assertion that is rewritten counts as one removed and one added, so "adds" includes rewrites; the paper says so and says it cannot tell a weaker assertion from a stronger one (§5.3). The finding is a count of syntactic changes, not of test quality.

### F7 · observation · agent-test-loses-oracle-when-modified · E3
- practice: a modified test method that ends with no explicit assertion, the paper's "most direct syntactic form of weakening", agent-supported against human-authored (§5.3).
- claim: "Our data therefore show neither that agents weaken the tests they modify more often than developers, nor that they do not" (§5.3).
- evidence: 0.79% of test methods modified by agent-supported PRs (458 methods) against 0.49% of those modified by human-authored PRs (1,658). The pooled-repository model gives OR 0.008 (CI 0.001-0.056), but tau is 6.29; agents lose the oracle more often in an estimated 22% of repositories, and 7 repository intervals lie entirely above 1 against none below (§5.3, Table 6).
- effect: mixed
- reader: the paper itself declines to read the model's OR as evidence that agents lose oracles less often. The raw rates run the other way from the model. Model fitted without the PR term, so intervals may be too narrow; losses may be refactorings into helpers (§5.3). Graded E3 for the comparison it makes, with no support for either direction.

### F8 · observation · agent-test-smell-evolution · E3
- practice: change in the count of test smells (JNose) caused by a PR, at PR level and at test-method level, agent-supported against human-authored (§5.4, Table 7).
- claim: "evidence is weaker than for the previous research questions"; PR-level estimates are borderline and "not reproduced at the level of individual test methods" (§5.4).
- evidence: overall Smell Delta, additions beta = -8.271 (p = 0.024), modifications beta = 10.829 (p = 0.046). After Holm over the four aggregate tests neither is significant, so "indicative" (§6.5). Only General Fixture (beta -0.598, padj 0.004) and Exception Catching Throwing (-0.458, padj 0.011) differ after correction, both on additions; none on modifications. Method level: modifications beta = -0.0175 (p = 0.101), additions 0.0535 (p = 0.229).
- effect: mixed
- reader: the authors treat these as hypotheses (§6.3). The PR-level models use an identity link on heavy-tailed signed differences and may be driven by a few large contributions (§6.5). The p-values for the two aggregates are not adjusted in the main analysis, which is why they pass.

### F9 · observation · agent-pr-coverage-of-production-changes · E3
- practice: line coverage of the production code that a test PR changes, measured with JaCoCo by running each project's suite before and after the PR, agent-supported against human-authored, in the 95 repositories that could be built (§4.3.5, §5.5).
- claim: "we detect no difference in how well agent-supported and human-authored PRs cover their production changes" (§5.5).
- evidence: mixed PRs, coverage of changed classes 50.7% against 49.5% (+1.2 pp, OR 1.07, padj = 1.000); covered share of new lines 51.3% against 48.1% (+3.2 pp, OR 1.14, padj = 1.000, CI -2.6 to +8.9 pp). Contributed tests reach 77.4% against 75.4% of covered new lines (Table 9, §5.5). Estimated agents higher in 57% of repositories. 9 robustness variations change no conclusion (§5.5).
- effect: none
- reader: only PRs that also change tests are in the analysis; production-only PRs, where agents may do worse, are not (§5.5). The authors say the data "cannot establish that the two groups are equivalent". Intervals of the two largest models are not relied on because of misspecified dispersion (§5.5 Model fit). The paper reports that agent test PRs touch classes that were already better covered (+0.49 logit, p = 0.007).

### F10 · observation · agent-test-only-pr-narrow-coverage · E3
- practice: coverage of the classes that the tests of a test-only PR execute, agent-supported against human-authored (§5.5, Table 9).
- claim: in test-only PRs "agents' tests cover less of the code they exercise", and the result "should be confirmed on a larger sample" (§5.5).
- evidence: 44.5% against 55.6% (-11.1 pp, OR 0.62, padj = 0.032). Rests on 142 PRs in 45 repositories; only 11 repositories hold both groups (28 agent, 35 human PRs), where the raw means are 30.4% against 43.5% and agents are lower in 7 of 11. Similar amount of test code (median 58 against 61 lines), covered lines median 173 against 389. In 7 robustness variations OR 0.55-0.64, all p < 0.05 (§5.5). Gap at 10 lines -16.1 pp; the size interaction is not significant (p = 0.123).
- effect: hurts
- reader: the only significant difference in the coverage family, on 11 repositories with both groups; the authors call it the least precise finding. Verification dropped more agent test-only PRs than human ones (29.9% against 16.2%); the result holds when all PRs are kept (OR 0.55). Coverage does not measure fault detection (§6.3).

### F11 · observation · repository-heterogeneity-of-agent-test-difference · E3
- practice: the spread of the agent against human difference between repositories, from the random slope of each model (§5.1, §5.2, §6.1).
- claim: "statements such as 'agent-supported PRs test more' hold on average, not necessarily in a given project" (§6.1).
- evidence: for each outcome in RQ1 the spread tau exceeds the average effect. OR for IsTestPR: 95% of repositories expected between 0.24 and 11.33; agents higher in an estimated 70%. The more a repository already tests, the smaller the difference (correlation -0.28 to -0.59); median gap +13.8 pp in the middle third by baseline, +5.6 in the lowest, +2.7 in the highest (§5.1). For additions the correlation is -0.91 (§5.2).
- effect: mixed
- reader: the percentage scale shrinks differences near 0% and 100%; the authors say the negative correlation also holds on the log-odds scale. Moderators they name (suite maturity, CI strictness, review, instruction files, which agent) are not tested (§6.1).

## Limits stated by the authors

- Observational: associations, not causal effects; models adjust for repository and size but not for task type or difficulty (§6.5).
- Agent use is inferred from traces; agent use with no trace sits in the human-authored group. The direction of the resulting bias is uncertain and the authors do not assume it is conservative (§6.5).
- Only merged PRs, so results show what projects accept after review (§6.5).
- Neither smells nor coverage measure whether tests detect faults (§6.5).
- Java only; coverage only for repositories that build with Maven or Gradle; 391 of 22,932 repositories with agent activity; Codex, Copilot and Claude Code supply almost all agent PRs; period January 2025 to April 2026 (§6.5).
- Non-significant results are not evidence of equivalence (§6.5).

## Reader's notes

- Every finding is observational and graded E3: the within-repository comparison with a size control is the strongest design in the paper, and it still has no randomisation, no task-type control and no ablation.
- "Agent-supported" mixes five agents and any degree of agent involvement; PRs matching several agents are counted for each (§4.2.7). Devin has 9 and Cursor 292 PRs, so the results speak for Codex (7,067), Copilot (5,764) and Claude Code (5,387). No result is split by agent in the parts read.
- 40% of agent-supported PRs were merged in the last two months of the window (§4.2.7); the data are dominated by recent agent versions, which the paper does not name.
- The median repository has 3 stars, 28k Java lines, 3 PR authors and is 1.3 years old (§4.2.7). The projects are small and young; the paper does not test whether the result holds for large mature ones.
- The agent-supported group merges much faster (median 0.6 against 9.7 hours, §4.2.7), which hints at less review time. The paper does not draw on it.
- Whether the repositories hold instruction files is named as a candidate moderator and was not measured (§6.1).
- The practitioner advice in §6.4 (ask agents to update linked tests; check that a modified test keeps an assertion) follows from F3, F6 and F7 and is not tested.
