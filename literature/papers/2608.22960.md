## Question

Do the three kinds of process signal used to evaluate coding agents (what the agent does next, how uncertain the task is, which step caused the outcome) measure the same thing? Studied with a replay-based causal estimator on file localization (§1, §4).

## Findings

### F1 · observation · next-action-driven-by-tool-output-provenance · E3
- practice: predict the agent's next file from the paths in its most recent tool output, against a code-dependency-graph ranking and a repository-frequency ranking, on steps that go to a file not visited before (§4.2, Table 3).
- claim: "the dominant predictor of a coding agent's next action is its own execution provenance, not the code dependency graph" (§4.2).
- evidence: 341 first-visit decision points. Top-3 hit rate 0.326 [0.276, 0.375] for last-output provenance against 0.058 for a strengthened graph predictor and 0.072 for repository frequency (Table 3). Paired gain over the graph predictor +0.136 at top-3 and +0.259 at top-10 (§4.2). 0.689 of first-visit targets had been mentioned in earlier tool output (§4.2). Provenance uses 3.46 effective candidates against 1,719.13 for the graph (Table 3). Using the whole observation history instead of the last output adds +0.011 at top-3 and raises candidates from 3.46 to 18.8 (C.2).
- effect: helps
- reader: E3: predictors compared on the same points, no intervention on the agent. One agent and model on file localization in Python repositories. The graph predictor is the authors' own construction, strengthened by them (B.3); only 46.2% of agent objects resolve to a graph node (§4.3).

### F2 · observation · code-graph-as-scoping-prior · E3
- practice: compare the agent's step order against a within-episode permutation null that keeps the visited set and destroys the order; measure the visited set's edge density in the code dependency graph against random same-size sets (§4.3, Figure 4).
- claim: "the code dependency graph is useful as a scoping prior, not as a next-step transition model" (§4.3).
- evidence: one-hop lift 0.94, three-hop 1.02, same-community 1.01 against the null (§4.3); observed adjacent one-hop rate 0.284 against 0.301 expected (C.3). Visited-set edge density 0.269 against 0.0087 for random sets, 30.9 times (§4.3). Leakage-controlled rank quantile of unvisited gold files 0.049 [0.021, 0.084] on n = 39 instances, and 0.103 seeded from an early prefix on n = 54 (§4.3, C.3).
- effect: mixed
- reader: E3: a null built from the same episodes, not a controlled treatment. The graph helps on where the agent works and not on how it moves. The gold-ranking samples are small (n = 39 and n = 54).

### F3 · observation · reuse-rate-permutation-null · E3
- practice: judge agent reuse of tools and objects against a within-episode permutation null rather than from raw reuse rates (§4.4).
- claim: raw reuse rates "are arithmetic consequences of vocabulary size and trajectory length"; immediate object repetition, temporal clustering and recency or frequency bias are real behaviour (§4.4).
- evidence: tool reuse 79.1% and object reuse 41.6% carry no information, because the null's standard deviation is exactly zero (§4.4, C.3). Objects repeated in adjacent steps 1.83 times the null rate (permutation p ~ 10^-141); previous frequency 1.70 times and recency rank 1.74 times expectation among revisits. Tool self-repetition lift 1.02, p = 0.51; tool transition mutual-information lift 1.13 (§4.4). 487 episodes (C.3).
- effect: mixed
- reader: E3 against a null on one agent. The raw rate is uninformative and the temporal pattern is not, so the direction is split by measure.

### F4 · observation · task-level-execution-variance · E3
- practice: replay 8 continuations from each of 190 prefixes (1,901 replays, 12.7 hours) and ask which factor explains the variance of the outcome across replays (§4.1, §4.5).
- claim: "execution uncertainty resides primarily at the task level rather than at the step level" (§4.5).
- evidence: instance identity explains 0.640 of residual replay variance against a permutation null of 0.196 (p = 5 x 10^-4); step position rho = -0.131 and tool type p = 0.65 explain nothing (§4.5, Figure 5). 50.5% of segments have replay variance exactly zero, and 22.9% of episodes have every estimated contribution zero (§4.5).
- effect: mixed
- reader: E3: variance partition, no control. The authors' own estimator on 38 instances; the m = 8 replays are coarse, which they state. Variance is first residualised against the mean because the outcome is bounded (§4.5).

### F5 · practice · replay-based-step-attribution · E3
- practice: estimate each step's causal effect on the final outcome by replaying the agent from a rebuilt prefix, observationally where the policy still varies and by substituting an alternative action where it does not (SCAE, §3.1, §4.5).
- claim: formal identification of step effects does not give measurability at feasible replay cost: "we cannot certify which step mattered in any individual episode" (§4.5, §5).
- evidence: of 190 intervention-estimated step effects, 5.3% reach uncorrected p < 0.05 (the nominal chance rate) and 0 survive BH-FDR at q = 0.10 (§4.5). 1,901 replays over 12.7 hours (§4.5). Environment replay was byte-identical over 100 actions, 3 re-executions each, and context compaction occurred in 0 rollouts (§4.1, B.2).
- effect: hurts
- reader: E3: the estimate is compared with its chance rate, with no other step-attribution method on the same episodes. The authors built SCAE; the failure at m = 8 may reflect their replay budget (they argue the cause is task-level variance, §5). Entropy probes used 4 to 6 replays per point (B.2).

### F6 · practice · llm-judge-failure-attribution · E4
- practice: an LLM judge picks the step to blame for an episode's outcome; the same judge and rubric run once on the full trace with the outcome shown and once on the first 60% of the trace with the outcome withheld (§4.6, B.2).
- claim: a full-trace judge "conditions on descendants of the scored step", which displaces its verdict later; the bias is in the evaluation mechanism, not in noise against a causal reference (§4.6).
- evidence: verdict moves +0.537 later in normalised position [+0.459, +0.610], later in 59 of 70 episodes with 10 ties, sign test p = 1.1 x 10^-16 (§4.6, Figure 6). Mean position 0.214 prefix-only against 0.751 full-trace, median shift +0.667 (C.9). 3 judges on 23 common episodes: +0.533, +0.434, +0.394, all with sign test p below 10^-4; no detectable heterogeneity, p = 0.181 (Table 5).
- effect: hurts
- reader: E4 by design: information set manipulated, same episodes, same judge. The truncation fraction was fixed in advance after an earlier design, truncating before the step the estimator chose, was found to force a positive shift (B.2, D.2). The judge prompt is the authors'; the 3-judge replication has 23 episodes and a low-powered heterogeneity test (§5). The blamed step is not checked against a certified causal answer, so "later" is read as bias because of the design, not because a correct step is known.

### F7 · observation · llm-judge-semantic-relevance-selection · E3
- practice: none applied; the full-trace judge's top step is characterised against steps that touch or reveal a gold file, and against five rules that use no language model (§4.6, Table 4).
- claim: what the judge selects is "semantically enriched, downstream-informed relevance" and not demonstrably causal contribution (§4.6).
- evidence: 0.900 of the judge's verdicts [0.829, 0.971] fall on gold-provenance steps against a 0.413 baseline; inside that class the verdict is late, 0.746 against a uniform null of 0.5 (Figure 6, §4.6). Best zero-LLM rule, last gold-provenance step, agrees with the judge on 0.243 of episodes against 0.053 by chance (Table 4). Enrichment is significant in 2 of 3 judges, heterogeneity p = 0.044 (Table 5).
- effect: mixed
- reader: E3, n = 70 episodes. The selection is characterised, not compared with a correct answer. The content of what judges select differs across models (Table 5), so this transfers less than F6. A pre-registered judge-versus-estimator disagreement of 97.1% (68 of 70) was withdrawn as uninformative because the reference is noise (C.10, D.2).

### F8 · practice · action-entropy-as-uncertainty-proxy · E3
- practice: use the action model's predictive entropy, which costs no replays, as a stand-in for replay-based execution uncertainty (§4.5).
- claim: "zero-cost predictive entropy from the action model does not proxy replay-based execution uncertainty" (§4.5).
- evidence: Spearman rho = -0.088 [-0.244, +0.062] at step level and -0.219 [-0.518, +0.126] at instance level. A control quantity that should respond gives rho = -0.425 [-0.695, -0.102] (§4.5, B.3). A threshold-defined exception, high-entropy steps with more significant effects, did not replicate: difference +0.056 [-0.008, +0.135] (C.5).
- effect: none
- reader: E3: two measures correlated, with a positive and a negative control, which makes the null interpretable. 38 instances, and the CIs include sizeable negative values, so "none" means none detected.

### F9 · practice · pre-execution-outcome-forecast · E2
- practice: predict the localization outcome before the agent runs from 7 pre-execution covariates of the issue and repository (issue length, named files, traceback, error terms, repository size, identifier counts), with a Bayesian logistic model (C.7, B.2).
- claim: the forecast "does not forecast the outcome"; reported as a negative result (Figure 1 caption, C.7).
- evidence: leave-one-repository-out AUROC 0.481 over 12 repositories, base rate 93.99%; ECE 0.015, Brier 0.058; a flat risk-coverage curve (C.7). The pre-registered usefulness threshold was AUROC 0.60 (D.2, Table 12).
- effect: none
- reader: E2: one number against a chance level, no other forecaster. At a 93.99% base rate there are about 30 failing episodes (reader's arithmetic), which limits any forecast. Covariates were chosen by the authors with no search (C.7).

### F10 · observation · next-action-predictability-by-step-type · E2
- practice: none applied; next-action prediction accuracy is split by the kind of step and by what the agent just did (§4.2, Tables 1 and 2, Figure 3b).
- claim: "query generation, not path selection, is the hard part of next-action prediction"; prediction is trustworthy after a search and not after a read (§4.2).
- evidence: top-3 by object type: handler steps (27.3% of steps) 0.582, path steps (51.1%) 0.185, novel free-text query steps (21.6%) 0.029 (§4.2). By last step: after a search 0.469 (n = 228, ECE 0.0125), after a read 0.160 (n = 206), after a directory listing 0.057 (n = 35) (Table 2). A low predicted candidate count is the worst-calibrated stratum (Table 2). After a parser defect that affected 75.3% of query objects was repaired, the best query model reached top-3 0.076 at coverage 0.181, a net change of +0.002 from the original (C.4). Routing the candidate set on the predicted tool raised top-1 from 0.109 to 0.150 and cut effective candidates from 39.93 to 12.85 (Table 1, §4.2).
- effect: mixed
- reader: E2: descriptive splits on one agent, with no alternative to compare against. A search-heavy localization task makes these splits specific to this task.

## Limits stated by the authors

- Task scope is file localization; process structure in code editing, patch synthesis or open-ended tool use may differ (§5).
- The step-level causal estimate is identified formally but empirically weak: 0 of 190 survive FDR (§5).
- Values are estimated at selected prefixes with a finite number of replays, so contributions are segment approximations; more replays are unlikely to remove the limit (§5).
- Exogeneity of decoding noise and transferability of substituted actions are assumptions that traces cannot test (§5).
- The judge replication has 3 models and low power; the content of judge selection is unstable across models (§5).
- The task, policy and model uncertainty decomposition is validated only on a synthetic process (§5).
- Only 46.2% of agent objects resolve to dependency-graph nodes (§5).

## Reader's notes

- The paper scores no coding task. It scores how well measurement procedures work on file-localization episodes; no finding is about patch success. The localization success rate under the criterion gold files are a subset of named files is 93.99% (Table 10), with a 15.23% exact-set-equality rate that the authors attribute to the agent naming test files (D.1).
- One agent (Codex CLI) and one model (gpt-5.5) generate all trajectories; the judges include 2 other models, run on 23 episodes (Table 5).
- The corpus is 46% django (Table 10), so repository-level generalisation is thin; leave-one-repository-out is used for predictors.
- The authors report their own errors: a parser defect (C.4), a retired pre-registered criterion (C.10) and four pre-registered entries that did not hold (Table 12). This raises confidence in the reported nulls. It does not make the nulls independent: the replay count was chosen by the authors, and a null at m = 8 is not a null at larger m.
- The paper's practical reading for an agent builder is narrow: a full-trace LLM judge asked "which step caused this" is biased toward late, gold-related steps, and a prefix-only judge differs from it by about half the trace position.

## Discrepancies

- §4.6 text gives collider displacement of +0.534, +0.435 and +0.394 for the three judges; Table 5 gives +0.533, +0.434 and +0.394.
- Collider isolation is stated as +0.537 over 70 episodes with 10 ties (§4.6, Figure 6); Table 12 gives +0.537 over n = 60, the non-tied count.
- D.2 says the collider-isolation magnitude implies descendant conditioning accounts for most of the displacement; this is an interpretation, since the manipulation shows displacement and not its share.
