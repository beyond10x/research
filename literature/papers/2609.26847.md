## Question

How often is a merged agent PR followed by a fix within 30 days, compared with merged human PRs in the
same repositories, who authors the fix, and does anything visible at merge time mark the PRs that need
one (§1)?

## Findings

### F1 · observation · autonomous-agent-pr · E3
- practice: an agent product opens and gets merged a PR in a popular repository; the later fix rate is compared with merged human PRs from the same repositories over the same window. A fix is a later PR within 30 days that is typed fix, co-edits a non-boilerplate file of the merged PR, and is confirmed as a direct fix by a human or an LLM judge (§4.1.1).
- claim: "agent merges attract verified fixes at 1.62 times the human odds" (§4.1.2).
- evidence: shared window, Table 2: 3.68% of agent merges (74 of 2,012) against 2.34% of human merges (95 of 4,063) carry a verified fix; Mantel-Haenszel odds ratio over 218 repositories 1.62 (95% CI 1.10-2.39, p = 0.015), risk ratio 1.59. Candidate fixes: 20.9% against 14.7%, odds ratio 1.41 (1.19-1.68). Own-window agent rate: 4.5% verified (203 of 4,505), by agent in Table 1: Codex 5.5, Cursor 5.2, Devin 3.7, Copilot 3.5, Claude Code 3.2 (n = 63). Half of the 30-day incidence arrives in the first week (§4.1.2, Figure 3).
- effect: hurts
- reader: E3: agent and human PRs are not assigned and the human PRs cover a shorter window (to 2025-06-28); matching is by repository only, so task type, PR size and risk differ. The verified rate is a floor (file co-location, 30 days, fix-typed PRs only, §6). The lower bound of the odds ratio is 1.10 and only 218 repositories have both cohorts. Claude Code and Cursor counts are too small to compare (63 and 153 PRs).

### F2 · observation · same-agent-fixes-own-merged-pr · E3
- practice: nothing applied; who opens the verified fix PR of a merged agent PR was classified as the same agent, a human or another agent (§4.2.1).
- claim: "Agents largely fix their own merges by 69.6 %"; human merges are fixed by humans 89.1% of the time, so fixing "stays largely within the authoring population" (§4.2.2).
- evidence: Table 3, 263 verified agent-merge pairs: 69.6% same agent, 27.4% human, 3.0% another agent. By agent: Copilot 95.0% (n = 40), Cursor 87.5% (n = 8), Devin 72.7% (n = 88), Codex 59.2% (n = 125, humans 38.4%), Claude Code 0.0% (n = 2). Human baseline, 110 pairs: 89.1% human, 10.9% agent.
- effect: helps
- reader: the paper reads this as agents finishing their own job; the data are shares with no outcome measured, so the effect value is the authors' reading (schema proposal P9). Codex commits carry no marker (§4.3.1), but the PR-level split is by who opened the PR, so it is not affected. Per-agent shares rest on small n for Cursor and Claude Code.

### F3 · observation · agent-share-of-commits-on-fix-prs · E3
- practice: nothing applied; every commit of the verified fix PRs was classed as agent, automation or human by author login and commit-message markers (§4.3.1).
- claim: "who opens the fix PR is, on marked evidence, also who writes it", and agents author a higher share of commits on fix PRs than on their merged PRs in general (§4.3.2).
- evidence: Table 4, 123 verified fix PRs excluding Codex: average agent share per PR 87.4%, 76.4% of PRs agent-authored throughout, median 2.0 commits; human-opened fix PRs: 0.8% over 124 PRs and 554 commits. Table 5, all 3,940 merged agent PRs excluding Codex: 78.8% average share, 54.1% all-agent. Per agent on fix PRs: Devin 92.0%, Copilot 86.6%, Cursor 79.1%.
- effect: helps
- reader: E3: the fix PRs are compared with all merged PRs, which are a different population. Codex, the largest cohort, is excluded because it does not sign commits (fewer than 2% carry a marker, §4.3.1), so the 87.4% and 76.4% cover four agents only; the abstract states 76.4% without that limit. Shares are lower bounds by construction. Same schema misfit as F2.

### F4 · practice · llm-judge-validated-against-human-labels · E3
- practice: label candidate fix pairs with an LLM judge (Claude Opus 4.8, temperature 0), developed on the 45 pairs two annotators agreed on, then check it on 50 new agent pairs and 50 new human pairs relabelled by the second author (§4.1.1).
- claim: the judge "substantially matches the human" and has Direct-fix precision of 90% on both cohorts (§4.1.1).
- evidence: human-human binary agreement 45 of 50, Cohen's kappa 0.77; judge-human kappa 0.78 on agent pairs; precision 27/30 = 90% on each cohort, pooled 54/60 = 90% (Wilson 95% CI 80-95%). On the three-way label the kappas fall to 0.60 (human-human) and 0.46 (judge-human) (§6). 2,510 agent pairs and 2,206 human pairs were labelled by the judge (§4.1.1).
- effect: helps
- reader: E3: the judge is compared with human labels, with no ablation of the judge. The sample is 50 pairs per check, annotated by the first two authors, one of whom built the judge's examples; recall is not measured, only precision. The paper reads the verified rate as a floor for that reason.

### F5 · observation · merge-time-signals-and-later-fix · E3
- practice: nothing applied; agent merges with and without a verified fix were compared on four merge-time signals with Mann-Whitney U and Cliff's delta (§4.4.1).
- claim: "merge-time signal distributions of agent PRs on both groups are nearly identical (all effects negligible to small)" (§4.4.2).
- evidence: Table 6, verified fix: time under review p < 0.001, delta -0.221 (small); review items p < 0.001, delta -0.239 (small); commits per PR p = 0.75, delta +0.013; post-first-push churn p = 0.41, delta +0.032. A negative delta means the PRs with a fix sit lower on the signal.
- effect: none
- reader: the two significant signals point to less review time and fewer review items on PRs that later need a fix, but the effect is small and pooled across repositories, where the paper itself says repository confounds can enter (§4.4.1). The 61.4% of agent PRs with no recorded human review (§1, from Duma et al.) makes review items a thin measure.

### F6 · observation · commits-before-merge-and-later-fix · E3
- practice: nothing applied; within-repository conditional logistic regression of a verified fix on each signal on a log10 scale, with the number of non-boilerplate files shipped as size control (§4.4.1, Equation 1).
- claim: "the PRs that needed many rounds of work before the merge are the ones most likely to need more work after it" (§4.4.2).
- evidence: odds ratio per tenfold increase: commits 6.1 (p < 0.001), review items 2.4 (p = 0.022), churn 1.3 (p < 0.001), time under review no significant effect (p = 0.18) (§4.4.2, Figure 5; intervals in the figure only).
- effect: hurts
- reader: more commits before merge goes with more fixes after it; this is correlation on 203 verified fixes, with no control for task difficulty, which could drive both. A tenfold range of commits is wide, so 6.1 is not a per-commit effect. The sign of review items differs between the pooled view (fewer items with a fix, F5) and this one (more items, odds ratio 2.4); the paper attributes the change to repository effects without testing it.

### F7 · practice · post-merge-monitoring-of-agent-prs · E0
- practice: follow an agent PR past the merge and read its code changes, instead of treating the merge as finished work (§5.1).
- claim: "a PR should also be monitored beyond the merge", and verification of agent contributions "requires code review (i.e., reading the code changes)"; the authors propose a monitoring framework as future work (§5.1).
- evidence: no test of monitoring or of code review in this study. Cited support: a content-level model on AIDev PRs predicts post-merge modification at AUC 0.671 (Rahman and Shihab, 2026, §5.1).
- effect: helps
- reader: the recommendation follows from F5 (merge-time metadata does not mark the PRs that need a fix) and F1, but no practice was applied and no outcome of monitoring is measured. The cited AUC of 0.671 is modest.

## Limits stated by the authors

- Author-class counts measure who committed or marked a change, not who wrote it; Codex commits carry no marker, so agent shares are floors and Codex is excluded from the commit analysis (§6).
- The candidate link is file co-location within 30 days; it can miss cross-file fixes, fixes slower than 30 days and fixes inside non-fix-typed PRs, so verified rates are floors (§6).
- AIDev labels agents from commit-author patterns, so an unmarked agent PR in the human table counts as human; this can inflate the human-fixed share (§6).
- Population: five agents in repositories with at least 500 stars; other agents, low-activity repositories and later behaviour are out of scope (§6).
- Verification is reliable on the binary label, not on the three-way label (§6).
- Ownership is scoped to who authors the fix, not who reviews it (§6).
- Commit fetches cap at 30 per PR; under 2% of PRs reach it (§6).

## Reader's notes

- Task difficulty, PR size and risk are not matched between agent and human PRs; only repository is stratified, and file count enters only in RQ4. Agents may be given different kinds of tasks than humans in the same repository.
- A fix by a human of a human merge and a fix by an agent of an agent merge are counted the same, but the fix PR itself can be wrong; the study does not follow fixes of fixes.
- The 30-day window, fix-type tag and file co-edit are the authors' operational definition. The task-type tag comes from AIDev, so its accuracy is outside this paper.
- The LLM judge (Claude Opus 4.8) and one of the five agents under study (Claude Code, 130 PRs, 63 with a full window) come from the same vendor family; the paper does not discuss it and Claude Code is too small a cohort for it to matter for the headline numbers.
- Merge outcome stops at 30 days; the paper does not measure what the fixes cost or how serious the defects were.
- The paper's Appendices A and B (the labeller and the marker patterns) are not in the extracted text, so the commit classification rules were not read in full.

## Discrepancies

- The abstract and §1 say 5,044 human PRs; Table 5 counts 4,900 human PRs and Table 2 counts 4,063 on the shared window. These are different filters, not stated together.
- Figure 3 gives n = 4,396 agent and 5,044 human merges and a 30-day verified incidence of 4.5% against 2.6% (§4.1.2); Table 2 gives n = 2,012 and 4,063 and 3.68% against 2.34%. The 4.5% equals the own-window agent rate of Table 1 (4,505 PRs), so Figure 3 mixes windows, while §4.1.2 calls it "the shared observation window".
- Table 4 has 124 human-opened verified fix PRs, and Table 3 has 110 verified human-merge pairs; unique PRs should not outnumber pairs. Not explained in the parts read.
- The abstract says "76.4 % of the verified fix PRs are agent-authored throughout all commits"; Table 4 gives 76.4% over the 123 fix PRs of four agents, with Codex's 103 fix PRs excluded.
