## Question

Do users understand the code they produce when a coding agent writes it, compared with a chatbot
that makes them write the code themselves, and do they extend that code better afterwards (§1, §3)?

## Findings

### F1 · practice · agent-edits-code-instead-of-chatbot-snippets · E4
- practice: users were randomly assigned either an agent that edits their code as diffs they can accept or reject (Aider, GPT-4.1) or a chatbot that gives only syntax and snippets of five lines or fewer; both built a tic-tac-toe variant website in 50 minutes (§3.2).
- claim: agent users "finish the initial task more accurately/quickly than chatbot users" (§4.1).
- evidence: initial task accuracy on a 15-rule rubric, agent against chatbot, p = 0.00, d = 1.4; time until submission p = 0.00, d = 1.2 (Figure 4 b, c). Group means in the figure only. Prompts in the initial task 5.8 ± 0.4 (agent) and 11.6 ± 2.5 (chatbot) (§3.5). Background ability did not differ, p = 0.12, d = 0.4 (Figure 4 a).
- effect: helps
- reader: randomised assignment on one task, so E4. Single task, single web domain, students, and an older agent and model (Aider with GPT-4.1) than the agents named in §2.1. The chatbot is the authors' construction and is not a no-AI control (§3.2). The accuracy score is from an LLM judge (Gemini-3.1 Pro) with kappa 0.96 against Author A (§3.2); the two authors agree on 98% of rules for 20 submissions.

### F2 · practice · agent-edits-code-instead-of-chatbot-snippets · E4
- practice: as F1; the measurement is 12 multiple-choice comprehension questions on the user's own submitted code, answered without seeing the code, generated per user by GPT-5.2 from templates (§3.3).
- claim: agent users "score much lower on recall and reasoning questions, despite access to mechanisms meant for understanding: diff reviews and summaries of execution traces" (§4.1).
- evidence: comprehension, agent against chatbot, p = 0.00, d = 0.9 in Figure 1; recall p = 0.00, d = 1.3 and reasoning p = 0.08, d = 0.5 in Figure 4 d. Table 7 by question type, agent against chatbot: select names and IDs 0.701 and 0.793 (p = 0.035), identify own code 0.593 and 0.960 (p = 0.000, d = 1.873), purpose of a function 0.630 and 0.860 (p = 0.004), effect of a code change 0.741 and 0.750 (p = 0.916). By file: HTML 0.691 and 0.895, CSS 0.627 and 0.755 (p = 0.061), JavaScript 0.642 and 0.951 (Table 7). With initial task accuracy added to the regression, agent users still score lower (§4.3, Figure 6).
- effect: hurts
- reader: randomised, so E4, but the instrument favours the writer: "identify own code" asks which of two snippets the user wrote, and chatbot users typed theirs. This question type carries the largest gap. The two other recall and reasoning types show smaller gaps and the code-change type none. Questions were skipped for criteria the user did not attempt (note 8, §3.3). The authors checked question validity on samples of 60 and 20 questions per group and found 94% to 100% valid (A.9.1). Reasoning alone is not significant (p = 0.08).

### F3 · practice · agent-edits-code-instead-of-chatbot-snippets · E4
- practice: as F1; after the first task every user did an extension task of 20 minutes with the chatbot: add a corner win condition, red and blue symbols, and a reset button (§3.4).
- claim: agent users' initial gains "do not largely transfer to the extension task"; "agents do not aid understanding" and fail to improve extension accuracy (§4.1, §1).
- evidence: extension accuracy on a 12-rule rubric, agent against chatbot, p = 0.45, d = 0.2; extension time p = 0.69, d = 0.1 (Figure 4 b, c). Among users with initial accuracy above 0.50, p = 0.18, d = 0.5 (Figure 1; the abstract says the agent users' lead reverses there; the means are in the figure only). Path model, group effect on extension accuracy: direct 0.065 (p = .608), total 0.038 (p = .712) (Figure 9 b).
- effect: none
- reader: randomised, so E4. "No significant difference" at 27 per group; the authors call all analyses exploratory (§5). The agent group had a warm-up with the chatbot before the extension task (§3.4), the chatbot group did not need one. Prompts in the extension task were 6.8 ± 0.9 (agent group) and 4.7 ± 0.6 (§3.5).

### F4 · observation · background-skill-and-agent-outcomes · E3
- practice: observed: users' pre-task background ability (12-item multiple-choice quiz, §3.1) against each outcome, fitted separately per group in a linear regression with a group interaction (Equation 1, §4.2).
- claim: "agents equalizing users regardless of BG" on initial accuracy; background ability still predicts comprehension in both groups and extension accuracy only for chatbot users (§4.2, Figure 5).
- evidence: adjusted R² 0.37 for initial accuracy, 0.17 for comprehension, 0.05 for extension accuracy (Figure 5; coefficients in the figure only). Path model: background total effect on extension accuracy 0.531 (p = .025), of which 0.514 via comprehension (p = .003); direct −0.120 (p = .636) (Figure 9 b).
- effect: mixed
- reader: background ability was measured, not assigned, so an observation; n = 27 per group and a regression with an interaction, not a controlled contrast, so E3. The paper reads the equalising as agents masking skill in evaluation; the same data say novices and experts reach similar initial accuracy with an agent. The effect value `mixed` is chosen because comprehension still tracks background while initial accuracy does not.

### F5 · observation · copied-task-criteria-as-prompt · E3
- practice: observed: the prompts of agent users were labelled by an LLM (Gemini-3 Flash, agreement with Author A 94%, Author A and B 90%, on 50 prompts) into four strategies, and mean comprehension is reported per strategy (§5.1, Table 1).
- claim: "Users who copied criteria had the lowest comprehension and users adding code syntax had the highest, despite similar BG" (§5.1, Takeaway 1).
- evidence: Table 1, mean comprehension and users per strategy: criteria into syntax 0.743 (9 users), iterative debugging 0.692 (5), copying criteria 0.654 (25), explain the codebase 0.635 (6); background ability 0.684, 0.662, 0.668 and 0.692. Regression on prompt proportions with background ability (A.4): copy −0.4685, exploratory −0.7447, debugging −0.3378, intercept 0.7141, background 0.5688; no p-values in the text.
- effect: hurts
- reader: observational with groups of 5 to 25 users who can fall in several groups; no test is stated for the differences. The strategy lowest in Table 1 is asking the agent to explain the codebase (0.635, 6 users), which the paper does not discuss as counter to the explanation idea. Users who write technical prompts may understand the code before prompting, so the direction of cause is open (A.4 says so for familiarity). The authors' proposal of refusing low-effort prompts is not tested.

### F6 · observation · careful-code-review · E3
- practice: observed: how agent users handled the agent's diffs: auto-accept by prompting again, accept all, accept per file, or override by manual edit or reject (§5.2); mean comprehension per type (Table 2).
- claim: "Agent users who review each file have higher comprehension than those who auto-accept edits"; even they "do not reach chatbot users' mean comprehension" (§5.2, Takeaway 2).
- evidence: Table 2, mean comprehension and users: accept each file 0.777 (7 users), accept all 0.664 (20), override 0.661 (15), auto-accept 0.615 (6). Regression on interaction proportions with background ability (A.4): auto-accept −0.3343, override −0.2136, accept all −0.1585, intercept 0.4751, background 0.5088; no p-values in the text. Comparison with the chatbot mean is in Figure 1 only.
- effect: helps
- reader: users chose their review style, so an observation; groups of 6 to 20 overlap and the file-by-file reviewers also had higher background ability (0.714 against 0.603, Table 2), which the regression adjusts for. Reviewing per file is the option users with more background skill take, not an assigned practice.

### F7 · observation · concise-agent-code · E3
- practice: observed: four readability metrics of the agent users' final JavaScript file (lines, entropy, volume, proportion of comment lines) each regressed on comprehension (§5.3, A.3).
- claim: "Users with JS code of fewer lines, comments, and volume had higher comprehension"; comprehension is higher when agents write simpler code (§5.3, Takeaway 3, §1).
- evidence: Figure 8, coefficients in the figure only; the caption names fewer lines and a smaller proportion of comments, the takeaway adds volume. Agent users' initial JavaScript: 124.89 ± 3.61 lines and 0.13 comment proportion; chatbot users' 83.08 ± 5.27 lines and 0.07 (Table 5); extension task 144.79 against 103.56 lines (Table 6).
- effect: helps
- reader: within 27 agent users and four separate regressions because the metrics are collinear (§5.3), so no control. Longer code comes from users whose agent completed more of the rules (A.11 says so), so length may stand for task scope. Users in §6.2 cite comments as making extension easier, which points the other way for comments (U44, U54); one quote says comments helped extension but not understanding (U31).

### F8 · practice · agent-edits-code-instead-of-chatbot-snippets · E4
- practice: as F1; after the initial task users rated five-point statements on usefulness, effort, understanding, ownership and preference (§3.3, §6.1).
- claim: users "find the agent more helpful and simpler than chatbots, but recognize weaker understanding"; "users prefer the agent over chatbots", most prefer the option to switch (§6.1).
- evidence: Table 3, agent against chatbot: helpful 4.7 and 3.3; took mental effort 1.9 and 3.7; I understand how my code works 3.3 and 4.2; code feels like my own 2.5 and 3.7; could easily extend 3.1 and 3.2; prefer the agent in new tasks 4.2 and 3.9; prefer switching 4.6 and 4.1. Perceived comprehension predicts measured comprehension, adjusted R² 0.327, p < .001; perceived modifiability against extension accuracy 0.203, p < .001 (Table 8, A.6).
- effect: mixed
- reader: randomised groups, so E4, but the comparisons are of means with ± and no test stated. Mixed: the agent is rated better on usefulness and effort and worse on understanding and ownership.

### F9 · observation · requests-for-finished-code-from-chatbot · E3
- practice: observed: the chatbot users' prompts were labelled into seven strategies by the same procedure as F5, mean comprehension per strategy (A.10, Table 4).
- claim: chatbot users "who actively request for help via snippets, design, and syntax tend to have higher comprehension than those who ask the chatbot to write the code for them" (Table 4 caption).
- evidence: Table 4, mean comprehension and users: snippet request 0.853 (9), design help 0.834 (14), syntax help 0.826 (21), clarification 0.811 (11), debugging 0.781 (5), jailbreaking 0.755 (5), frustration 0.583 (1). Background ability follows the same order (0.658 down to 0.462).
- effect: hurts
- reader: groups of 1 to 21 users, no test, and background ability falls with comprehension, so the ordering can reflect skill. Only a trend description in A.10. The effect `hurts` is for asking the chatbot to finish the work.

### F10 · observation · comprehension-predicts-extension-accuracy · E3
- practice: observed: initial task accuracy and comprehension added as predictors of extension accuracy, and a path model with both as mediators of the group effect (§4.3, A.5, Figure 9).
- claim: both predict extension accuracy, and the two opposing paths from the agent explain why extension accuracy is similar: "agents trade better code scaffolds for worse comprehension, impeding code extension" (§4.3, Figure 7).
- evidence: adjusted R² for extension accuracy from 0.05 to 0.34 (§4.3 text; the Figure 7 caption says 0.22). Path model, agent against chatbot: indirect via initial accuracy 0.177 (p = .006), indirect via comprehension −0.204 (p = .003), total indirect −0.027 (p = .810), total effect 0.038 (p = .712) (Figure 9 b).
- effect: helps
- reader: mediation on 54 users of a design where neither mediator was assigned, so the paths are associations, not shown cause; the model is saturated and the authors call it a summary (A.5). `helps` refers to comprehension raising extension accuracy.

## Limits stated by the authors

- Population and domain: CS students on two website tasks; results may not transfer to other users or tasks (§8).
- The interface offers fewer workflow customisations than the agents users choose in practice (§8).
- LLM tools generate the comprehension questions and score the code, so errors may remain despite checks (§8).
- Sample of 27 per group is moderate, so all analyses of why agent users lack comprehension are exploratory (§5).
- Short-term productivity can be enough for some projects, such as a personal website (§8).
- Longitudinal effects and other tasks such as algorithm design and data analysis are not tested (§7).

## Reader's notes

- The agent is Aider with GPT-4.1 and diffs the user accepts; the chatbot cannot see the user's code (§3.2, A.2). Results may differ with the agents named in §2.1.
- Users knew only the task rules, not the later questions; 16% said they anticipated the extension task (A.8.3). No similar check is reported for the comprehension questions.
- Both groups used an AI for the extension task, the chatbot, so the extension task tests extension with chatbot help and not without AI (§3.4); the abstract says "without agents".
- The paper does not report means for initial accuracy, extension accuracy or comprehension per group in the text; p-values and Cohen's d are in figures and several are written "p = 0.00".
- Perceived and measured understanding agree (Table 8, A.6); the paper reads that as support that the questions measure understanding. No effect direction is claimed for it, so it is not a finding here.
- The agent-chatbot contrast changes who writes the code and also the number of prompts, the review step and the mental effort (Table 3); the paper assigns the comprehension gap to writing.

## Discrepancies

- Figure 7 caption says adding initial accuracy raises adjusted R² for extension accuracy "0.05 → 0.22"; §4.3 text and the figure label say 0.05 to 0.34.
- Figure 6 caption says adjusted R² "0.40 → 0.42"; the figure label says 0.15, and Figure 5 gives 0.17 for the model without initial accuracy.
- Takeaway 3 lists fewer lines, comments and volume; the Figure 8 caption lists only fewer lines and a smaller proportion of comments.
- Figure 4 gives reasoning questions p = 0.08, d = 0.5, while the abstract and §1 say agents harm comprehension with p < 0.002 and d > 0.80; the larger figure belongs to the combined score (Figure 1) and to recall.
- Table 7 prints Cohen's d with a positive sign for the recall and reasoning rows and a negative sign for the file rows, with the agent below the chatbot in both.
