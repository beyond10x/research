## Question

When do skills help a coding or terminal agent, why do they work, and where do they fail? The paper
splits this into four questions: skill against direct workflow memory built from the same trajectories,
the role of success and failure labels when a skill is made, transfer across agent frameworks, and
retrieval from larger or more confusable skill pools (§1, §3.1).

## Findings

### F1 · practice · distilled-skill-vs-workflow-memory · E4
- practice: turn the same set of earlier trajectories into a SKILL.md placed in the agent's environment as a resource, against cleaned workflow traces appended to the task instruction; same tasks, agents and trial budget (§3.3, A.2, Table 5).
- claim: "the strongest aggregate effect is therefore not skill over raw execution, but skill over direct workflow memory" (§5.1).
- evidence: oracle-status success on 528 paired triples, Skill 327 of 528 (61.9%) against Workflow Memory 295 of 528 (55.9%) (Table 9). Mean paired delta +0.0606, 95% bootstrap CI [+0.0076, +0.1136], 1,000 iterations (Table 10, §5.1). Table 1 (5 trials per task), 6 mixtures, 6 agent-benchmark rows: the skill is above workflow memory in 24 of 36 cells (reader's arithmetic); on Terminal-Bench Pro in 4 of 12 cells. Example cell: Codex, Terminal-Bench 2, 5s0f, 0.7548 against 0.4452.
- effect: helps
- reader: a controlled contrast on equal tasks, so E4. The CI lower bound is +0.76 points. The two arms differ in more than representation: workflow memory is appended to the task instruction and the skill is a file the agent may open (A.2, Table 5), and a pipeline cleans the traces while an LLM writes the skill, so the finding compares two construction pipelines and two delivery routes. The paired labels use one trial per task and arm (A.2). Both artifacts are built from trajectories on the tasks later scored (A.4); that is reuse on the same task, not transfer to new tasks.

### F2 · practice · skill-distillation-from-traces-alone · E4
- practice: inject a skill distilled from earlier trajectories against no prior experience (Raw); the same comparison for workflow memory against Raw (§3.3).
- claim: skill over raw is not significant; "the most robust aggregate difference ... is not skill versus raw" (A.3).
- evidence: Table 9: Raw 312 of 528 (59.1%), Skill 327 of 528 (61.9%), Workflow Memory 295 of 528 (55.9%). Table 10: Skill against Raw +0.0284, CI [-0.0227, +0.0795]; Workflow Memory against Raw -0.0322, CI [-0.0814, +0.0208].
- effect: none
- reader: both CIs include zero, so no difference was found at this sample. The numbers average over all six source mixtures, including failure-only pools; F3 shows the mixtures differ in sign, so this average hides a large spread.

### F3 · practice · source-trajectory-success-failure-mixture · E4
- practice: build the skill from a fixed budget of 5 source trajectories, from 5 successes and 0 failures (5s0f) to 0 successes and 5 failures (0s5f), and score it on the same tasks (§3.3, Table 1).
- claim: the grid lets the authors observe "how the quality of the underlying experience pool changes the downstream failure modes" (A.2). The text states no result on the failure-only pool; the sign pattern below is read from Table 1.
- evidence: Table 1, skill against the Raw baseline, 5s0f: Codex 0.7548 against 0.5935 (Terminal-Bench 2), 0.7250 against 0.5083 (SkillsBench), 0.7455 against 0.5394 (Pro); Gemini 0.7923 against 0.5000, 0.7429 against 0.4762, 0.6692 against 0.5615. At 0s5f: Codex 0.5161 against 0.5935, 0.4500 against 0.5083, 0.4303 against 0.5394; Gemini 0.4769 against 0.5000, 0.4095 against 0.4762, 0.4615 against 0.5615. Skill above Raw in 6 of 6 rows at 5s0f and below Raw in 6 of 6 at 0s5f (reader's arithmetic).
- effect: hurts
- reader: the effect is `hurts` for the failure-only source and `helps` for the success-only source; the heading carries the failure-only side, which is the practice the paper's grid adds. n = 5 trials per task, no test per cell. The tasks were kept because their raw runs held both successes and failures (A.4), so the source pools are balanced by construction.

### F4 · practice · outcome-labels-in-skill-distillation · E4
- practice: show the skill writer which source trajectories succeeded and which failed, against the same trajectories with those annotations removed (no-hint) (§3.3, A.5).
- claim: "withholding outcome labels has little effect when the source pool contains only successful trajectories, but its impact grows sharply once failed trajectories are introduced" (§5.4).
- evidence: Table 16 (normal against no-hint success), 6 rows by 6 mixtures: normal is higher in 28 of 36 cells (reader's arithmetic). Gemini, Terminal-Bench 2, 3s2f: 0.7462 against 0.4000; 5s0f: 0.7923 against 0.4231. Codex, Terminal-Bench Pro, 5s0f: 0.7455 against 0.8364. Gemini, Terminal-Bench Pro: normal is higher in 2 of 6 cells (reader's arithmetic).
- effect: mixed
- reader: an ablation on equal tasks, so E4. The direction is `helps` on 5 of the 6 rows and the reverse on Gemini with Terminal-Bench Pro, so `mixed`. The text's "little effect" at all-success pools does not match the Gemini Terminal-Bench 2 5s0f cell (see Discrepancies). One run per cell, no test.

### F5 · practice · skill-distillation-from-traces-alone · E3
- practice: inject the skill and have an LLM judge label the failure or success mode of one trajectory per arm in each of 528 paired triples (§4, A.2).
- claim: "skills usually do not work by supplying missing facts. They work by stabilizing action" (§5.1); skills "reduce several execution-layer failures" (§1, §5.2).
- evidence: mechanism labels in the skill arm: procedural_anchor 65.7%, knowledge_injection 4.5% (§5.1). Execution-layer failure modes (SC2): 37.3% of raw-arm labels, 33.3% of workflow-arm, 23.5% of skill-arm (§5.2); 124 of 528 skill arms against 197 raw and 176 workflow (§4). environment_infrastructure_failure 5.3% raw, 1.7% workflow, 0.2% skill; output_format_schema_mismatch 7.4% raw, 3.2% skill; background_service_lifecycle_failure 2.7% raw, 0.8% skill (§5.2, Table 11). algorithmic_logic_error 8.3% raw, 11.0% workflow, 7.4% skill; static_verification_without_runtime 12.5%, 12.5%, 11.7% (§5.2).
- effect: helps
- reader: the arms are a control, but the measure is an LLM judge's label on one trajectory per arm, with no uncertainty reported and no test, so E3. Human checks cover the 238 open-coding labels (714 trajectory-label checks, all confirmed; 95.8% exact agreement on the mapping to 12 modes, kappa 0.952, Table 3, §4) and not the 1,584 arm-level assignments (A.3). The judge saw the skill text for the skill arm only.

### F6 · practice · skill-distillation-from-traces-alone · E3
- practice: give the agent a skill it must decide to apply, adapt or drop (§5.3).
- claim: "the same abstraction that makes skills useful also creates a new failure surface" (§5.3).
- evidence: skill_guidance_misapplied_or_ignored in 10.0% of skill-arm cases against 0.8% raw and 0.4% workflow memory (§5.3, Table 11). Invocation or boundary failures (SC3) in 78 of 528 skill arms against 19 of 528 raw (§4). capability_or_safety_limit 1.1% raw, 0.0% workflow, 0.4% skill (Table 11).
- effect: hurts
- reader: judge-labelled shares from one trajectory per arm, so E3. The label set was induced from the same corpus, so the new failure mode may partly reflect that a skill arm has a skill to misapply and the other arms do not.

### F7 · practice · workflow-memory-injection · E3
- practice: append cleaned workflow traces of earlier runs to the task instruction (Workflow Memory arm; §3.3, Table 5).
- claim: workflow memory "carries irrelevant exploration, failed branches, and verbose process noise that can increase timeout and drift" (§1, §5.3).
- evidence: timeout_budget_exhaustion in 10.6% of workflow-memory cases against 1.7% raw and 4.4% skill (§5.3, Table 11). Success 295 of 528 (55.9%) against Raw 312 of 528 (59.1%), delta -0.0322 with CI [-0.0814, +0.0208] (Tables 9 and 10). Workflow-guided success is 54.5% of workflow-arm cases (Table 11).
- effect: hurts
- reader: the timeout share is a judge label; the success difference to Raw includes zero in its CI. At 5s0f on Gemini, Terminal-Bench 2, workflow memory scores 0.6231 against Raw 0.5000, a gain (Table 1), so the harm depends on the source mixture.

### F8 · practice · compact-plan-text-vs-skill · E4
- practice: inject a short plan of 3 to 5 high-level steps taken from the task instruction, or a workflow-derived test-first template, as plain text instead of a SKILL.md; Gemini CLI on 26 Terminal-Bench 2 tasks, 5 trials each (A.8, Table 12).
- claim: the skill advantage is not "simply caused by any compact procedural hint" (§5.1).
- evidence: Table 12, 130 trials per condition: Raw 65 of 130 (50.0%), short plan 62 of 130 (47.7%), test-first 77 of 130 (59.2%), Workflow Memory 81 of 130 (62.3%), Skill 103 of 130 (79.2%).
- effect: mixed
- reader: equal tasks and trial counts, so E4, but one agent and no test. Short plan against Raw is none; test-first against Raw is +9.2 points (reader's arithmetic) and helps. The Workflow Memory and Skill values equal the 5s0f cells of Table 1 for this row (reader's inference), so the test-first source mixture is probably also 5s0f; the parts read do not say. The test-first template is the authors' own design.

### F9 · practice · distilled-skill-vs-workflow-memory · E3
- practice: as F1; the measurement is success and tokens per task on the 83 tasks for which all three arms have token metadata (A.9, Table 13).
- claim: "We therefore interpret Skill as the more effective representation and Workflow Memory as the more token-efficient one" (A.9).
- evidence: Table 13, equal task weighting. Success: Raw 64.1%, Workflow Memory 64.8%, Skill 69.6%. Total tokens per task: Raw 555.7K, Workflow Memory 426.2K, Skill 521.5K. Skill against Raw +5.5 points and -34.2K tokens; Workflow Memory against Raw +0.7 points and -129.5K; Skill against Workflow Memory +4.8 points and +95.3K.
- effect: mixed
- reader: the 83-task intersection is chosen by data completeness, not by design, and no test is given, so E3. Skill-arm token fields are incomplete in the exported metadata (A.2). Table 13 calls the baseline "Raw trajectories" with the cost note "Full prior traces provide broad evidence but carry the largest context load", which does not match the Raw arm as defined, no prior experience (see Discrepancies).

### F10 · practice · skill-library-expansion · E4
- practice: hide the task's ground-truth skill among 4, 9, 19, 49 or 99 distractors (pool sizes 5 to 100) and measure skill identification offline by embedding ranking (Arm 1, Qwen3-Embedding-0.6B top-1) and by explicit agent selection without running the task (Arm 2) (§3.3, §5.5, A.7).
- claim: pool size contributes to the difficulty of identifying the right skill, with similar distractors the larger stressor (§5.5).
- evidence: top-1 embedding precision averaged over distractor types falls from 88.3% at pool size 5 to 76.9% at 100; explicit agent selection from 70.0% to 63.7% (§5.5, Figure 3a). Random pools in Arm 1: 97.7% to 84.1% (Table 4).
- effect: hurts
- reader: the pool size is assigned on the same tasks, so E4, but with one query per task and pool setting and no test. Averages combine two agents (Arm 2) and three distractor regimes. Arm 1 and Arm 2 are offline and do not run the task; the paper does not link them to success.

### F11 · practice · confusable-skill-distractors · E4
- practice: fill the pool with distractors that are embedding-space near neighbours of the ground-truth skill ("similar"), against random or far-away ("dissimilar") distractors (§5.5, A.7).
- claim: "semantic confusability is the more important stressor for identifying the correct procedural artifact" (§5.5).
- evidence: Arm 1 top-1 precision at pool size 5 and 100: similar 70.5% and 53.4%, random 97.7% and 84.1%, dissimilar 96.6% and 93.2% (§5.5, Table 4). Arm 2 on similar pools at size 5: Gemini 54.3%, Codex 51.9%; at size 100: Gemini 55.4%, Codex 31.9% (§5.5).
- effect: hurts
- reader: the distractor type is assigned on the same tasks, so E4. The "similar" pool is built with the same embedding model that Arm 1 uses to rank, so the Arm 1 drop partly reflects that choice. One query per task and pool.

### F12 · practice · skill-library-expansion · E4
- practice: place the whole pool of 5 to 100 skills in the agent's environment with no preselection, run the task (Arm 3), and parse which skills the agent opened or invoked (§3.3, §5.5, A.7).
- claim: "exact ground-truth skill invocation is neither sufficient nor strictly necessary for success"; downstream success "remains comparatively insensitive" to the collapse of use precision (§5.5).
- evidence: parsed actual-use precision averaged over the two agents falls from 29.6% to 3.3% between pool sizes 5 and 100, while success moves from 36.4% to 39.3% (§5.5, Table 4). Gemini precision 16.9% to 0.7%, success about 36% to 39%; Codex precision 42.3% to 5.9%, success 35.4% to 42.0% (§5.5). Arm 3 recall at size 100: 54.3% to 73.6%; precision 0.7% to 8.1% (§5.5, Table 15). Codex, random pool, success 24.3% at size 5 and 35.5% at size 10 (Table 15).
- effect: none
- reader: pool size is assigned on the same tasks, so E4 for the claim that success stays flat. There is no no-skill baseline in RQ4 in the parts read, so the study cannot say whether the pool helps at all, and the per-cell swings in Table 15 (Codex 24.3% to 44.8%) have no noise estimate. RQ4 used GPT-5.4 for Codex, not GPT-5.3-Codex (§3.2).

## Limits stated by the authors

- The tasks are terminal and tool-using benchmarks; long-horizon web use and open-ended collaboration are not covered (§7).
- Few agent-model configurations; results may not hold for other scaffolds, model families or versions (§7).
- The taxonomy rests on a stratified open-coding sample of about 3% of the normalised records, so rare modes may be missing (§7).
- The paired-triple labels are LLM-assisted, not exhaustively human-coded; one representative trial per arm and task is used; token metrics are incomplete for some skill-arm runs (A.3).
- RQ4 results use GPT-5.4 and are comparable only within RQ4 (§3.2).

## Reader's notes

- The skills and the workflow memories are built by the authors' own pipelines, with prompts in Appendix B (not read), so the skill advantage is the advantage of this skill writer. The paper's results compare the authors' own system against variants of it.
- The source trajectories come from the same tasks that are then scored (A.4: tasks with both successful and failed raw runs, a pool is built, "rerun the selected tasks"). Every skill and workflow memory therefore holds a record of an earlier attempt at the test task. The paper's claim of skill "transfer" is not tested on unseen tasks.
- RQ3 (cross-framework transfer, Codex artifacts used in Gemini CLI) has a design in §3.3 and A.6 and a figure (Figure 4), but no result in the prose of the parts read. Figure 4's text shows a Raw baseline of 56% and bar labels from 54 to 84, which cannot be tied to mixtures from the extracted text. No finding is written for it.
- Raw baselines are reruns on tasks chosen because earlier raw runs both passed and failed; this selects mid-difficulty tasks.
- The judge, Claude Sonnet 4.6, is a different model from both evaluated agents, but it read truncated transcripts (a 4,000-character head and an 8,000-character tail per trajectory in the paired prompt, A.2).
- The aggregate Table 9 and Table 10 numbers (528 triples) use one trial per arm; Table 1 uses n = 5 trials per task. They are different samples of the same experiment.
- Success is the benchmark verifier's reward (A.2); code quality and effort are not scored.
- Of the three benchmarks, only SkillsBench is built around skills; Terminal-Bench is a command-line benchmark, not repository-level software work.

## Discrepancies

- §5.4 says withholding outcome labels "has little effect when the source pool contains only successful trajectories". Table 16 at 5s0f gives Gemini, Terminal-Bench 2, 0.7923 normal against 0.4231 no-hint; Gemini, SkillsBench, 0.7429 against 0.6190; Codex, Terminal-Bench Pro, 0.7455 against 0.8364.
- Table 13 labels the baseline row "Raw trajectories" and describes it as "Full prior traces", with input of 541.5K tokens, the largest of the three. Table 5 and §3.3 define Raw as receiving no prior experience.
- Table 7 lists 3,594 failed trials and 3,594 skill-arm trials; both groups sum with their partners to 8,135 (4,541 + 3,594 and 1,883 + 2,658 + 3,594). Two equal counts for unrelated groups may be a copy error; not explained.
- A.1 gives 86 SkillsBench tasks. The percentages in Tables 14 and 15 (for example 97.7% = 86 of 88, 84.1% = 74 of 88, reader's arithmetic) fit 88 queries per pool setting; not explained.
- §5.1 and A.3 call Skill against Workflow Memory "the strongest aggregate effect"; A.8 reports 79.2% against 62.3% on 26 tasks (a gap of 16.9 points, reader's arithmetic) and A.9 reports +4.8 points on 83 tasks. The samples differ and the text does not reconcile them.
