## Question

When a maintainer revises a SKILL.md, what does the revision do to a coding agent's compliance,
task action and correctness, and to its token cost, and how do Skills change together with the
harness configuration (§1)?

## Findings

### F1 · practice · added-command-or-path-rule-in-skill · E4
- practice: present the same request and model with the Skill's old body and with its new body, where the revision added a directive, a line that states an imperative and names a command, path or identifier in backticks; one answer per request, with only the Skill name and description as the third condition (§3.2, §3.4).
- claim: "An added rule raises compliance in single answers on all 21 models" (§1).
- evidence: compliance with the added rule, new minus old, on the same N = 300 probes: mean +0.41 [+0.35, +0.46] over the 16 open models, per-model +0.344 (OLMo 2-7B) to +0.448 (Gemma 2-9B), old 0.210 to 0.280, new 0.554 to 0.725, all p < 0.001 (Table 3, Fig. 4a). Five closed models +0.43 [+0.35, +0.52] on 144 probes (Fig. 4c). High-star repositories, 16 models, +0.44 [+0.36, +0.52] (Fig. 4b). Not detectably different by commit intent or harness change in the same commit (smallest Holm-adjusted p = 0.24, §5.1.1).
- effect: helps
- reader: old against new on the same probes is a paired control, so E4. The check is a string match for the rule's own token, so it counts an answer that repeats a token it was shown; the paper's two annotators' labels on a stratified sample of 240 responses, re-weighted to all main-set answers, give a larger gain in directive following (about +0.52, §3.2). Probes need the rule by construction and a regular-expression filter keeps 17% of candidate directives (§7.1). All models answered without thinking. The requests and checks were written by Qwen 3.5-27B, and Qwen models gain +0.04 more (§7.1).

### F2 · practice · stated-rule-vs-token-mention · E4
- practice: add to the old Skill a sentence that only names the rule's token, or add the full rule line, and compare the two on the same probes; four models (Phi-3-mini, Phi-4-mini, Qwen 2.5-7B, Qwen 3.5-9B), 292 probes (§5.1.2, Fig. 5).
- claim: "Stating a rule beats naming its token" (§5.1.2).
- evidence: stating the rule adds +0.15 [+0.12, +0.19] beyond naming the token (Fig. 4g); per model +0.16, +0.12, +0.17, +0.17 (Fig. 5). Adding only the rule line to the old Skill gives +0.25 to +0.31, about two thirds of the full revision's +0.39 to +0.43. Removing the rule line from the new Skill lowers compliance by about 0.21. On the 88 probes whose token the old version already contains, stating the rule adds +0.04 [+0.02, +0.07].
- effect: helps
- reader: an ablation with four prompt variants per probe. The rule line contains the token, so the paper says the two conditions overlap and do not split the effect exactly (§7.1). Four small models only.

### F3 · practice · length-matched-irrelevant-skill · E4
- practice: add to the old Skill unrelated Skill text as long as the revision's growth, and compare with the old Skill (§5.1.2).
- claim: "Unrelated text of the same length has no detectable effect" on compliance (§5.1.2); a growing document around an unchanged line also has no detectable effect (§5.1.6).
- evidence: no number in the text; the row is in Fig. 5 (four models, 292 probes). For the second claim see Table S20, not read.
- effect: none
- reader: E4 by design; the values are in a figure and a supplementary table, so the grade rests on the paper's statement. Compliance here is a string match, so an effect of text length on quality would not show.

### F4 · practice · prose-only-skill-revision · E4
- practice: revisions that change only prose or examples, with the Skill's existing directive line left alone; 154 dilution probes, four models (Qwen 2.5-7B, Qwen 3-8B, Qwen 3.5-9B, Phi-4-mini) (§5).
- claim: such revisions "barely move compliance with a Skill's existing rules" (§5).
- evidence: change in compliance +0.017 [+0.002, +0.034], inside an equivalence margin of 0.08 fixed before the run (per-model data-derived bounds at most 0.06), while the Skill body itself adds +0.57 over none (Table S12). The same revisions add +34 input and +2 output tokens per request (§6.3).
- effect: none
- reader: a pre-set equivalence margin on equal probes, so E4. Four small models; the check grades a rule that the revision did not touch.

### F5 · observation · rule-names-token-new-to-skill · E3
- practice: the 300 main-set probes are split by whether the checked token already appears in the old Skill (193 new, 107 present); nobody assigned the split (§5.1.3, Table 3).
- claim: "The gain comes from tokens new to the Skill" (§5.1.3); a rule that names a command or path the old Skill lacks is what changes behaviour (§5, Insight).
- evidence: a new token lifts compliance by +0.51 to +0.66 over 16 models from an old-version baseline of 0.05; an already-present token starts at 0.61 and lifts it by +0.08 [+0.03, +0.12] (107 probes; Table 3 columns). In a sample of 30 of the 107, 18 restate a rule and 7 add a rule about a token shown earlier only in an example; those 7 show +0.04 [−0.01, +0.08]. On 260 requests that do not need the rule, token use rises +0.02 to +0.06 under the new version against +0.38 to +0.45 where it is needed (six models, Table S32).
- effect: helps
- reader: a post hoc split, no control; the paper itself says part of the difference may be headroom, since the already-present subset starts at 0.61 (§5.1.3). The sandbox shows the same pattern: where the old Skill already contained the token (23 tasks) no action gain is detected (§5.2.2).

### F6 · practice · rule-deletion-from-skill · E4
- practice: present the same probes with the Skill versions in reverse order, so the revision deletes a directive (245 deleted-directive probes) (§3.2, §5.1.4).
- claim: "Deleting a rule lowers compliance with it" (§5.1.4).
- evidence: compliance falls by 0.27 to 0.33 on each of eight models (six Qwen models, Phi-4-mini, OLMo-2), about three quarters of what adding a rule gains (Table S15). By hand-checked reason, exploratory: deleting a duplicate −0.12 (n = 27), deleting a replaced rule −0.58 (n = 24) (Table S16).
- effect: hurts
- reader: this is the same probes in reverse, so E4, and the drop is on the checked rule by design. A deletion that removes a duplicate costs little in the small split; the reason labels were assigned by Claude Sonnet 4.5 and 64 were hand-checked (§3.2).

### F7 · observation · skill-revision-gain-by-model-generation · E3
- practice: the revision's gain is compared between older and newer releases of the same model family, 12 pairs of generations (§5.1.5).
- claim: "Older and newer model generations gain similarly" (§5.1.5).
- evidence: no generation difference significant after Holm correction (Table S17); data-derived bound 0.077, about a fifth of the main effect, 0.062 along the Sonnet ladder, 0.071 for the directive-following part. A separate family of tests on new-token probes finds one step that differs, Qwen 2.5-7B to 3-8B, −0.083, Holm-adjusted p = 0.018. Per-model gains in Table 3 range +0.344 to +0.448 over releases from 2023-12 to 2025-11.
- effect: none
- reader: models were not assigned; the paper says the old Skill versions mostly post-date the older models, so authoring time and generation are not crossed (§7.1). A negative result with a bound of 0.077, so a smaller interaction remains possible.

### F8 · practice · skill-revision-in-long-context · E4
- practice: place the probe inside a context of about 15k or 40k tokens with a coding-agent system prompt, fourteen tool schemas, the Skill and a prior exploration exchange, and let four open models answer once (149 probes) (§5.1.7).
- claim: "Part of the gain survives in long contexts" (§5.1.7).
- evidence: the new version raises compliance by +0.07 to +0.28 (8 of 8 model-length cells significant) against +0.37 to +0.42 in a short answer on the same probes; mean +0.25 [+0.20, +0.30] at 15k and +0.15 [+0.11, +0.19] at 40k (Fig. 4e, 4f). About three fifths survive at 15k (95% CI 53 to 72%) and about two fifths at 40k (29 to 46%). Where the context already shows the token but the old Skill lacks it (28 probes) the revision adds +0.31 [+0.20, +0.42]. In short answers the gain falls from 0.424 at low occupancy to 0.270 when the Skill fills three quarters of the window (Table S19).
- effect: helps
- reader: short against long on the same probes is an equal-task contrast. The gain stays positive and shrinks, so the direction is helps at a smaller size. The contexts are built by the authors, with a single exploration exchange, not recorded agent sessions.

### F9 · practice · added-command-or-path-rule-in-skill · E4
- practice: an executing agent (mini-SWE-agent scaffold, 12 steps, network-less sandbox holding the repository at the new version's commit) runs 80 tasks whose added rule names a command, flag, file or identifier that exists in the repository, with the old or the new Skill body in the prompt; Qwen 3.5-9B, Qwen 3.5-27B, Devstral-Small-2507 and Claude Sonnet 4.5, three runs per cell and one for Sonnet (§5.2.2, Table 4).
- claim: "every agent takes the required action more often" with the new version (§5.2.2).
- evidence: action rate none / old / new: Qwen 3.5-9B 0.32 / 0.42 / 0.58, Qwen 3.5-27B 0.40 / 0.42 / 0.62, Devstral 0.34 / 0.44 / 0.80, Sonnet 4.5 0.49 / 0.62 / 0.81; new minus old +0.16, +0.20, +0.36, +0.19, mean +0.23 [+0.15, +0.31] (Table 4, §5.2.2). On the 62 tasks where every path, script, command and target the old Skill names still exists, +0.22 [+0.14, +0.30], against −0.05 [−0.24, +0.16] for the difference to the 18 tasks with a missing reference. Where the old-version agent had seen the token in its own output, Qwen 3.5-27B still gains +0.19 [+0.08, +0.29]. Execution (28 tasks) rises +0.13 to +0.25, with the CIs of two agents spanning 0.
- effect: helps
- reader: E4, paired on 80 tasks. The tasks were built so the required token exists in the repository, with the rule added by the revision; the action is the rule's own command, file or identifier, which is what the rule asks for. One scaffold and one sandbox that shows only the first and last 2,000 characters of an output (§7.1). Sonnet 4.5 has one run per cell.

### F10 · practice · added-command-or-path-rule-in-skill · E4
- practice: as F9; the measurement is final correctness of the produced artifact, judged blind to model and version by annotators who are not authors of the paper or the Skills (§5.2.3, Table 5).
- claim: "blind judges see modestly higher final correctness"; Table 5 "is our primary outcome evidence" (§1, §5.2.3).
- evidence: all 80 tasks, old to new: Qwen pooled 0.37 to 0.50, +0.13 [+0.05, +0.20] (151 pairs); Sonnet 4.5 0.60 to 0.65, +0.06 [−0.06, +0.18] (72 pairs); pooled over the three judged agents +0.10 [+0.04, +0.17] (Table 5, §5.2.3). Automated check on 36 tasks: Devstral +0.24 [+0.07, +0.44], Sonnet 4.5 +0.03 [−0.18, +0.25] (Table 4). The paper puts the power for Sonnet's 72 pairs at about 0.5 against an effect of +0.13 (§7.1).
- effect: helps
- reader: E4 with blind human judgement, one run per model, task and version. The gain is significant for the two Qwen models only. 17 pairs in two rounds were dropped as unclear after adjudication (3 of 72 and 14 of 168, Table 5). Sonnet 4.5's rise is not distinguishable from zero. The automated check agrees with the annotators only moderately (κ = 0.50 to 0.55, §7.1).

### F11 · practice · lazy-skill-loading-catalog · E4
- practice: list only the Skill's name and description in the prompt and leave the body at a path in the checkout, so the agent decides whether to read it; the same 80 sandbox tasks and four agents as F9 (§5.2.4).
- claim: "On-demand loading keeps about half of the action gain" (§5.2.4).
- evidence: the new-minus-old action gain averaged over four agents falls from +0.23 to +0.12 [+0.06, +0.18]; 51% survives (95% CI 28 to 75%). Sonnet 4.5 +0.19 under both modes; the three open models keep about 38% (16 to 61%): Qwen 3.5-27B +0.20 to +0.08, Qwen 3.5-9B +0.16 to +0.07, Devstral +0.36 to +0.13. Sonnet 4.5's final correctness rises by +0.19 [+0.03, +0.39] on 36 tasks, because its old Skill works worse on demand (0.50 against 0.67 preloaded). The two agents opened the Skill in 89% (Qwen 3.5-27B) and 88% (Sonnet 4.5) of new-version episodes; a read showed the added rule in 71% and 69% of reads; once shown, Sonnet acted in 88% [77, 97] and Qwen in 61% [48, 74] of episodes (§5.2.5).
- effect: mixed
- reader: E4, in-prompt against on-demand on the same tasks. Better for Sonnet 4.5, worse for the open models. The sandbox truncates a read to 2,000 characters at each end, so the paper expects gains for long Skills to be lower than under harnesses that show whole files (§7.1). The comparison is of the revision's gain under each mode, not of the Skill against none.

### F12 · practice · added-command-or-path-rule-in-skill · E4
- practice: measure tokens per request for the old and new Skill body in single answers, input and output (§6.1).
- claim: "A revision adds input tokens but shortens the answer" (§6.1.1).
- evidence: input +18% to +19% on all 16 open models (for example Qwen 2.5-7B 1,522 to 1,811 tokens), output −2 to −19 tokens per response; total tokens +17% on the open models and +24% to +27% on four Claude models (Table 6, Table 7). Added tokens per additional compliant response 633 to 891 (Table 6). Mean latency on three open models −7.2% to −1.6% (Table 7). In juxt/allium a rule to run `allium check` cut the answer from 201 to 81 tokens and raised compliance from 0.07 to 0.99.
- effect: hurts
- reader: paired on the same probes, so E4. The cost is a counted prompt-length difference, not a bill; at list prices the paper says the bill rises less because output costs three to five times more than input (§6.1.1, Table S31 not read). Single answers, not episodes (see F13).

### F13 · practice · added-command-or-path-rule-in-skill · E4
- practice: as F9; tokens per sandbox episode, summed over turns, old against new Skill body (§6.2.1).
- claim: "A revision adds no detectable cost per episode" (§6.2.1).
- evidence: the new version changes the tokens of an episode by −2.3% to +3.0% across the four agents (+0.8% on average); every interval spans zero and lies within −14% to +12% (Table 7). The paper attributes this to fewer steps offsetting the longer prompt (§6.2.1).
- effect: none
- reader: a null with a bound of about +12%, so a cost rise below that is not excluded. 80 tasks, three runs per cell and one for Sonnet 4.5.

### F14 · practice · skill-body-always-in-context · E4
- practice: carry the old Skill body in the prompt of a sandbox episode, against the name and description alone (§6.2.2).
- claim: "Carrying a Skill body costs far more than revising it" (§6.2.2).
- evidence: the old version costs 37% to 57% more tokens per episode than none, 50% on average over the four agents (Table 7, §6.2.2). The body is re-sent every turn, and agents with a Skill body take fewer turns but still use more tokens.
- effect: hurts
- reader: E4, none against old on the same 80 tasks. Cost only; the same table of action rates (Table 4) shows that the old Skill also raises the action rate over none for all four agents (+0.02 to +0.13, reader's arithmetic from Table 4), so the cost buys some gain.

### F15 · observation · rules-with-tokens-and-no-compliance-gain · E3
- practice: for each added rule and each model, a rule–model pair, check whether compliance changed and whether tokens grew; five samples per condition, so compliance moves in steps of 0.2 (§6.1.2).
- claim: "One rule–model pair in five adds tokens with no detected gain" (§6.1.2).
- evidence: compliance improves in 58% of pairs; in 20% the prompt grows with no detected change (repository-clustered 95% CI 16.1% to 24.2%; 18% to 27% under six alternative thresholds); in 17% neither changes; in 5% compliance falls. Of the 55 rules that at least half the models classify as overhead, 27 are already followed (mean old compliance at least 0.5) and 28 are ineffective, ignored whether present or not.
- effect: hurts
- reader: a post hoc classification, no control. At five samples per condition an unchanged rate is compatible with a small real change, which the paper says (§7.1), so an "overhead candidate" is not shown to have no effect; the paper recommends controlled removal tests before deleting.

## Limits stated by the authors

- Level-1 compliance counts an answer that repeats a token it was shown, so it includes exposure; the control conditions overlap because the rule line contains the token (§7.1).
- The findings apply to concrete, mechanically checkable rules; the literal filter keeps 17% of candidate directives and under-represents prohibitions, conditional rules and permission guardrails (§7.1).
- Models answered without reasoning; open models span 3.8B to 32B; the closed models come from two vendors (§7.1).
- The sandbox uses one published scaffold, not production agents, and shows the first and last 2,000 characters of an output (§7.1).
- The corpus skews to moderately popular repositories, none above 375 stars in the main corpus; a high-star set repeats the central comparisons (§7.1).
- Every effect is conditional on a request that needs the rule; 25% of 1,454 later in-scope commit–rule pairs need it (95% CI 14 to 40%), so in the paper's scenario an in-scope request gains about 0.10 in single-answer compliance and about 0.06 in required action (§7.2).
- The Sonnet 4.5 outcome estimate is underpowered: 72 pairs, power about 0.5 for +0.13, about 125 pairs would give 80% (§7.1).
- Documented motives only; maintainers may revise for a new model or harness without saying so (§7.1).
- The generation result is a negative finding with a bound of 0.077 (§7.1).

## Reader's notes

- RQ1 results are descriptive and have no effect direction, so they are not findings. For the record: of 2,608 revisions 55.0% add or delete a MUST/NEVER constraint, conditional rule or numbered step, 19% change examples or code only, 14% prose only (Fig. 3a); first/last pairs are a median of two revision commits apart and 60% of revised Skills end longer (§1, Table 2, +101.09 words on average); commits that revise a Skill change harness configuration in 23.0% of cases against 18.5% of matched commits, +4.5 points [+1.6, +7.3], chiefly CLAUDE.md (+2.1) and AGENTS.md (+2.0) (§4.3); creation commits 36.7% against 21.8% (§4.3); 37.6% of revision commits carry an AI-agent or bot signature against 40.5% of others (§4.1). The rule classifier misses most MUST/NEVER and conditional lines (recall 0.18 and 0.19, §4), so the 55.0% is a lower bound on rule changes.
- All effect sizes concern the rule the revision added, graded by whether the answer contains the rule's token or the agent runs the rule's command or touches its file. Whether the task was done better in ways the rule does not cover is measured only by the blind judgement of F10 and the automated check on 36 tasks.
- Probes were generated by an LLM (Qwen 3.5-27B) from the maintainers' own added line, then filtered; the request is built so that the rule is needed. Real requests need it in about a quarter of later commits (§7.2), a number the authors derive from 100 hand-labelled pairs reweighted to 1,454.
- The paper's practical advice (add a rule when it gives the agent information the Skill lacks; check before deleting; size a Skill for the smallest model that will read it, §7.2) is the authors' reading. The second and third points rest on F6 and F7, which are the weaker findings.
- The paper says earlier work compares a Skill or a configuration file with its absence (§2); this paper compares versions. F14 is its only comparison with none, and it measures cost.
- On the 36 tasks with an automated check the paper says final correctness rises less than the action rate, by differences of +0.03 to +0.08 (§5.2.3); Table 4 reports action over all 80 tasks, so those differences cannot be checked from the text.
- The pre-registered equivalence margin of 0.08 (§5) is stated as fixed before the run; no registry is named.

## Discrepancies

None found in the parts read. Small differences: 6,957 revision commits in Table 1 against 6,955 in §4.3 (855 repositories re-cloned of 856); 14% in §4.1 against 13.6% in Fig. 3a for prose-only revisions.
