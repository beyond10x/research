## Question

Does designed agent memory (Mem0, Zep, BM25 retrieval) still help once the model is strong enough
to search the raw history itself with a coding agent's tools, and what does each option cost
(Abstract, §1)?

## Findings

### F1 · practice · extracted-facts-memory-vs-full-context · E4
- practice: store extracted facts with Mem0 (written by the same model that answers, top-200 facts shown per question) instead of giving the model the whole raw history in context (§2, Table 1, Appendix B).
- claim: "Mem0 beats full context only with GPT-4o-mini" (Abstract, §3).
- evidence: correct rate on 152 questions, Mem0 against full context, Table 2. GPT-4o-mini 78 against 74. GPT-6 Luna 80 against 92. Claude Opus 5.5 95 against 95. One run per cell.
- effect: mixed
- reader: methods compared on the same 152 questions with the same model, so E4. One conversation and one run per cell; the author says "differences of a few questions may not hold in a second run" (§6). The history fits every model's context, so full context is always possible (§6). Mem0 ran with default extraction and retrieval only.

### F2 · practice · temporal-graph-memory-vs-full-context · E4
- practice: store the conversation as a temporal graph with Zep (Graphiti, one session per episode, top-20 edges shown per question) instead of full context (§2, Appendix B).
- claim: Zep is below full context with every model and is never on the cost-accuracy frontier (§3).
- evidence: correct rate, Zep against full context, Table 2. GPT-4o-mini 43 against 74. GPT-6 Luna 51 against 92. Claude Opus 5.5 87 against 95. Zep's graph holds 128 facts from the 19 sessions with GPT-6 Luna against 195 with Claude Opus 5.5 (§3).
- effect: hurts
- reader: same design and limits as F1. Zep ran with default settings; the paper says other settings may do better (§6).

### F3 · practice · bm25-retrieval-vs-full-context · E4
- practice: store raw turns and show the model the top-8 BM25 turns, plus or minus 2 turns around each, instead of full context (§2, Table 1).
- claim: BM25 and full context with GPT-6 Luna are on the frontier of Figure 1 (§3); BM25 is not claimed to match full context.
- evidence: correct rate, BM25 against full context, Table 2. GPT-4o-mini 74 against 74. GPT-6 Luna 82 against 92. Claude Opus 5.5 90 against 95. Cost per question, BM25 against full context: $0.00028 against $0.0028, $0.00021 against $0.0019, $0.013 against $0.117.
- effect: mixed
- reader: lower accuracy with the two stronger models and about a tenth of the per-question cost with all three (reader's arithmetic from Table 2). Same one-conversation, one-run limits as F1.

### F4 · practice · memory-store-built-before-questions · E4
- practice: pay once to build a Mem0 or Zep store before any question, against full context which has no build step (§3, Table 2).
- claim: "Mem0's build alone costs more than full context's whole rollout with the same model"; Paying to build memory a stronger model does not need "is a memory tax" (§3).
- evidence: Mem0 build against full context's whole rollout: $0.56 against $0.43 (GPT-4o-mini), $0.45 against $0.29 (GPT-6 Luna), $25.88 against $17.84 (Claude Opus 5.5) (§3). Break-even on the same history after 372, 545 and 596 questions; LoCoMo asks 152 (§3). Zep build is $0.092, $0.103 and $6.224 (Table 2).
- effect: hurts
- reader: the Zep build is below the full-context rollout in all three models, so the claim holds for Mem0 only. The break-even holds for one history; the paper says designed memory may survive as a cost trade-off when many questions share one history (§6). Cost is list price (§2).

### F5 · practice · stronger-model-writes-memory-store · E4
- practice: write the Mem0 or Zep store with a stronger model, and read it with each of the three models (writer and reader swapped, retrieval calls no model) (§4, Table 3).
- claim: "A stronger reader does not recover what the writer left out"; the writer "limits every reader" (§4).
- evidence: Table 3, correct rate. Zep store written by GPT-4o-mini, read by GPT-4o-mini, GPT-6 Luna, Claude Opus 5.5: 43, 43, 45. Zep store written by Claude Opus 5.5: 66, 71, 87. Mem0 store written by GPT-4o-mini: 78, 83, 84; by Claude Opus 5.5: 89, 91, 95.
- effect: helps
- reader: a swap of one factor on the same questions, so E4. Single run per cell, and the gaps for Mem0 are 1 to 11 points on 152 questions. The paper reports the Zep store written by GPT-6 Luna in Table 3 (52, 51, 55) but does not discuss it.

### F6 · practice · agent-search-over-raw-history-vs-full-context · E4
- practice: with Claude Opus 5.5, give a coding agent (Pi, Codex or Claude Code) the raw history as one JSON file and let it search with its own tools, against putting the whole history in context (§2, Table 1).
- claim: "With Claude Opus 5.5, Pi tops the cost-accuracy frontier"; 99% for less than half the cost of full context (Abstract, §5).
- evidence: Pi 99% for $6.95 a rollout against full context 95% for $17.84 (§5). Pi reads about 10,000 input tokens a question, 7,900 cached, against 28,900 for full context (§5). Codex 98% for $25.41 and Claude Code 97% for $28.41 (§5). On the 88 questions without photo evidence, Pi 100 and full context 99 (Table 4).
- effect: mixed
- reader: cost helps for Pi only; Codex and Claude Code cost more than full context at the same accuracy. The accuracy lead is not a search effect (F9). The author says "Whether searching the record answers more than reading all of it, this study does not settle" (§5). Pi's single miss is an answer-key error (F10).

### F7 · practice · agent-search-over-raw-history-vs-full-context · E4
- practice: as F6, with GPT-4o-mini and GPT-6 Luna as the model (§2, §3).
- claim: with GPT-4o-mini "Codex opens the conversation file for three questions in four and Claude Code almost never, and otherwise they answer from the question alone"; the paper does not claim an agent lead with GPT-6 Luna (§3).
- evidence: correct rate, Table 2. GPT-4o-mini: Pi 63, Codex 28, Claude Code 29 against full context 74; Codex opens the conversation file for three questions in four and Claude Code almost never (§3). GPT-6 Luna: Pi 91, Codex 88, Claude Code 91 against full context 92. Cost per question with Luna, Pi $0.0032 against full context $0.0019 (Table 2).
- effect: hurts
- reader: same single-run limits. Whether the file was opened was reported by the author in prose with no count or method.

### F8 · practice · alternative-harness-same-model · E4
- practice: run Claude Opus 5.5 under three different coding agents (Pi, Codex, Claude Code) on the same 152 questions, same prompt (§2, Appendix C).
- claim: the same model "costs so differently across harnesses" (§5, citing the HarnessTax blog).
- evidence: Claude Opus 5.5, correct rate and cost per rollout: Pi 99% and $6.95, Codex 98% and $25.41, Claude Code 97% and $28.41 (§5). Cost per question $0.046, $0.167, $0.187 (Table 2).
- effect: helps
- reader: helps means Pi is cheaper at about the same accuracy; accuracy differences of 1 to 2 points are 2 to 3 questions of 152. Agent versions are reported (§2). Claude Code and Pi were capped at 100 turns, a question at 20 minutes, and a failed trial was re-run with only the accepted one counted (Appendix B), so cost excludes failed attempts.

### F9 · observation · input-asymmetry-explains-agent-lead · E3
- practice: the agents were given LoCoMo's official file with photo captions beside the turn text; the memory methods and full context got turn text only. 116 of 419 turns share a photo, 64 of 152 questions have evidence in such a turn (§2).
- claim: "Photo captions account for most of Pi's lead over full context"; without photo evidence Pi matches full context for less than half its cost (§5).
- evidence: with Claude Opus 5.5, Pi answers seven questions that full context misses and misses none that it answers; six of the seven have photo evidence (§5). Correct rate on the 88 non-photo questions, Table 4: Pi 100, full context 99, Mem0 99, Codex 99, Claude Code 99. On the 64 photo questions: Pi 98, full context 89, Mem0 91, Codex 97, Claude Code 95.
- effect: none
- reader: effect is on the comparison of agents and full context on the non-photo questions, where the difference is one answer. The split is a post-hoc subgroup, so E3. The paper says the caption asymmetry touches comparisons between agents and memory methods, not those among memory methods (§6). That makes F1 to F3 and F5 free of it, and F6 and F8 not.

### F10 · observation · benchmark-answer-key-error-caps-score · E1
- practice: one LoCoMo question ("what kind of painting Caroline shared with Melanie on 13 October 2023") has a wrong answer key: in the conversation Melanie shares the painting and Caroline a drawing (§5).
- claim: Pi's "one miss is LoCoMo's mistake"; it answers every question whose key is sound (Abstract, §5).
- evidence: Pi with Claude Opus 5.5 says "Caroline shared a drawing, not a painting" and is marked wrong; full context, Codex and Claude Code point out the same mistake and are marked wrong too; Pi is right on the other 151 questions (§5).
- effect: hurts
- reader: one case, found by the author. A GPT-4o-mini judge with a lenient rubric and "at least one wrong answer key" are stated limits (§6), so 99% on this conversation is near the ceiling and cannot separate the strong cells.

## Limits stated by the authors

- One conversation of LoCoMo's ten and one run per cell; differences of a few questions may not hold in a second run (§6).
- A GPT-4o-mini judge with a lenient rubric, and at least one wrong answer key (§6).
- The agents could read photo captions that the memory methods were not given (§6).
- The history fits every model's context window; results may differ on LongMemEval and on histories that do not fit (§6).
- Mem0 and Zep ran with default extraction and retrieval; costs are list prices and depend on each provider's caching (§6).

## Reader's notes

- The task is question answering over a chat log, not coding. The paper's coding-agent claim is that agents (Pi, Codex, Claude Code) search raw history well; whether this carries to a code repository or a long agent session is not tested.
- The models GPT-6 Luna and Claude Opus 5.5 are named as in the paper. Three models differ in vendor and in reasoning effort (high for two, none for GPT-4o-mini), so the "weak to strong" axis is not a clean single factor.
- Memory methods answer one question per call with a fixed template; agents start a fresh container per question (§2). The agents therefore have no memory across questions, which is the setting where designed memory is least useful for them.
- The judge is the same family as the weakest model. Its agreement with a stronger judge or with humans is not reported.
- Cost counts the build and every call, excluding the judge; whether Pi's cached input is priced at the cached rate is not stated.
- The paper does not give a variance or a test for any comparison.
