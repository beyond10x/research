## Question

When a project's instruction file disagrees with the existing code, do coding agents follow the file
or the code, and does one sentence in the user's own instruction file make them follow the code (Abstract, §1)?

## Findings

### F1 · practice · stale-instruction-line · E2
- practice: the agent receives a project instruction file that asks for one convention (for example print) while every existing module uses the other (logging); the feature request names no convention. Measured on the arm without the sentence: the share of the 4 or 5 choices per run that match the file, the code or neither (§4, §5.1).
- claim: "Without the sentence, 90.1% of the agents' choices followed the stale file" (Abstract); the agents "follow the file" (§1).
- evidence: 649 of 720 choices (90.1%) matched the stale file and 4.2% matched the existing code (§5.1, Figure 5a). Claude Code matched the file in 86.4% (95% CI 79.7 to 92.3, resamples of projects) and the code in 7.5%; Codex CLI matched the file in 93.9% (CI 90.7 to 96.7) and the code in 0.8% (Figure 5a). The file prevailed for both agents in 14 of 16 kinds of choice; the exceptions are Money and Configuration, where Claude Code followed the file in fewer than half of its choices (§5.1, Figure 5b; per-kind bars in the figure only).
- effect: hurts
- reader: numbers that describe the stale-file arm. The with-sentence arm is a comparison for the sentence (F4), not a control without a stale file, so the harm itself is not measured against agreement between file and code. Each kind appears in both directions across projects, so a model's general preference for one convention favours neither outcome (§4). Author-built synthetic projects of 3 to 8 modules, one feature per run (§8). Whether a human would have judged the file or the code correct in each choice is not examined.

### F2 · observation · stale-line-followed-despite-reported-conflict · E2
- practice: read, in the arm without the sentence, whether the agent's final reply names a conflict between file and code, together with which source the choices followed. A second model, Claude Opus 5.5, judged each reply without knowing condition, agent, task or code changes (§4, Appendix A).
- claim: "Claude Code pointed out the conflict in 79 of 80 runs and still followed the file"; the agent "treated the code as the part that was out of line" (Abstract, §5.2).
- evidence: Claude Code named the conflict in 79 of 80 runs, and in those runs 86.2% of its choices still matched the file (§5.2, Figure 6). Codex CLI named the conflict in 2 of 80 replies; in 60 of 80 runs it followed the file without mentioning the conflict (§5.2).
- effect: hurts
- reader: a count over the same 80 runs as F1, with no comparison. The judge is an LLM, though blind to condition and run with a criterion fixed before the first run (Appendix A). The finding says the agent saw the conflict; it does not say the agent should have chosen the code, which is the authors' premise.

### F3 · observation · rewrite-of-working-code-to-match-file · E2
- practice: with the stale file and no sentence, a Codex CLI run rewrote existing modules so that they match the file. A run counted as a rewrite when it removed 20 or more lines from Python files that existed before the run; the original test files were restored afterwards and run with held-out tests for the new feature (§4, §5.4).
- claim: "A stale file ... can lead an agent to break code that worked" (§1).
- evidence: Codex CLI rewrote existing code in 20 of 80 runs, across 12 of the 40 projects, removing a median of 198 lines from 9 files; the project's original tests then failed in 17 of the 20 runs (§5.4, Figure 7 shows one case, kanbanlite: an `Enum` replaced by string constants, `ImportError` for `Column`). Claude Code rewrote existing code in neither condition (§5.4).
- effect: hurts
- reader: the rewrites are a property of one agent and model (GPT-6 Sol under Codex CLI) with a 20-line threshold chosen by the authors. The rewrite was what the file asked for, so a failing original test is the cost of obeying the file, not an agent error in the usual sense. The effect of the sentence on rewrites is F5.

### F4 · practice · code-precedence-sentence-in-user-level-file · E4
- practice: add one sentence to the user-level instruction file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`): "When a repository's documentation and its existing code disagree, follow the conventions used in the existing code, and in your final reply point out each inconsistency you found between the documentation and the code." Every project was run with and without it, twice per agent and condition (§4).
- claim: the sentence "raised the share of choices that follow the code from 4.2% to 91.4%" (Abstract, §5.3).
- evidence: 658 of 720 choices (91.4%) matched the existing code with the sentence, 87.2 percentage points more than without (95% interval 83.6 to 90.9, resamples of projects) (§5.3). Claude Code 7.5% to 94.4%, Codex CLI 0.8% to 88.3% (§5.3, Figure 5a).
- effect: helps
- reader: E4: the same 40 projects, the same stale file, wording and place in context in both arms; only the sentence differs (§5.5). The sentence bundles two instructions, follow the code and report inconsistencies, and the two were not separated. The projects, kinds and stale files were built by the authors and the conflict is the only thing in the task; the sentence says exactly the case the task tests, so the size of the effect on real repositories with partial staleness is not measured. The authors evaluate their own sentence (`independent: false`). One model per agent, 2 runs per cell.

### F5 · practice · code-precedence-sentence-in-user-level-file · E4
- practice: as F4; the measurement is whether the agent rewrites existing code and whether the project's original tests plus held-out feature tests pass after the run (§4, §5.4, §5.5).
- claim: the sentence "stopped the rewrites and raised the test pass rate from 89.4% to 100%" (Abstract).
- evidence: tests passed in 89.4% of runs without the sentence and in all 160 with it. Codex CLI's pass rate rose from 78.8% to 100% and every one of its failing runs was a rewrite (§5.5). With the sentence no Codex CLI run rewrote existing code, against 20 of 80 without (§5.4).
- effect: helps
- reader: E4 by the same A/B as F4. All of the gain is from Codex CLI (Claude Code had no rewrites in either arm; 78.8% of 80 is 63 Codex passes, and 89.4% of 160 is 143, so Claude Code's 80 runs all passed without the sentence, reader's arithmetic). The tests encode the project's original conventions, so a pass rate here measures agreement with the code, not general correctness.

### F6 · practice · code-precedence-sentence-in-user-level-file · E0
- practice: as F4; the measurement is tool calls and running time per run (§4).
- claim: "Runs with the sentence also used slightly fewer tool calls and less time" (§5.5).
- evidence: no number, test or figure in the text; the paper says only that tool calls and running time were recorded and that they were lower with the sentence (§4, §5.5).
- effect: helps
- reader: asserted in one sentence of the text; the data may be in the released run records, which were not read. "Slightly" is the authors' word.

### F7 · practice · agent-reports-doc-code-conflicts · E4
- practice: as F4; the second clause of the sentence asks the agent to name, in its final reply, each inconsistency it found between the documentation and the code (§4). Measured by the blind Opus 5.5 judge (Appendix A).
- claim: with the sentence "both agents reported the conflicts they found in all 160 runs"; "Teams: use the conflicts the agent reports to correct the instruction file" (§5.3, Figure 8).
- evidence: reporting in all 160 runs with the sentence (§5.3). Without it Claude Code named the conflict in 79 of 80 runs and Codex CLI in 2 of 80 (§5.2).
- effect: helps
- reader: the contrast is a real A/B for Codex CLI (2 of 80 to 80 of 80) and near the ceiling for Claude Code. The clause is part of the same sentence as the precedence rule, so the report cannot be separated from it. That teams then use the reports to correct the file is not tested.

### F8 · practice · code-precedence-rule-in-agent-system-prompt · E0
- practice: the maker of an agent states in the system prompt that existing code takes precedence over the instruction file (§6, Figure 8).
- claim: "Users then get the rule without having to add it themselves"; the rule "can be placed in the agent's own system prompt, where it reaches every user without any action on their part" (§6).
- evidence: none. The study put the sentence in the user-level file, not in a system prompt (§4). Basis given in Figure 8 is §3 and §5.3.
- effect: helps
- reader: an extrapolation from F4. A system-prompt rule ranks differently from a user-level instruction, which is the mechanism the paper relies on (§3), and it was not run.

### F9 · observation · emphatic-instruction-file-preamble · E3
- practice: Claude Code introduces the instruction file with "IMPORTANT: These instructions OVERRIDE any default behavior and you MUST follow them exactly as written"; Codex CLI wraps AGENTS.md in an INSTRUCTIONS tag with no such line (§3, Figure 3). Nobody varied this; the two agents differ in both harness and model.
- claim: "The emphatic preamble in Claude Code is not needed" for the file to prevail (§5.5).
- evidence: Codex CLI, with no preamble, followed the stale file in 93.9% of its choices; Claude Code, with it, in 86.4% (§5.5, §5.1).
- effect: none
- reader: a comparison across two different agents and models, not a removal of the preamble, so it is E3 and the preamble's own effect is confounded with everything else that differs. It supports the narrower statement that the file prevails in a harness without the preamble.

## Limits stated by the authors

- The study covers 40 Python projects in which the instruction file is the outdated source, 16 kinds of convention, feature tasks completed in a single unattended run, and two agents: Claude Code with Claude Sonnet 5.5 and Codex CLI with GPT-6 Sol (§8).
- Results are reported per agent and per kind because "an overall rate can hide changes in opposite directions" (§4).
- The paper has no separate limitations section beyond §8.

## Reader's notes

- The mechanism (instruction hierarchy, instruction versus tool output) is argued in §3 from cited work and is "consistent with" the result (§5.5). No experiment varies how the file or the code reaches the model, so the attribution in the Abstract is E0 and no finding here rests on it.
- The prediction was fixed before the run and the sentence names the exact case the tasks test. In a real repository the agent must also decide which of many lines is stale; the study makes every conflict a clean two-convention choice.
- The agents are the authors' own choices of command-line settings (Appendix A): Claude Code ran with auto memory off and a dedicated config directory, Codex CLI with `-s danger-full-access`. The user-level file is the only variable.
- Prevalence of stale files is cited from other work, not measured here: 73.8% of AI configuration files in 441 company repositories committed once and never modified; 23.0% of 356 public repositories with instruction-file references to code that no longer exists (§2). Three cases of staleness in Supabase and OpenAI Codex lasted 13, 2 and 24 days (§2, Figure 2); they carry no claimed effect on agents and are not findings.
- The with-sentence arm cannot show that the agent would have been right to follow the code when the file, not the code, is the intended convention; the study builds only the case where the file is stale (§8).
- All 320 runs were valid; one run was repeated after a sandbox rejection (Appendix A).
- Pass rates are on the project's original tests plus held-out tests for the new feature; no review, readability or maintenance outcome is scored.
