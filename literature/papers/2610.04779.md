## Question

When several coding agents open pull requests in one repository at the same time, how should a
coordinator separate cheap signals (file overlap, learned risk scores) from the executable check
(`git merge-tree`) that decides whether two PRs merge textually (§1, §2)?

## Findings

### F1 · observation · merge-conflicts-without-authored-file-overlap · E2
- practice: pairs of concurrent agent PRs were replayed with `git merge-tree` and the textual conflicts were split by whether the two PRs' authored changed-file sets intersect (§5.1).
- claim: "79 conflicts (47.3%) occur despite disjoint authored file sets"; the cause is that authored diffs are measured against PR-specific bases and the merge against the common merge base, so branch history adds conflicts (Abstract, §5).
- evidence: 715 pairs, 167 conflicts, 88 with authored overlap and 79 without (§5.1). A detector that requires overlap has maximum recall 88/167 = 52.7% (§5.1). In 64/79 (81.0%) zero-overlap conflicts every conflicted path is in exactly one PR's authored diff (§5.1). Rebuilding both authored patches on the two-head merge base: 48 of 79 reconstructable, all 48 clean, 31 inconclusive (12 patch conflicts on the base, 7 absent paths, 1 binary, 2 clone failures, 9 other) (§5.3). File overlap alone has held-out AUROC 0.694 (Table 2).
- effect: hurts
- reader: counts of one stratified sample (cross-agent pairs enriched), so E2; the authors say neither prevalence nor AUROC is a population quantity (§5.1). The reconstruction check removes conflicts in 48 cases but has no comparison arm, and the authors say it validates the three-way-merge explanation and does not rule out branch staleness against the default branch (§5.3). The direction is about overlap as a conflict detector, not about an agent outcome.

### F2 · observation · file-overlap-sparse-collision-proxy · E2
- practice: authored changed-file lists of co-active PR pairs were counted for overlap in the scope corpus (§3.2).
- claim: file overlap is informative but not a safety predicate; "path collision and intent collision are not alternate encodings of the same target" (§3.2).
- evidence: 577,045 co-active pairs; 42,600 (7.38%) share any authored file; of these 65.0% share exactly one file and 33.9% share only configuration, documentation, CI, manifest or related files (§3.2). Of 6,945 near-duplicate-title candidates, 79.6% share no authored file (§3.2).
- effect: hurts
- reader: descriptive counts with no comparison, so E2. The scope corpus is a different sample from the replay set and the paper reports no conflict outcome for it. The effect is a statement about the proxy's coverage, not about agent success.

### F3 · practice · lineage-features-for-conflict-ranking · E4
- practice: rank PR pairs for replay with decision-time features of branch lineage (paths changed on the base-to-head history of each PR, one-sided touch, behind-base flags, base churn, branch age) added to authored-overlap and metadata features; a logistic model on 12 features, a lineage-union rule and an untuned random forest, fit on 218 dev pairs and tested on 497 repository-held-out pairs with 117 conflicts (§5.2).
- claim: "most of the gain comes from lineage state rather than authored-overlap features alone"; lineage state "substantially improves held-out prioritization" (§5.2, §10).
- evidence: held-out AUROC / PR-AUC, Table 2: file overlap 0.694 / 0.424, metadata risk 0.743 / 0.428, file-list LLM 0.732 / 0.555, lineage-union rule 0.877 / 0.611, 12-feature logistic 0.882 [0.845, 0.917] / 0.661, random forest 0.902 [0.875, 0.928] / 0.701. Feature-subset ablation, Table 3 (AUROC / PR-AUC / Brier): overlap-only 0.702 / 0.444 / 0.159; metadata-only 0.748 / 0.482 / 0.154; lineage-only 0.873 / 0.636 / 0.128; full 0.882 / 0.661 / 0.113. 30 alternative repository splits: median AUROC 0.876, range 0.829 to 0.901; lineage-only median 0.805 (Appendix A). Leave-one-agent-family-out AUROC 0.845 to 0.901; leave-one-language-out 0.835 to 0.950 (§9, Appendix A).
- effect: helps
- reader: an ablation of feature groups on one fixed held-out split, so E4 in the schema's sense, but the outcome is the ranking quality of a predictor for textual conflict and not agent success. The authors design the features and the benchmark (`independent: false`). The test set is 497 pairs from a stratified, cross-agent-enriched sample. At the dev-selected binary threshold the logistic recall is 49.6%, below file-overlap recall 53.8% (Appendix A), so the gain is in ranking only. The authors state that the random forest, not the logistic model, is the stronger baseline (§9).

### F4 · practice · replay-budget-triage-by-predicted-risk · E2
- practice: replay only the top share of PR pairs ordered by the predicted conflict score, with the budget fixed in advance (§6).
- claim: "At a 33.3% replay budget the learned models recover roughly 81-83% of held-out conflicts" (§10); the authors call this "the central operational result" (Appendix A).
- evidence: logistic model recovers 32.5%, 58.1%, 81.2% and 96.6% of 117 conflicts after replaying the top 10%, 20%, 33.3% and 50% of pairs, with precision 76.0%, 68.0%, 57.2%, 45.4%; random forest 32.5%, 57.3%, 82.9%, 96.6% (§6). Brier score 0.113 [0.096, 0.132] (§6).
- effect: helps
- reader: no baseline ranking (such as file overlap or random order) is run at the same budgets in the text, so there is nothing to compare against and the grade is E2. The conflict share in the test set is 117/497 = 23.5% (reader's arithmetic), so random order would recover about the budget share; the figure shows ROC curves only. The authors state that they have not shown that predicting is cheaper than running the checker (F5).

### F5 · practice · verify-every-pair-when-checker-cheap · E2
- practice: run the exact check (`git merge-tree`) on every PR pair and drop the predictor when the check is cheap (§6, Abstract).
- claim: "If local textual replay is available and cheap, verify every pair and discard the predictor"; triage matters only when the authoritative chain is costlier, rate-limited, remote or queued (§6).
- evidence: 5,940 timing records of local three-way replay: median 0.02 s, 90th percentile 0.38 s, 95th percentile 0.50 s (§6, Appendix A). End-to-end lineage-fetch timing was not recorded, and no net-savings claim is made (§6, §9).
- effect: helps
- reader: the timings describe the checker and nothing is compared with a triage run, so E2. The claim follows from the authors declining to show a saving, and is an argument for the exact check, not a measured gain. The result holds for a textual check only; build and test checks were not timed.

### F6 · practice · llm-conflict-judge-from-file-lists · E3
- practice: ask a language model (Claude Haiku 4.5) for a conflict verdict, confidence and rationale from the repository identifier and each PR's authored file paths (capped at 150 per side), with no merge result and no lineage (§5.1, Appendix B).
- claim: the file-list LLM "assigns low conflict probability to the zero-overlap stratum"; the authors call this "a result for that restricted information set, not a claim about language models in general" (§5.1, Figure 3).
- evidence: recalls 92.0% of overlap-visible conflicts and 2/79 (2.5%) of zero-overlap conflicts (§5.1). Held-out AUROC 0.732 [0.673, 0.787] and PR-AUC 0.555, against 0.877 / 0.611 for the lineage-union rule and 0.694 / 0.424 for file overlap (Table 2).
- effect: hurts
- reader: compared with the lineage rule on the same pairs, without randomisation, so E3. The LLM sees less information than the lineage models, so the contrast is about information, not about the model. One model, one prompt.

### F7 · practice · delay-pr-start-on-predicted-scope-overlap · E3
- practice: an online gate decides START or DELAY for each arriving PR using decision-time features (held-out AUC 0.66), delaying when the predicted chance of overlap with an open PR exceeds a threshold; replayed on 97 repository streams against observed order, FIFO serialisation and an oracle gate (§4.3).
- claim: scope-aware gating "removes observed collision exposure much more efficiently than full FIFO serialization" (Figure 2 caption); "scheduling-feasibility results under frozen labels and non-reactive agents, not claims that textual or semantic conflicts were prevented" (§4.3).
- evidence: 97 streams, 19,397 PRs, 38,526 observed scope-collision pairs (§4.3). Median de-overlap and median makespan inflation: FIFO 100% at 167.3% (bootstrap CI 114.2 to 195.7); oracle gate 100% at 33.4% (20.0 to 47.4); trained gate at threshold 0.20, 91.7% (81.2 to 97.5) at 65.0% (35.7 to 99.2) (§4.3, Appendix A). Excluding the two mega-repositories leaves the medians essentially unchanged (§4.3).
- effect: mixed
- reader: policies are compared on the same episodes, but in a simulation with fixed durations and agents that do not react to delay (§9), so E3. The outcome is a scope collision (a shared authored file), not a conflict or a defect; F1 shows that proxy misses about half of conflicts. Fewer collisions come with 65.0% longer makespan at the median.

### F8 · practice · forecast-file-overlap-from-pr-text · E3
- practice: predict at open time, from title, body, timing and repository metadata only, whether two open PRs will end up sharing an authored file (T1) (§4.1).
- claim: T1 "is therefore a useful planning heuristic, not a verification result", and the numbers "should not be read as saturating the task" (§4.1).
- evidence: frozen test set of 5,387 pairs from 229 repositories, 39.93% positive, trained on 24,283 pairs from 870 repositories. AUC: repository base rate 0.601, title Jaccard 0.629, TF-IDF cosine 0.644, repository-held-out logistic 0.644 pooled and 0.684 within-repository, four-feature fusion 0.676, zero-shot LLM 0.704, LLM plus all open-time features 0.740 (§4.1, Appendix B).
- effect: helps
- reader: a ladder of baselines on one test set, E3. The best score is 0.740 AUC, the authors' own benchmark and baselines. The LLM, its prompt and its version are not stated in the parts read. The target is a shared authored file, which F1 and F2 show is a weak proxy for conflict.

### F9 · observation · cross-agent-vs-same-agent-conflict-rate · E3
- practice: the conflict rate of replayed PR pairs from two different agent families was compared with pairs from one family (§3.1).
- claim: "We therefore do not claim a cross-vendor penalty"; agent-family effects "require larger matched replay" (§3.1).
- evidence: pooled, stratified replay: cross-agent 48/115 conflict (41.7%), same-agent 119/601 (19.8%). Within 60 repositories that have both kinds: same-agent 17/60 (28.3%), cross-agent 26/60 (43.3%); exact McNemar p = 0.078, 15 cross-only against 6 same-only discordant pairs. A composition check expects 37.4% cross-agent conflict (§3.1). In the filtered T2 pool: 31.8% against 20.9% (Appendix B).
- effect: none
- reader: groups were not assigned, so E3. The matched test does not reach p < 0.05, which is why `none`; the raw gap points the other way, and the sample is small and enriched for cross-agent pairs (115 of 716).

### F10 · observation · truncated-lineage-metadata · E3
- practice: lineage features of truncated or missing rows were zeroed in the held-out test as a stress test of the 12-feature model (§9, Appendix A).
- claim: "A deployment should therefore fall back to exact verification when lineage metadata is incomplete rather than treating missing state as evidence of safety" (§9).
- evidence: lineage missing for 1/715 pairs, 60/714 retrieved rows truncated, 44 truncated or missing rows in the held-out test. AUROC on the 453 untruncated test rows 0.904. Zeroing the eight lineage features for the truncated rows lowers AUROC from 0.882 to 0.791 and PR-AUC from 0.661 to 0.574 (§9, Appendix A). Eight of the 11 OneSidedTouch false negatives carry truncated lineage (Appendix A).
- effect: hurts
- reader: a comparison of the same model with and without the degradation, E3. Zeroing is a conservative construction by the authors, not how an operator would handle missing data. The fallback itself is not run.

### F11 · practice · repository-stratified-evaluation · E3
- practice: stratify merge-outcome estimates by repository, and hold out whole repositories in train and test splits (§4.1).
- claim: "A model can otherwise appear to learn interaction risk while mostly learning repository mixture"; pooled outcomes show Simpson reversals (§4.1).
- evidence: duplicate-title candidates: crude merge odds ratio 0.851, repository-stratified Mantel-Haenszel 1.507. Fix-in-flight candidates: 0.581 against 1.090 (§4.1). T1 logistic: 0.644 pooled and 0.684 within-repository (§4.1).
- effect: helps
- reader: crude against stratified estimates on the same data, E3. It is advice on how to evaluate coordination signals, with no agent-outcome measure. The matched cross-agent analysis in F9 has the same shape.

### F12 · practice · heuristic-orders-checks-checker-decides · E0
- practice: keep three signal classes apart: observable proxies (file overlap), learned scores that only rank, delay or escalate work, and executable checks that alone establish a property; extend to a chain of predicates, text, build, test, specification, where passing an earlier one is never taken as evidence for a later one; show the maintainer why work was delayed or escalated (§2, §7).
- claim: a heuristic failure "can waste verifier effort or latency, but it cannot by itself upgrade an unchecked pair into a certified one"; such explanations "calibrate trust better than a generic '87% conflict probability'" (§7).
- evidence: none. §7 says it is "a design implication rather than an empirical result"; no build, test, semantic or specification verifier is evaluated.
- effect: helps
- reader: asserted by the authors with no data, so E0. Only the textual predicate is tested in the paper, and F5 argues against even the triage layer when the check is cheap.

## Limits stated by the authors

- Textual property only: a clean `git merge-tree` result says nothing about build, tests, semantics, security or intent (§9).
- The lineage evaluation is small and stratified: 497 test pairs, 117 conflicts; the 715-pair set over-samples cross-agent pairs and is not population-representative (§9).
- Model headroom: the random forest at 0.902 beats the logistic model at 0.882, so the logistic model is not near an upper bound (§9).
- Repository, language and agent concentration remain external-validity concerns (§9).
- The default-branch tip at PR time was not kept, so the 79 zero-overlap conflicts may partly reflect branch staleness and not interaction between the two PRs (§5.3, §9).
- The scheduling replay freezes historical labels and durations and assumes agents do not react to delay (§9).
- Lineage-fetch cost was not captured, so no net-compute-saving claim is made (§9).
- The T2 artifact has no completed learned or LLM resolver run, so the trivial-resolution floor is not compared with modern resolvers (§4.2).
- The raw T2 hunk text is not released for licence reasons (§9).

## Reader's notes

- No agent was run by the authors. All data are recorded PRs, replayed with git, plus one LLM baseline; the paper says nothing about how agents would behave under the proposed gate or triage.
- The authors build the benchmark (MergeGym), the features and the baselines and report them; the prior measurement [1] (arXiv:2607.04697) used as background is by the same three authors.
- The 79.4% of agent PRs open concurrently with another agent PR (26,691 of 33,596 in AIDev-pop) is from prior work and is "used only as background" (§3.1, Table 1), so it is not a finding here.
- The T2 result (a trivial best-of-three resolution strategy matches 76.2% of 1,469 locatable hunks; later side 49.6%) is a description with no claimed effect on an outcome and is not a finding. The same holds for the T2 conflict yield by PR size (10.3% to 34.3%).
- The 12-feature model is graded on a fixed dev/test split chosen by a repository hash, with 50 and 117 conflicts; the interval widths in Table 2 do not include the choice of split, which Appendix A varies over 30 partitions.
- Schema fit: the paper is a benchmark and measurement study with no agent success outcome. `design: repo-mining` is the closest value; the closed set has no value for a replay-based predictor evaluation (see P11 in `SCHEMA.md` for a similar misfit).

## Discrepancies

- None found in the parts read. The 716 against 715 pairs (§3.1 against §5.1) and 601 against 600 same-agent pairs differ by one pair that has no authored file list, as §5.1 states.
