## Question

How does the merge probability of agent-authored pull requests vary by agent and over the life of a
repository, which tasks do they cover, and how do merged agentic PRs differ from merged human PRs in
size, review effort and bug-inducing commits (§1, §3.1)?

## Findings

### F1 · observation · merge-rate-by-agent-product · E3
- practice: nobody assigned a condition. Merge probability of closed agentic PRs compared across the 5 agent products, from a binomial mixed model with agent and quarter as fixed effects and repository as a random intercept (§4.1).
- claim: Claude has the highest model-adjusted merge probability, Devin the lowest; Claude's repositories are larger and more complex, Devin's are less popular (§4.1, Finding 1).
- evidence: model-adjusted merge probability (Table 3): Claude 84.3%, Codex 73.5%, Cursor 63.9%, Copilot 59.6%, Devin 43.0%. Odds ratios with Tukey-adjusted p (Table 5): Claude over Copilot 3.631 (p = 0.001), over Cursor 3.023 (p = 0.009), over Devin 7.098 (p < 1e-3); Claude over Codex 1.929 (p = 0.178); Copilot over Cursor 0.833 (p = 0.951); Copilot over Devin 1.955 (p = 0.073). Closed PRs per agent in the 309-repository set, Table 2: Codex 5,954, Devin 1,346, Copilot 1,218, Cursor 521, Claude Code 191.
- effect: mixed
- reader: E3, observational, with no control for task or repository beyond the random intercept. The raw merged shares in Table 1 rank the agents differently: Codex 5,451 of 6,057, Claude Code 166 of 219, Copilot 874 of 1,259, Cursor 291 of 541, Devin 512 of 1,355, i.e. 90.0%, 75.8%, 69.4%, 53.8% and 37.8% (reader's arithmetic). Claude Code PRs are 191 of 9,227 and come from 22 repositories, so its estimate rests on few repositories. Which PRs an agent opens, and who triggers it, is not observed.
### F2 · observation · merge-rate-over-repository-lifecycle · E3
- practice: nobody assigned a condition. Merge probability of agentic PRs by quarter of the repository's agentic activity span (first to last agentic PR split in four equal parts), from the same mixed model (§3.2, §4.1).
- claim: the quarter is not associated with merge probability after accounting for agent and repository; "no evidence of a systematic temporal effect" (§4.1, Finding 2).
- evidence: model-adjusted merge probability (Table 4): Q1 65.4%, Q2 63.7%, Q3 68.2%, Q4 67.7%. Pairwise odds ratios (Table 5): Q1/Q2 1.075 (p = 0.896), Q2/Q3 0.819 (p = 0.325), Q3/Q4 1.026 (p = 0.996). Human PRs, raw merged share by quarter: 0.850, 0.840, 0.856, 0.853 (§4.1).
- effect: none
- reader: E3, no control; the quarters are positions inside each repository's own span, so they are not calendar time and not the time since the agent was adopted. A repository's last agentic PR defines the end of Q4, which can bias the last quarter. The conclusion in §7 that Q3 PRs "are more likely to be merged" does not agree with this finding (see Discrepancies).

### F3 · observation · merge-rate-over-repository-lifecycle · E3
- practice: nobody assigned a condition. Per-agent merge rate by quarter, compared between consecutive quarters with a two-proportions z-test, pooled over repositories (§4.1, Figure 5).
- claim: merge rates rise over the span for Claude and Copilot and fall for Cursor and Codex; the authors read the rises as "a progressive adaptation between human developers and coding agents" and conclude there is no strong evidence of a systematic maturity effect (§4.1).
- evidence: significant consecutive-quarter differences only for Claude Q3 to Q4 (p = 0.0042), Copilot Q2 to Q3 (p = 0.0002) and Codex Q2 to Q3 (decrease, p = 0.00); for Copilot, Cursor and Devin the Q2 rate is below the Q1 rate (Figure 4, values in the figure only). Merge rate of Claude, Copilot and Devin is higher in Q4 than in Q1; Codex and Cursor have their lowest rate in Q4 (§4.1).
- effect: mixed
- reader: E3. The z-tests treat PRs as independent and ignore the repository effect that the mixed model in F2 handles, and they compare 3 pairs per agent without correction. The direction differs by agent, so "adaptation" does not explain all five. Claude Code has 191 PRs in 22 repositories, so a single repository can move its quarterly rate.

### F4 · observation · merge-rate-by-task-category · E3
- practice: nobody assigned a condition. Each agentic PR was summarised by gpt-4.1-mini, the summaries were clustered with BERTopic (36 clusters, merged to 24 topics by the first two authors), and the merge ratio per topic was compared after a parametric empirical Bayes shrinkage (§3.3.2, §4.2, Figure 7).
- claim: agents are used mostly for repetitive, low-complexity tasks (documentation, dependency management, testing); PRs for localised, well-defined tasks (GitHub Actions workflows, CI and build, dependencies, documentation, assets, typos) are merged at high and stable rates, and PRs for LLM integration, model evaluation, JSON templates and function implementation at lower or less stable rates (Findings 3 and 4).
- evidence: merge ratio of 0.80 or more, often above 0.90 in most quarters, for GitHub Actions workflows, CI and build, asset management, dependency, hook management, license and token management; 0.60 to 0.80 for UI, logging, async, type checking, translation, function implementation and cloud; at or below about 0.60 in at least one quarter for LLM integration, model evaluation and JSON template (§4.2.1). Topic labels checked on 100 stratified-sampled PRs: 87% correctly assigned, Cohen's kappa 84.2% between two authors (§4.2). Counts per topic are in Figure 6 only; no count or test per topic is in the text.
- effect: mixed
- reader: E3, a comparison between task groups with no control and no test for the differences. The task is inferred from an LLM summary of the PR text and a clustering the authors merged by hand, so the label, the PR and the outcome share one source. Token and license topics are the rarest and among the best merged; the authors read this as selection by developers, which is untested. This is an observation of where agents are used, not evidence that routing a task type to an agent raises merges.

### F5 · observation · merge-rate-by-task-category · E3
- practice: nobody assigned a condition. The merge ratio per topic compared quarter by quarter (§4.2.2, §4.2.3, Figure 8).
- claim: differences in mergeability between structured and complex task types shrink in the last quarter; categories move in different directions over the span (Finding 5).
- evidence: topic merge ratios in Q3 range from about 0.35 to 0.97; in Q4 many topics sit between about 0.60 and 0.75. Increasing over the quarters: function implementation, cloud, token management, UI. Decreasing: dependency and documentation gradually, asset management, test and simulation sharply. Stable: type checking at about 76% to 82%, hook management, typos, GitHub Actions workflows (§4.2.2). Some topics have no PR in some quarters, e.g. token management in Q2.
- effect: mixed
- reader: E3 at best: values are in Figure 8, no test, topic cells with few PRs. The explanations (growing review strictness, developer learning) are not tested. The statement that function implementation improves while test and dependency PRs decline should not be read as a trend without counts.

### F6 · observation · agent-pr-review-process-vs-human-pr · E3
- practice: nobody assigned a condition. Merged agentic PRs per agent compared with merged human PRs from the same repositories and quarters on contributors, commits, changed files, comments, changed lines and time to merge; Mann-Whitney U and Cliff's delta (§4.3, §4.3.1).
- claim: "no consistent differences between various agents, with meaningful effects limited to specific agents and metrics" (Finding 6).
- evidence: Table 7, Cliff's delta (agentic against human): Devin commits 0.344 (medium) and comments 0.365 (medium); Copilot contributors 0.281, comments 0.281, commits 0.171, time to merge -0.204, files -0.187, lines -0.174 (all small); Cursor contributors 0.279 and comments 0.239 (small); Claude files 0.255 and lines 0.287 (small); Codex commits -0.255, time to merge -0.210 and comments -0.148 (small). Between agents (Table 8): Codex against Copilot commits -0.580 (large), Codex against Devin comments -0.794 (large).
- effect: mixed
- reader: E3. Only merged PRs are compared, so a PR that needed too much review and was closed is not in the sample. The agents are used on different tasks and repositories (F1, F4), which the paper names as a possible explanation for Codex being fast to merge and Claude PRs touching more files, but does not control. The balanced sample is drawn per repository-quarter, so it does not match on task type.

### F7 · observation · agent-pr-review-process-vs-human-pr · E3
- practice: nobody assigned a condition. All merged agentic PRs pooled against all merged human PRs on the six metrics, without separating the agents (§4.3.2, §4.3.3).
- claim: the aggregate differences are statistically significant on five metrics but negligible in size; agentic PRs are on average merged slightly faster and receive more comments (Finding 6).
- evidence: Table 9 (Cliff's delta): contributors 0.075, commits 0.060, changed files -0.066, time to merge -0.146, comments 0.137, all p < 1e-3 and negligible; changed lines -0.018 (p = 0.296). Comments: same median of 1, mean 2.24 against 1.54, maximum 90 against 29 (§4.3.2). By quarter (Table 10), time to merge delta is -0.123, -0.118, -0.171, -0.183 for Q1 to Q4, the last two small; contributors delta stays below 0.11.
- effect: none
- reader: E3, no control. With 2,275 PRs per group, significance on negligible deltas is expected, so "none in practice" is the honest reading; the aggregate hides agent-level differences of up to a medium size (F6). The faster merge may reflect easier tasks (F4), as the authors say.

### F8 · observation · autonomous-agent-pr · E3
- practice: nobody assigned a condition. Share of merged agentic and human PRs that contain at least one bug-inducing commit, found by keyword-identified bug-fix commits and the SZZ implementation of PyDriller, compared per quarter with chi-square and Cramér's V (§4.3.4).
- claim: agentic PRs have "comparable to, and often lower than" the human bug-inducing rate; the authors conclude that agentic contributions "are not associated with increased defect risk" (Finding 7, §4.3.4).
- evidence: Table 12a, agentic against human: Q1 p = 0.560, V = 0.015; Q2 p = 0.110, V = 0.060; Q3 p = 0.175, V = 0.041; Q4 p = 0.021, V = 0.068; all negligible. The proportions themselves are in Figure 12 only; the text says the agentic share is lower in every quarter.
- effect: none
- reader: E3. SZZ with PyDriller has recall 0.67 and precision 0.39 without issue-date filtering in an outside evaluation, and the authors had no ground truth for these repositories (§6). Later PRs have less time to be blamed, and the paper does not say how it handled that for the Q4 PRs. A non-significant difference at these V values is not shown to be no difference. Only merged PRs are in the sample, and only Python.

### F9 · observation · bug-inducing-rate-over-repository-lifecycle · E3
- practice: nobody assigned a condition. Bug-inducing share of merged agentic PRs compared between consecutive quarters (§4.3.4, Table 12b).
- claim: the agentic bug-inducing rate declines between the second and third quarters, which the authors link to developers and reviewers becoming familiar with AI contributions and to better models (§4.3.4).
- evidence: Table 12b: Q1 against Q2 p = 0.760 (V = 0.009); Q2 against Q3 p = 0.001 (V = 0.109, small); Q3 against Q4 p = 0.691 (V = 0.012).
- effect: helps
- reader: one significant pair out of three, no correction, and the text reports no human trend across quarters for comparison. A quarter is a position in each repository's own span, and SZZ needs later fix commits, so later PRs are less likely to be flagged whatever their quality. The causal explanation is not tested.

### F10 · observation · reviewer-adaptation-to-agent-prs · E1
- practice: nobody assigned a condition. Two repositories' PRs read by the authors across quarters: instructor (Devin, PRs #1232 in Q1 and #1783 in Q4) and Kiln (Codex, PRs #387 in Q1, #648 and #693 in Q4) (§4.1).
- claim: as teams gain experience they "become more proficient at crafting effective prompts, evaluating agent-generated code, and integrating it" (§4.1).
- evidence: Devin PR #1232 needed several revision rounds ("Don't edit this file at all"; "you still edited the file, just revert the whole thing"), while PR #1783 in the same repository was merged after 13 of 15 automated checks passed with minimal discussion. Codex PR #387 (a narrow test-configuration task) merged in about one day after 14 checks; PR #648 took about two weeks; PR #693 was closed after about five weeks, with the developer noting "Codex did a decent job, but I had to fix a lot, especially on UI side".
- effect: mixed
- reader: E1, 5 cases picked by the authors; 2 merged quickly (#1783, #387) and 3 slowly or not at all (#1232, #648, #693). The PRs differ in task and size as well as in time. The paper has no data on prompts or on how reviewers changed; the claim about prompt skill is inferred, not observed.

## Limits stated by the authors

- Only five agents from one dataset, so agents outside it are not covered (§6).
- Only repositories with more than 100 stars and only Python; less popular or newer repositories may differ (§6). The authors expect, without data, that patterns generalise to other languages (§6).
- The lifecycle stage is defined as the span between the first and last agentic PR per agent-repository pair; other definitions could give other results (§6).
- Open PRs are excluded, and they may differ from closed ones (§6).
- SZZ is imperfect (recall 0.67, precision 0.39 in an outside study) and no ground truth was available (§6).
- Topic labels involve human judgement; some agent-assisted PRs may not be identifiable from metadata, and other confounders may remain in the human comparison (§6).
- All data come from GitHub (§6).

## Reader's notes

- The model-adjusted merge probabilities of Table 3 differ from the raw merged shares of Tables 1 and 2: Codex 90.7% raw against 73.5% adjusted, Claude Code 79.1% against 84.3% (Table 2 counts, reader's arithmetic). The abstract's emphasis on Claude and §7's "Claude generated PRs achieve the highest merge rates" holds only for the adjusted figure and the 22-repository Claude Code sample.
- The 9,428 closed agentic PRs overall merged at 77.4% (7,293 of 9,428; reader's arithmetic), against human PRs at 0.84 to 0.856 per quarter (§4.1). The paper does not compare the two merge rates directly and the human shares are raw, so a gap between agentic and human merge rate is not a finding of this paper. Li et al. [67] report human PRs merged more often (§5.2).
- All outcomes are observed after the fact in public repositories: merge, review counts, time to merge and SZZ-based defects. No finding involves an assigned practice, so none can be graded E4, and none says what a team should do to raise merge rates.
- Nobody knows who prompted each agent PR, with what instructions or context files, or how much a human edited it before opening. The paper's explanations about prompting skill and developer familiarity are therefore not testable here.
- Defects after merge are measured with an automatic proxy only; reverts, security smells and review outcomes are not measured.
- Task categories come from an LLM summary of the PR text, so the topic and the stated purpose of the PR are the same text; a PR whose body is a template can fall into the template's topic.
- Findings 3 and 5 explanations (developers delegating low-complexity tasks, becoming conservative in Q4) are speculation in the text; no developer was asked.

## Discrepancies

- §1 and §7 give Claude as the best-merged agent; Table 1 and Table 2 raw counts put Codex first (90.0% and 90.7%, reader's arithmetic). The text does not say that the adjusted and raw rankings differ.
- §7 says "PRs submitted during the third development quarter are more likely to be merged than those submitted during other stages". Finding 2 and Table 5 say no quarter comparison is significant.
- §4.3.1 states Cursor's LOC difference is not significant "(Cliff's δ = 0.375)"; Table 7 gives p = 0.375 and δ = -0.044 for that cell.
- §4.3.1 cites Table 8 for agentic against human comparisons of comments and lines; those are Table 7. The comments paragraph lists significant differences "only for Copilot, Cursor, and Devin", while Table 7 also has Codex at p < 1e-3 with δ = -0.148 (a lower comment count).
- §4.3.1 says only Claude differs significantly from human PRs in changed files, then states in the next sentences that Copilot and Cursor modify significantly fewer files; Table 7 has Claude, Copilot and Cursor significant (p < 1e-3, < 1e-3, 0.009).
- §4.2 names the original classifier "Gemini-4.1-Mini"; §3.3.2 names gpt-4.1-mini as the summariser used.
- §6 says construct validity has "four primary sources" and then lists five.
- §3.2 reports 539 repositories and per-agent counts of 304, 136, 58, 57 and 51; Table 1 and §1 give 489 repositories and 274, 123, 50, 52 and 50. The text attributes the difference to a validation step, without counts of what was dropped.

## Leads

- Li et al. [67], the AIDev dataset: agentic PRs against human PRs, with human PRs merged more often and agents better on documentation tasks; no arXiv id in the text.
- Peralta et al. [85]: 717 random agentic PRs read by hand; 35.7% of rejected agentic PRs were rejected because of the agent's failure, and 15.4% of merged ones needed human feedback or reviewer commits; no arXiv id in the text.
- Popescu et al. [86]: about 110,000 PRs from 5 agents; agentic code is retained less and churns more; no arXiv id in the text.
- Hora et al. [49]: over 48,000 agentic commits; 23% of agentic commits touch test files against 13% of human commits; no arXiv id in the text.
- Huang et al. [52] (agentic code carries more redundancy) and Agarwal et al. [2] (agent use associated with more code complexity), both on AIDev; no arXiv ids in the text.
