## Question

When a skill library grows from the skills known to help a task to a large library, how much does the pass rate fall, and is the fall caused by the agent picking wrong skills or by the larger context (§1, Abstract)?

## Findings

### F1 · practice · skill-library-expansion · E4
- practice: for each (task, model) pair, run the agent with only the task's authored helpful skills (the "oracle" bundle), then with the same skills hidden among libraries of 52, 102 and 202 skills; the added skills are the bundles of other SkillsBench tasks (§4, A.2).
- claim: "performance degrades as libraries grow—by up to 21% when scaling from a small set of helpful skills to a 202-skill library" (Abstract).
- evidence: pass-rate drop Δ, pooled over both models, Table 1: 0.08 [0.02, 0.15] at 52 skills, 0.14 [0.09, 0.19] at 102, 0.21 [0.15, 0.27] at 202. Haiku 4.5, Table 4: 0.10, 0.22, 0.26. Sonnet 4.6: 0.06 [−0.03, 0.15], 0.05 [−0.03, 0.13], 0.15 [0.06, 0.24]. Haiku's CI excludes zero from 52 skills, Sonnet's only at 202 (B.1). 38 pairs, 2,545 trajectories (§4). Whether the unit is binary or fractional pass rate is not stated for Tables 1 and 4.
- effect: hurts
- reader: same tasks, same agent, library as the only change, so E4. The authors' own experiment on a benchmark built by others. Pairs were kept only if the oracle skill lifted the pass rate by at least 4 points (A.1); selecting on a measured uplift can inflate the oracle baseline, and the paper does not say whether the filter runs and the baseline runs are separate samples. The drop at 202 skills is an average of 38 pairs over two models of one vendor. The agent harness is not named in the parts read.

### F2 · practice · skill-selection-failure-in-large-library · E3
- practice: split the drop of F1 by which skills the agent invoked in each trajectory (no skill, oracle skills only, or at least one distractor), and attribute it to a change in the shares of those events (skill shadowing) or to a change in pass rate within an event (context overhead) (§3, Eq. 10).
- claim: "skill shadowing dominates, accounting for up to 68% of degradation and serving as the only statistically significant effect" (§1); "the skill selection failure, not the enlarged context, is the primary bottleneck" (Abstract).
- evidence: shadowing component Δshd, pooled, Table 1: 0.03 [−0.01, 0.07] at 52, 0.08 [0.02, 0.15] at 102, 0.14 [0.06, 0.26] at 202, against Δ of 0.08, 0.14, 0.21. Share of trajectories that invoked only oracle skills, Table 2: 88.0% with the oracle bundle, 80.3% at 52, 64.4% at 102, 52.6% at 202; no skill invoked 12.0%, 16.1%, 28.3%, 38.5%. Bound Δshd,sup pooled, Table 6: 0.06 [0.01, 0.18], 0.14 [0.04, 0.29], 0.24 [0.09, 0.46]. Per model (Table 5): Haiku Δshd 0.17 [0.02, 0.37] at 202 against Sonnet 0.04 [−0.04, 0.15].
- effect: hurts
- reader: the split conditions on what the agent did after the library was assigned, so the events are not randomised; E3, not E4. The decomposition is exact by construction (Eq. 10), so the share assigned to each part depends on the definition of the events. 0.14 of 0.21 is 67% (reader's arithmetic); the "up to 68%" is not derived in the text. Per model, only Haiku shows a significant Δshd; for Sonnet no component separates from zero (Table 5).

### F3 · practice · enlarged-skill-listing-context · E3
- practice: the same split as F2; the context overhead is the part of the drop due to lower pass rate in the same invocation event when the library is larger (Eq. 10).
- claim: context overhead "remains small and indistinguishable from zero"; the point estimates are "suggestive only" (§4).
- evidence: Δctx pooled, Table 1: 0.06 [−0.11, 0.22], 0.06 [−0.11, 0.23], 0.07 [−0.13, 0.25] at 52, 102 and 202 skills. Bound Δctx,sup pooled, Table 6: 0.08 [−0.08, 0.29], 0.07 [−0.08, 0.31], 0.07 [−0.06, 0.34]. Binary pass rate within "oracle only" trajectories, pooled, Table 7: 0.52 with the bundle, 0.44, 0.45, 0.45 at 52, 102, 202; Haiku 0.43, 0.33, 0.26, 0.34; Sonnet 0.62, 0.57, 0.58, 0.51. Fractional, pooled, Table 8: 0.87, 0.83, 0.85, 0.80.
- effect: none
- reader: no difference was found, but every Δctx interval is 0.33 to 0.38 wide (reader's arithmetic), wide enough to hold the whole of Δshd; "indistinguishable from zero" is a power statement, as the authors say (§4). The point estimate of Δctx is positive at every size and the pooled within-event pass rate is lower than with the bundle at every size (Table 7), so "none" is the paper's reading, not evidence of no cost. For Sonnet, Δctx is at least Δshd at every size (B.1).

### F4 · observation · model-differences-in-skill-choice · E3
- practice: two models are compared on how their invocation shares change as the library grows (B.4).
- claim: "Haiku's failure mode under expansion is therefore abandonment"; "Sonnet's failure mode is wrong selection" (B.4).
- evidence: share of trajectories with no skill invoked, Table 10: Haiku 19.1% with the bundle, 23.2%, 46.5%, 65.9% at 52, 102, 202 skills; Sonnet 2.5%, 6.8%, 5.9%, 4.5%. Share invoking at least one distractor, Table 9: Haiku 0.02, 0.06, 0.05; Sonnet 0.06, 0.09, 0.14. Haiku oracle-only share 80.9% to 29.3%, Sonnet 97.5% to 81.4% (Table 10).
- effect: hurts
- reader: both models lose pass rate (F1), Haiku more (0.26 against 0.15 at 202 skills); the finding is that they lose it by different routes. Two models of one vendor and one size class each; the difference may be about these two models, not about model size. With the bundle alone and no distractors, Haiku already invokes no skill in 19.1% of trajectories (Table 10).

### F5 · observation · overlapping-skill-descriptions · E1
- practice: the most frequent distractor skills at 202 skills are listed with the task they displaced (A.4, Table 3); a distractor is any skill outside the task's bundle, "not adversarially constructed" (Definition 7).
- claim: a distractor whose description superficially matches the query better than the helpful skill can capture the agent; example of a skill that "invokes this wrong one in ALL 26 trajectories" (§1).
- evidence: first-picked distractor, number of trajectories at 202 skills (Table 3): video-frame-extraction for mario-coin-counting 51; senior-data-scientist for trend-anomaly-causal-inference 37; reflow_machine_maintenance_guidance for manufacturing-fjsp-optimization 14; csv-processing for econ-detrending-correlation 4; casadi-ipopt-nlp for energy-market-pricing 3. Of 494 trajectories at 202 skills.
- effect: hurts
- reader: a handful of cases selected as the most frequent ones; the paper does not give how many of the 38 pairs have any frequent distractor, or the pass rate of those trajectories. The distractors come from other tasks' bundles, so they are skills written for similar-looking tasks, which is the realistic case but not a sample of how a team's library grows. No description was edited, so the cause "description overlap" is the authors' reading of the examples.

### F6 · practice · retrieval-prefilter-for-skill-library · E0
- practice: filter the skill library by retrieval before the agent sees it, rewrite descriptions to disambiguate them, or route with a learned selector (§5).
- claim: "a natural next step is to attack this bottleneck directly through retrieval-based pre-filtering, description disambiguation, learned routing" (§5).
- evidence: none; no run of these methods is reported. Cited from outside: tool selection accuracy from above 90% with fewer than 30 candidates to 13.6% with 11,100 (§1, citing Gan and Sun, 2025).
- effect: helps
- reader: asserted as future work; the grade and effect record the claim only. The cited tool-selection figure is about tools, not skills, and is not tested here.

## Limits stated by the authors

- The study covers 202 skills and two models from a single provider; whether the patterns hold at ten times the size or on other architectures is open (§5).
- The context overhead is possibly real, but the sample is too small to confirm it (§4).
- Cells with fewer than 5 valid trajectories are left empty, and the mixed and no-skill buckets are sample-limited (B.3).

## Reader's notes

- All findings are on SkillsBench, whose tasks and skills were written by others; the authors' contribution is the decomposition and the experiment. No system of the authors is evaluated, so `independent` is true.
- Only tasks where the oracle bundle already helps are in the sample (A.1). Libraries made of skills that help on no task, or tasks with no helpful skill in the library, are not covered.
- The library grows by adding the bundles of other benchmark tasks (A.2). Each bundle is written for a different task, so overlap in scope comes from benchmark tasks that are alike, not from duplicate or near-duplicate skills.
- The number of runs per (task, model, library) cell, the agent harness and the sampling settings are not given in the parts read; the CIs resample pairs and then trajectories (A.3).
- The mitigations the authors name (F6) are not tested; the paper gives no run with a pre-filter or edited descriptions.
- Table 2 and Table 10 give pooled trajectory counts of 552, 542, 988 and 494 (sum 2,576, reader's arithmetic), against 2,545 in §4 and A.1; see Discrepancies.

## Discrepancies

- §4 and A.1 give 2,545 trajectories, with Haiku/Sonnet counts of 303/233 (bundle only), 297/233 (52), 544/441 (102), 273/221 (202). Table 10 gives 314/238, 306/236, 546/442 and 273/221, summing to 2,576 (reader's arithmetic). Only the 202-skill counts agree.
- B.3 says the binary pass rate within "oracle only" "falls monotonically with library size on both models". Table 7 does not: Haiku 0.43, 0.33, 0.26, 0.34; Sonnet 0.62, 0.57, 0.58, 0.51; pooled 0.52, 0.44, 0.45, 0.45.
- B.3 says the fractional pass rate within "oracle only" "drops by less than the binary pass rate at every library size", and gives ".87 → .80 vs. pooled p: .52 → .45 at |S|=202". Both drops are 0.07 at 202 skills (reader's arithmetic).
- §4 says "both Δctx and Δshd grow with library size". Δctx in Table 1 is 0.06, 0.06, 0.07 with intervals of about 0.35 width, so it is flat in practice.
- §1 says the agent invoked video-frame-extraction "in ALL 26 trajectories" for mario-coin-counting; Table 3 gives 51 first-picked trajectories for the same pair at 202 skills. Not explained in the parts read (the 26 may be one model).
- Haiku's Δ at 52 skills is 0.10 [0.03, 0.18] in Table 4 and 0.10 [−0.08, 0.28] in Table 5. The two tables use different bootstrap schemes (percentile of trajectories against two-stage clustered); B.1 says only that Haiku's drop "separates from zero already at |S|=52".
