## Question

Do repository context files such as `AGENTS.md` and `CLAUDE.md` improve a coding agent's task
success, and what do they change in its behaviour and cost (§1)?

## Findings

### F1 · practice · generated-instruction-files · E4
- practice: generate the context file with the agent's own recommended initialisation command (`/init` and equivalents) and model, then run the agent with it; compared with the same tasks and no context file (§4.1).
- claim: LLM-generated context files "have no significant effect on performance"; the authors "suggest omitting LLM-generated context files for the time being" (§4.2, §1).
- evidence: success rate with file against without, Table 5. SWE-bench Lite: Sonnet-4.5 58.7 against 59.9, GPT-5.2 54.4 against 56.6, GPT-5.1 Mini 47.6 against 47.7, Qwen 32.4 against 31.1. CTX-Bench: 65.2 against 73.2, 68.1 against 65.2, 50.7 against 54.3, 47.1 against 45.7. Lower in 5 of 8 settings; average change −0.5 and −2 (§4.2). Cochran-Mantel-Haenszel p = 0.87 and p = 0.37 (Table 3).
- effect: none
- reader: an ablation on equal tasks, so E4. One sample per task; standard errors of 2.7 to 4.3 points per cell (Table 5) are larger than every average change. "No significant effect" is not evidence of no effect at this sample size. Python only (§5).

### F2 · practice · generated-instruction-files · E4
- practice: as F1; the measurement is steps and inference cost per task.
- claim: they "increase the # steps in every setting ... leading to a significant ... cost increase of 20% and 23% on average" (§4.2).
- evidence: Table 2. Steps rise by 2.45 on SWE-bench Lite and 3.92 on CTX-Bench on average. Cost per task, without and with file, SWE-bench Lite: Sonnet-4.5 $1.30 and $1.51, GPT-5.2 $0.32 and $0.43, GPT-5.1 Mini $0.18 and $0.22, Qwen $0.12 and $0.13. Stratified permutation tests, Table 6: cost p < 0.00001 (SWE) and p = 0.00064 (CTX); steps p = 0.0287 and p = 0.00004. Reasoning tokens rise 22% for GPT-5.2 and 10% for GPT-5.1 Mini on SWE-bench Lite, 14% and 10% on CTX-Bench (§4.3).
- effect: hurts
- reader: the 20% and 23% are unweighted means of four per-model increases that range from 8% to 50% (reader's arithmetic from Table 2). The Qwen cost is an estimate from a public API price for a locally served model (§4.1).

### F3 · practice · instruction-files · E4
- practice: run the agent with the context file the repository's developers committed, taken at the state before the task's PR; compared with no file and with a generated file on the same 138 tasks (§4.1).
- claim: developer-provided files "improve agent performance by 2.4% on average (p = 21%), significantly outperforming LLM-generated ones (p = 3.8%)", and raise steps and cost (§4.2).
- evidence: CTX-Bench success with developer file against none, Table 5: Sonnet-4.5 70.3 against 73.2, GPT-5.2 68.1 against 65.2, GPT-5.1 Mini 55.8 against 54.3, Qwen 53.6 against 45.7. Table 3: against none p = 0.21, against generated p = 0.038. Steps +3.34 on average (§4.2); steps p = 0.00002 and cost p = 0.0126 (Table 6).
- effect: mixed
- reader: E4 by design. The gain over no file is not significant; the only significant success-rate result in the paper is developer-written against generated. The 12 repositories were selected because they have a context file, and the files average 641 words in 9.7 sections (Table 1). This is the first controlled finding on the practice that 2604.09388 F1 reports from experience.

### F4 · practice · instruction-files · E3
- practice: name a tool or a command in the context file.
- claim: "instructions in the context files are well followed"; the missing gain "is not due to a lack of instruction-following capabilities" (§4.3, A.2).
- evidence: `uv` is used 1.6 times per task when the file mentions it against fewer than 0.01 when it does not; repository-specific tools 2.5 times against fewer than 0.05 (§4.3). With a context file agents run more tests and more search, read and write commands (§4.3, Figures 5 and 11; values in the figures only).
- effect: helps
- reader: a comparison between files that mention a tool and files that do not, not a randomised one; the tools a file mentions are likely the ones the repository needs. Tool-call intents were labelled by an LLM judge, GPT-OSS-120B (A.2).

### F5 · practice · repository-overview-in-instruction-file · E4
- practice: put a codebase overview (directory listing and descriptions) in the context file. 8 of the 12 developer files and 95% to 100% of the files generated by three of the four models have one (§4.3).
- claim: context files "do not provide effective repository overviews": they do not reduce the number of steps before the agent first touches a file that the reference patch changes (§4.3, Figure 4).
- evidence: Figure 4, values not in the text. Removing the overview section from the generated file, GPT-5.2 only: CTX-Bench accuracy 62.32% against 68.12% (p = 0.15), cost $0.4027 against $0.4715 (p = 0.24); SWE-bench Lite 54.20% against 54.36% (p = 0.73) (Table 7).
- effect: none
- reader: E4 by design for the with and without comparison; the numbers behind the main claim are in a figure. The removal ablation is one agent, one run.

### F6 · practice · testing-instructions-in-instruction-file · E4
- practice: put test-running instructions in the context file; the ablation removes that section from the generated file with GPT-5.4 and reruns GPT-5.2 (Appendix B).
- claim: "the testing category leads to a significant increase in cost in both" benchmarks; "no category has a significant positive or negative effect on benchmark accuracy" (Appendix B).
- evidence: Table 7. Without the testing section: CTX-Bench cost $0.3730 against $0.4715 (p = 0.023), accuracy 66.67% against 68.12% (p = 0.80); SWE-bench Lite cost $0.2756 against $0.3272 (p = 0.0035), accuracy 57.72% against 54.36% (p = 0.099). Without the tooling section, SWE-bench Lite cost $0.2715 (p = 0.0012).
- effect: hurts
- reader: one agent, one run. The benchmark scores a task by its tests passing, so extra test runs by the agent can cost money without moving the score; the paper does not measure defects outside the benchmark's tests.

### F7 · practice · generated-instruction-files · E4
- practice: generate the context file with a stronger model, or with another agent's generation prompt (§4.4).
- claim: "stronger models do not necessarily generate superior context files"; "sensitivity to good prompts is overall small" (§4.4).
- evidence: files generated by GPT-5.2 or Sonnet-4.5 and used by GPT-5.1 Mini and Qwen: success improves 2% on average on SWE-bench Lite and worsens 3% on CTX-Bench (§4.4, Figure 7). Codex prompt against Claude Code prompt: no consistent winner across agents and benchmarks (§4.4, Figure 8).
- effect: none
- reader: small grids of single runs; the conclusions rest on the sign pattern, with no test stated.

### F8 · practice · instruction-files-without-other-docs · E4
- practice: remove all other documentation from the repository (`.md` files, example code, `docs/`) after generating the context file, then run the agents with and without context files; Claude Code excluded for cost (Appendix B).
- claim: then LLM-generated context files "consistently improve performance by 2.7% on average" and outperform developer-written ones; generated files "are mostly redundant with existing documentation" (Appendix B, Figure 12).
- evidence: the 2.7% only; the per-agent values are in Figure 12. No test or n in the text.
- effect: helps
- reader: the design is a controlled contrast and the one place the paper shows a gain from generated files. The caption says "tend to outperform", the text "consistently".

### F9 · observation · instruction-file-length · E3
- practice: none applied; the results are binned by context-file length (Appendix B, Figure 13).
- claim: "no clear dependency between the success rate or the per-instance cost and the context file length" (Appendix B).
- evidence: Figure 13, values not in the text; no statistic stated.
- effect: none
- reader: a visual binning of an existing result.

## Limits stated by the authors

- The evaluation covers Python only; tooling knowledge for Python may already be in the models (§5).
- Effects of context files on efficiency and security are not evaluated (§5).
- Better ways to generate context files are left to future work (§5).
- Per-repository estimates are noisy; most SWE-bench Lite tasks come from one repository, django (Figure 10 caption).

## Reader's notes

- The task descriptions, the tests and the execution environments of CTX-Bench were produced by LLM agents (GPT-5.2 in Codex) and reviewed by the authors; 138 tasks remain from 5,694 PRs (§3.2).
- Claude Code ran with its Task tool enabled, so Sonnet-4.5 could call Haiku-4.5 sub-agents (A.1). The paper does not say whether sub-agent work is counted in steps and cost.
- The score is tests passing on the benchmark's tests. Conventions, style and review outcomes, which instruction files usually address, are not scored.
- Pre-cutoff shares of CTX-Bench tasks are 17% (Sonnet-4.5), 40% (GPT-5.2) and 12% (GPT-5.1 Mini, Qwen); the contamination check is a figure with no test named (Appendix B).
- The stratification variable of the tests in Tables 3 and 6 is not stated in the parts read. The ± of Table 2 is not defined in its caption.
- The developer-file advice in §1, to include only instructions "not already present in the README", is the authors' recommendation; F8 is the experiment closest to it.

## Discrepancies

- §1 says developer files outperform generated ones "by a significant margin of 7% on average". Table 5 gives +5.1, 0.0, +5.1 and +6.5 points for the four agents, a mean of 4.2 (reader's arithmetic); §4.2's own averages (+2.4 and −2) imply 4.4.
- §4.2 says developer files raise cost by "at most 19%". From Table 2 the four increases are 13%, 42%, 6% and 15%, a mean of 19% and a maximum of 42% (reader's arithmetic).
- Table 5 labels its second block "Plan-Bench"; the caption and the Dev row identify it as CTX-Bench.
- Table 7's "Full" cost for GPT-5.2 ($0.4715 on CTX-Bench, $0.3272 on SWE-bench Lite) differs from Table 2's cost for the same setting ($0.57 and $0.43). Not explained in the parts read.
- Table 7's SWE-bench Lite accuracies do not correspond to whole counts out of 300 (reader's arithmetic); the CTX-Bench ones match counts out of 138.
- §4.2 writes p-values as percentages ("p-values of 87% and 37%", "p-value < 0.001%"); Tables 3 and 6 give 0.87, 0.37 and < 0.00001.
- Figure 4 and Table 6 call the developer condition "Human"; the rest of the paper calls it "Dev".
