## Question

Do the first 5k to 20k tokens of a coding-agent run tell apart a successful from a failed attempt on the
same issue, and does stopping and restarting a run on that signal beat letting it continue under a shared
token budget (§I, RQ1 to RQ3)?

## Findings

### F1 · observation · task-solve-rate-baseline · E3
- practice: outcomes of repeated runs cluster by task. A predictor that knows a task's solve fraction, computed from a reserved half of that task's attempts, is compared with predictors that use issue and prefix counts (§III.D, §IV.A, §IV.C).
- claim: static task solvability explains most of the outcome variation that pooled ranking picks up; "static task properties account for a substantial share of outcome variation" (§IV.A).
- evidence: intraclass correlation 0.797, 0.768, 0.713 and 0.815 across the four settings (Table I). Task-rate predictor at 5k tokens: pooled AUC 0.97 and within-task AUC 0.50 by construction, against pooled 0.58 for issue plus prefix counts (§IV.C, Figure 2). Adding the counts to the task rate leaves pooled AUC at 0.97.
- effect: helps
- reader: the comparison is between predictors on the same runs, with no randomisation, so E3. "Helps" is the effect on pooled ranking only; the same predictor has no within-task value. The oracle uses outcomes of the same task's other attempts, so it is an upper bound and not a deployable monitor (the paper calls it diagnostic).

### F2 · practice · early-prefix-features-for-outcome-prediction · E4
- practice: add 18 behavioural count features from the execution prefix (files inspected, repeated shell commands, error outputs, edits, test invocations) to 8 pre-execution issue features in a logistic regression, with unseen-repository cross-validation (§III.D).
- claim: "Early action counts and static metadata yield modest gains in cross-task pooled ranking (0.02–0.04 AUC)"; frozen embeddings of the initial turn give no consistent gain (§IV.B).
- evidence: primary corpus, issue only against issue plus prefix: pooled AUC 0.56 to 0.58 at 5k tokens (log loss 0.69 in both), 0.57 to 0.61 at 20k. Embeddings at 5k: pooled AUC 0.62 in both arms, log loss 0.67. Cross-task pairs within one repository: 0.56 [0.55, 0.59] at 20k against 0.49 for same-task pairs. Task categories and language add about 0.02 pooled AUC and less than 0.01 within-task (§IV.B).
- effect: helps
- reader: an ablation of the feature set on identical splits, so E4. The gain is on pooled ranking, which the paper attributes to cumulative interaction rates that "correlate with underlying issue difficulty", so it is not evidence of attempt-level signal. Primary corpus only for the 5k and 20k pooled numbers.

### F3 · practice · early-prefix-within-task-ranking · E4
- practice: score runs on the same issue with count models, frozen embeddings, a task-conditional logistic model fit on mixed-outcome tasks, and cross-setting transfer, and measure AUC within task. A label-permutation control inside each task and equivalence tests (TOST, bounds [0.45, 0.55] and [0.47, 0.53]) are applied (§III.C, §III.D, §IV.C).
- claim: early prefixes give near-chance discrimination between successful and failed attempts on the same task, although 87.51% of runs have already run a test command by 20k tokens (§IV.C, §V).
- evidence: within-task AUC 0.50 [0.49, 0.51] at 5k for counts; 0.49 [0.48, 0.50] for embeddings (Figure 2). At 20k, task-conditional model 0.50 [0.49, 0.51] over 38,447 pairs from 1,737 mixed-outcome tasks, inside both TOST bounds; OpenHands/Qwen3.5 0.50 [0.48, 0.52], OpenHands/MiniMax-M2.5 0.51 [0.49, 0.53], SWE-agent/Qwen3.5 0.48 [0.45, 0.52]. Transfer between settings at most 0.50 in all three pairs. 87.51% of active runs have run a test and 32.80% have edited at 20k (§III.B).
- effect: none
- reader: the permutation control and issue-only reference are the control, so E4. A null result: intervals of about plus or minus 0.02 exclude gains larger than that, but not smaller ones. No TOST claim is made for SWE-agent/Qwen3.5 because its permutation control deviated from 0.50. Features are action counts, not content of what the agent found.

### F4 · practice · fine-tuned-small-monitor-on-prefix · E4
- practice: fine-tune Qwen3-0.6B with LoRA and a linear head to predict final resolution at 20k tokens from the issue text plus the latest prefix messages, trained on matched success-failure pairs from one task, against the same model given the issue only (§III.E).
- claim: the "end-to-end neural monitor" does not recover attempt-level signal that count features and embeddings miss (§III.E, §IV.C.3).
- evidence: 32,406 attempts from 2,946 tasks, three seeds, three repository-disjoint folds. Within-task AUC 0.50 [0.48, 0.51] over 16,818 pairs from 859 mixed-outcome tasks; per fold 0.500, 0.496 and 0.490 (Table II). Log loss with prefix 1.788, 1.012 and 0.879 against 0.693 for issue only; pooled AUC 0.523, 0.504 and 0.469 against 0.526, 0.513 and 0.527 (Table II).
- effect: none
- reader: an ablation (issue only against issue plus prefix) on identical splits, so E4. The adapted monitor omits the intermediate test supervision and state-preserving edit transfer of the original design (§VI.b), so this is not a test of that design. One model size, 4,096-token input.

### F5 · observation · within-task-ranking-by-solve-rate-tier · E3
- practice: within-task AUC at 20k tokens on tasks grouped by empirical solve rate: low (below 25%), medium (25 to 75%) and high (above 75%) (§IV.C.4, Table III).
- claim: easier issues show the same near-chance early ranking as harder ones (§IV.C.4).
- evidence: count model 0.513 [0.484, 0.541] on 373 low-solve tasks, 0.488 [0.476, 0.502] on 800 medium, 0.496 [0.475, 0.519] on 564 high; neural monitor 0.504, 0.491 and 0.503 on 170, 405 and 284 tasks. Every interval contains 0.50 (Table III).
- effect: none
- reader: the tiers are post-hoc and descriptive, as the caption says, and tier membership is defined from the same outcomes that are ranked. No test across tiers.

### F6 · observation · within-task-ranking-by-token-landmark · E3
- practice: within-task AUC of the issue-plus-prefix count model at later token landmarks, and at run end for a reference-patch measure (§IV.C, §V).
- claim: separation appears only late, when much of the budget is spent or most runs have ended (§V.a).
- evidence: primary corpus, 0.52 [0.51, 0.53] at 30k (93% of runs active), 0.54 [0.53, 0.55] at 40k (69% active), 0.56 at 60k (23% active). Reference-hunk recall at run end: 0.62 [0.61, 0.64]. At 30k and 40k the three Open-SWE settings stay indistinguishable from chance.
- effect: mixed
- reader: discrimination rises with the landmark but the active population falls, and the survivors are selected by run length, which the paper names "selective attrition". Different landmarks cover different run subsets, so the trend is not a clean within-run comparison. The 0.62 uses the reference patch, which a deployed monitor does not have.

### F7 · practice · score-guided-restart-vs-random-restart · E4
- practice: at 20k tokens, abort runs scoring below a percentile threshold of the pooled issue-plus-prefix count model and start one cold replacement attempt drawn from the other recorded attempts on that task; compared with aborting the same fraction of runs at random. Replay on recorded runs, under a shared token cap (§III.F).
- claim: under a 75k cap, learned restart beats matched random restart by up to 1.98 percentage points, in two of four settings (Abstract, §IV.D).
- evidence: median threshold, 75k cap, learned minus random: OpenHands/Qwen3-Coder −0.458 [−0.677, −0.219], SWE-agent/Qwen3.5 +1.984 [+1.313, +2.600], OpenHands/Qwen3.5 +0.768 [+0.302, +1.221], OpenHands/MiniMax-M2.5 −0.663 [−1.014, −0.333] (Table IV). Uncapped replay: differences within 0.20 percentage points in all four settings (§IV.D).
- effect: mixed
- reader: matched random restart is a control on equal tasks, so E4, but the runs are recorded and the replacement is a sample of recorded attempts, not a live restart. The sign differs by setting. The score that drives the policy is mostly task difficulty (F1, F3), which F8 uses to explain the result.

### F8 · observation · stopping-gain-from-task-selection · E3
- practice: an exact algebraic decomposition of the learned-minus-random solve-rate difference into a between-task term (how stops are spread over tasks) and a within-task term (aborting the weaker attempt of the same task), at the 20k landmark, 75k cap (§III.F, Eqs. 4 to 6, Table V).
- claim: the gain over random restart "stems almost entirely from between-task stopping allocation", and attempt-level selection within a task contributes near zero (Abstract, §IV.D.1).
- evidence: total, between, within in percentage points: OpenHands/Qwen3-Coder −0.458, −0.494, +0.036; OpenHands/MiniMax-M2.5 −0.663, −0.704, +0.042; OpenHands/Qwen3.5 +0.768, +0.881, −0.113; SWE-agent/Qwen3.5 +1.984, +1.749, +0.235 (Table V). Between term spans −0.70 to +1.75, within term −0.11 to +0.24 (§IV.D.1).
- effect: none
- reader: effect is on the within-task term, which is near zero; the total is F7. The decomposition is arithmetic on the replay and is exact, but it describes four point estimates, with no interval on the components, and components are rounded independently (Table V caption).

### F9 · practice · cold-restart-vs-continuation · E4
- practice: compare learned and random cold restart at 20k tokens with letting the run continue, under the same hard token cap of 30k, 50k, 75k or 100k, over seven score thresholds and four settings: 224 restart configurations. The replacement attempt gets the residual cap minus 20k (§III.F, Eqs. 2 and 3).
- claim: "uninterrupted continuation achieves higher solve rates at lower mean token cost than both restart policies" (Abstract, §IV.D.2).
- evidence: 75k cap, continuation against median learned restart: 46.15 against 41.53, 28.71 against 20.66, 27.19 against 20.16 and 41.05 against 35.76 (Table IV); in SWE-agent/Qwen3.5 mean cost 68.10k tokens against 69.93k (§IV.D.2). Continuation dominates 56 of 56 configurations at 75k and 55 of 56 at 100k; 49 of 56 at 30k with 7 ties and 56 of 56 at 50k, so 216 of 224 overall (Table VI). The one non-dominated point is +0.0033 percentage points at +376 mean tokens.
- effect: hurts
- reader: continuation is the control on the same tasks, so E4, again on recorded runs. The result depends on the cap: at 30k and 50k, 91% to 100% of trajectories need more than the residual tokens (§IV.D.2), so a cold replacement can rarely finish, and the paper's own "cold restart discards 20k tokens" mechanism is not tested separately. Cost counts transcript tokens only (§VI.b). A warm restart is not tested here (see F11).

### F10 · practice · alternative-harness-same-model · E3
- practice: compare the two agent frameworks, SWE-agent and OpenHands, with the same model (Qwen3.5-122B) on the 7,102 tasks both corpora share (§IV.A).
- claim: framework choice moves the solve rate by more than any mid-run restart does (§V.c).
- evidence: mean solve rate 47.30% for SWE-agent against 33.24% for OpenHands, difference 14.06 percentage points [12.26, 15.95]; Spearman correlation of task solve rates 0.67 (§IV.A).
- effect: helps
- reader: two released corpora produced by a third party, with no assignment, so E3. Prompts, tool sets, step limits and run counts per task may differ between the two corpora; the paper does not list them. "Helps" is for SWE-agent. The 14.06 is uncapped; under the 75k cap SWE-agent resolves 28.71% (§IV.D.2).

### F11 · practice · state-preserving-restart-vs-cold-restart · E3
- practice: restart an aborted run while keeping its code edits and test diagnostics, against a cold restart. The paper reports this from related work and does not run it (§II.c, §V.c).
- claim: "cold prefixes lack attempt-level signal, retaining intermediate edits and test diagnostics is essential" (§V.c).
- evidence: second-hand from ref. [7], Qwen3.6-27B at a 25% false-positive target: resolution 66.6% to 71.8% with saved edits transferred, 66.8% with a cold restart (§II.c).
- effect: helps
- reader: the numbers are quoted from another paper and were not reproduced here; the grade is that paper's comparison, a before and after with no stated control in the text. The recommendation is the authors' reading of it.

### F12 · practice · pre-execution-routing-by-difficulty · E0
- practice: use static issue signals to provision tokens or route the issue to a solver before execution, in place of a mid-run stop (§V.c.1).
- claim: static signals "naturally support up-front token provisioning and solver routing", and abort-only stopping at 20k is "strictly dominated by pre-execution filtering at zero token cost" (§I, §V.c).
- evidence: no routing or filtering policy is run. The supporting numbers are pooled AUC 0.56 for the issue baseline at 5k (§IV.B) and the 14.06-point framework difference (F10).
- effect: helps
- reader: asserted from F1 to F3 and cited work ([9], [22]); no test of routing in this paper. The pooled AUC of 0.56 to 0.61 is weak for filtering, so the strength of the recommendation is not shown.

## Limits stated by the authors

- Public corpora: labels and trajectories reflect the original harnesses; transcript tokens ignore provider caching discounts and tool latency (§VI.a, §VI.b).
- The neural monitor drops intermediate test supervision and state-preserving edit transfer; the editor-tool heuristic can match file views as well as edits; replay gives zero credit to partial edits over the residual budget; Open-SWE task categories may come from post-hoc curation (§VI.b).
- Four open-weight settings, Python-centric benchmarks, linear and embedding classifiers and a 0.6B monitor; monitors that probe internal representations or use verifier feedback may differ; within-task discrimination needs mixed-outcome tasks (§VI.c).
- Bootstrap intervals resample out-of-fold predictions without refitting; intervals at 20k are unadjusted; Pareto dominance rests on point estimates (§VI.d).

## Reader's notes

- No agent was run by the authors. Every number is a replay or a model fit on recorded runs, so a live restart, with a replacement that sees different state, is not tested.
- The replay draws the replacement from recorded attempts of the same task. Where a task has few attempts the draw is limited; the paper does not give attempts per task for the replay.
- All four settings are open-weight models; no Claude or other closed-model setting, and no interactive human use.
- The replay uses the 20k landmark only; the verdict in F9 for another landmark or a larger cap is not tested.
- The outcome is a test-based resolve label from the benchmark harness; cost saved by stopping is measured in tokens, not money or time.
- ICC and the task-rate oracle use the same data as the within-task AUC, so near-perfect pooled AUC is partly a consequence of the clustering reported in the same tables.

## Discrepancies

- The abstract and §I say continuation wins at "216 of 224" configurations, and Table VI gives 49, 56, 56 and 55 dominated, which sum to 216; the 7 ties are at 30k and counted as ties that match continuation, so "higher solve rates at lower mean token cost" is not strictly true for those 7 (the paper says so in §IV.D.2).
- §V.c.1 sets the 14.06-point framework difference (uncapped, across frameworks) against "at most 1.98 percentage-point gain" of restarts (learned minus random, 75k cap). The two are different quantities, so the comparison is not like for like; under the 75k cap SWE-agent resolves 28.71% (§IV.D.2).
