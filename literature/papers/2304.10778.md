## Question

How good is the code that GitHub Copilot, Amazon CodeWhisperer and ChatGPT generate for function-level
problems, measured as validity, correctness, security, reliability and maintainability; what do
removing the docstring or renaming the function do to it; and how did the tools change over time (§1)?

## Findings

### F1 · practice · assistant-product-comparison · E3
- practice: give the same 164 HumanEval prompts (function signature plus docstring) to three products, Copilot and CodeWhisperer in an IDE, ChatGPT in its chat window, and run the benchmark's unit tests on the output (§3.2, §3.3).
- claim: "ChatGPT was the most successful and Amazon CodeWhisperer was the least successful tool" on correctness (§5.2).
- evidence: fully correct generations 65.2% ChatGPT, 46.3% Copilot, 31.1% CodeWhisperer; average code correctness 78.1%, 59.85%, 51.95% (§4.2, Figure 5). ChatGPT alone solved 36 problems, Copilot alone 15, CodeWhisperer alone 2 (§5.2, Figure 13). Partially correct 22.6%, 23.2%, 40.2%; incorrect 12.2%, 30.5%, 28.7% (Table 4).
- effect: helps
- reader: same problems for all three, so a comparison on equal tasks, but not a controlled one: one run per problem, nondeterministic tools (§6.2), three different interfaces and two generation methods for the IDE tools (§6.2), and no significance test. `helps` is the direction for ChatGPT against the other two. The 164 problems are public and may be in the training data; the paper does not discuss it.

### F2 · practice · assistant-product-comparison · E3
- practice: as F1; the measurement is code validity, that is, the generated script runs under Python 3.10.10 without an error (§3.3).
- claim: "All code generation tools are capable of generating valid code 9 out of 10 times with mostly similar types of issues" (§5.1).
- evidence: valid code 150 of 164 (91.5%) Copilot, 148 (90.2%) CodeWhisperer, 153 (93.3%) ChatGPT (§4.1). Causes in all three: incompatible types, syntax errors, functions of unimported libraries (§5.1).
- effect: none
- reader: the differences are 1 to 3 points on 164 problems, with no test. Validity here is "runs without an error on the given input", so wrong code that runs counts as valid; the authors note that type errors are less visible than syntax errors (§5.1).

### F3 · observation · static-analysis-of-generated-code · E2
- practice: SonarQube run on the generated code of the three tools for vulnerabilities, bugs and code smells; nothing assigned (§3.3, §4.3).
- claim: no difference in security; bugs are rare and specific to each tool; code smells are more common than bugs and appear in all three tools, "we could generalize the Code Maintainability results" (§5.3).
- evidence: security rating below 1 (best) in 0 problems for all tools (Table 2). Problems with one bug: 3 Copilot, 1 CodeWhisperer, 2 ChatGPT (Table 2); the bugs were different problems for each tool (§4.3). Problems with at least one smell: Copilot 14 + 3 + 2 = 19, CodeWhisperer 22 + 2 = 24 (Table 2). Average technical debt per problem with a smell 9.1, 5.6 and 8.9 minutes for Copilot, CodeWhisperer, ChatGPT; totals 172, 117 and 134 minutes (§4.3). Most common smells: naming, cognitive complexity (§5.3).
- effect: mixed
- reader: counts only; there is no human-written code or other control to compare with. Functions of a few lines give SonarQube little to find, which the authors say (§4.3, §6.1). Technical debt minutes are SonarQube's estimates, not measured effort. Some totals in §4.3 do not fit the Table 2 counts, see Discrepancies.

### F4 · practice · docstring-with-examples-in-prompt · E4
- practice: remove the docstring (task description and example calls) from each HumanEval prompt and give only the function name and parameters, then regenerate and score, on the same 164 problems (§3.4, §4.4).
- claim: "the lack of a proper explanation of the problems yields lower validity and correctness scores"; practitioners should provide "a comprehensive explanation of the problem, along with sample unit tests in the form of docstrings" (§5.4).
- evidence: Table 4, original against name only. Fully correct: Copilot 46.3% to 20.1%, CodeWhisperer 31.1% to 14.6%, ChatGPT 65.2% to 22.0%. Valid: 91.5% to 78.0%, 90.2% to 78.0%, 93.3% to 76.8%. Incorrect: 30.5% to 53.1%, 28.7% to 55.5%, 12.2% to 50.6%. Correctness did not fall for 45.1% (Copilot), 63.4% (CodeWhisperer) and 51.2% (ChatGPT) of the problems; those functions had self-explanatory names (§5.4).
- effect: helps
- reader: an ablation on equal tasks, so E4; one run per problem and tool, no test, and the tools are nondeterministic (§6.2). The ablation removes the description and the examples together, so it does not say which of the two matters. The effect is large (13 to 43 points of correctness) and the same in all three tools.

### F5 · practice · meaningful-function-names · E4
- practice: replace each function name in the prompt with `foo`, keep the docstring, regenerate and score, on the same 164 problems (§3.5, §4.5).
- claim: "Selecting a meaningful name for a function can significantly improve the performance of code generation tools"; but "providing thorough explanations for functions is even more critical" (§5.5).
- evidence: Table 4, original against `foo`. Fully correct: Copilot 46.3% to 42.1%, CodeWhisperer 31.1% to 27.4%, ChatGPT 65.2% to 61.6%. Valid: 91.5% to 93.9%, 90.2% to 89.6%, 93.3% to 92.7%. Two single problems: ChatGPT on #1 went from 100% to 0% correctness (§5.5); CodeWhisperer on #79 went from 100% to an invalid solution (§5.5, Listing 11).
- effect: helps
- reader: E4 by design. The drops are 3.6 to 4.2 points, about 6 or 7 problems of 164 (reader's arithmetic), with one run per cell and no test, so the size is small next to the nondeterminism the authors report in §6.2. The docstring still names the task in `foo` prompts, so this tests a name alone. The step from "names help a little" to "explanations help more" compares two different ablations, name only against docstring and examples.

### F6 · observation · tool-version-update-on-fixed-benchmark · E3
- practice: the same 164 problems run on an older and a newer version of Copilot and of CodeWhisperer; nothing assigned (§3.6, §4.6).
- claim: "both GitHub Copilot and Amazon CodeWhisperer increased the number of correct code suggestions on their new versions" (§5.6); "both Amazon CodeWhisperer and GitHub Copilot are improving rapidly" (§8).
- evidence: fully correct, old to new: Copilot v1.7.4421 to v1.70.8099 28.7% to 46.3%, CodeWhisperer Nov 2022 to Jan 2023 24.4% to 31.1% (§4.6). Average correctness 53.6% to 59.9% and 36.5% to 52% (§5.6). The abstract gives "18%" and "7%" and §5.6 "62%" and "28%" for the same two changes. Copilot's incorrect share rose from 20.1% to 30.5% and its partially correct share fell from 51.2% to 23.2%; CodeWhisperer's validity fell from 95.1% to 90.2% (§4.6).
- effect: helps
- reader: the old Copilot numbers come from the authors' earlier study (§3.6), not from a rerun in this setup, and the intervals differ, 13 months for Copilot and 2 months for CodeWhisperer (§6.2). No test. Amazon does not publish CodeWhisperer versions, so dates stand in for versions. The direction is for fully correct code; validity and the incorrect share moved the other way for one tool each.

### F7 · observation · version-update-regressions-on-individual-tasks · E3
- practice: the problem-by-problem comparison of the old and the new version of each tool; nothing assigned (§5.6).
- claim: the newer versions lose solutions the older ones had: the newer CodeWhisperer "provided partial or incorrect answers for 16 of the 40 problems" that were fully correct before (§5.6).
- evidence: CodeWhisperer: 16 of 40 earlier fully correct problems no longer fully correct; lower correctness for 20 of the 50 earlier partially correct ones (§5.6). Copilot: correctness raised for 65% of the earlier partially correct and for 9 of 33 earlier incorrect problems; the new version often returned only `pass`, and some problems failed on a missing import (§5.6). Both observed against the net gains in F6.
- effect: hurts
- reader: counts from one run of each version, so some of the churn may be run-to-run variation of a nondeterministic tool, which the authors name for Copilot ("the undetermined nature", §5.6). The paper gives no repeat runs to separate the two.
### F8 · observation · prompt-complexity-and-correctness · E1
- practice: the longer and more complicated prompts of HumanEval problems, compared by hand with simpler ones; nothing assigned (§5.2).
- claim: "the generated solutions for longer and more complex prompts for the functions yielded lower Code Correctness scores" (§5.2).
- evidence: one pair with Copilot, the function `common` (simple prompt, correct solution) against `minPath` (long prompt, "failed to generate any algorithm"), Listing 9 (§5.2). No count or statistic for the rest of the 164 problems.
- effect: hurts
- reader: a single example stands for a claim about all tools; prompt length is confounded with problem difficulty, which the benchmark does not separate. The authors write that the tendency "can also be generalized to all of the code generation tools" with no data shown.

### F9 · practice · minor-edit-of-partially-correct-generation · E1
- practice: take a partially correct generation and change a loop bound or a return expression by hand (§5.2).
- claim: "even with minor additional input from the programmer, the code correctness scores can be improved" (§5.2).
- evidence: ChatGPT on #10 scored 20% and, after changing the bounds and the increment of one `for` loop, 100% (Listing 7); CodeWhisperer on #54 scored 57% and the marked one-line `return` change is the correct solution (Listing 8). Partially correct generations were 23.2% (Copilot), 40.2% (CodeWhisperer) and 22.6% (ChatGPT) of the problems (Table 4).
- effect: helps
- reader: two cases the authors chose to show, with the reference tests at hand, so the fix is known in advance. The paper does not measure how long a person needs to find that edit, nor how often a partial solution is one edit from correct. The usefulness of partial solutions is an assumption in §4.2.

## Limits stated by the authors

- Trivial solutions (empty list, a boolean) pass tests by chance; 7.7 tests per problem on average may miss corner cases (§6.1).
- HumanEval functions are short, so SonarQube found little to report on security, bugs and smells (§6.1).
- One-shot generation with no hints; the tools are nondeterministic and keep changing, so the results may not replicate (§6.2).
- Two generation methods for Copilot and CodeWhisperer (automatic suggestion or a key combination), and block against line-by-line generation, chosen by the tool and not by the authors (§6.2).
- The two version comparisons cover different intervals, 13 months and 2 months (§6.2). CodeWhisperer's version is not recorded (§3.6).
- ChatGPT got an instruction "Generate code using the prompts I will provide" and the prompts one after another in the same chat window (§6.2).
- Only validity, correctness, security, reliability and maintainability were measured; readability, cyclomatic complexity and reusability were not (§6.3).
- One benchmark, Python only, one IDE (§6.4).

## Reader's notes

- Single runs per prompt and tool, with no repeats and no significance test anywhere; the paper reports percentages of 164 problems, where one problem is 0.6 points. Differences of a few points (F2, F5, the Copilot against CodeWhisperer gap in some cells) are within one to six problems.
- ChatGPT prompts were entered one after another in one chat window (§6.2), so earlier problems and answers were in its context for later ones; the IDE tools saw the open file. The three tools did not get the same context.
- HumanEval is a public benchmark whose canonical solutions are online; contamination is not discussed in the parts read. The tools are 2022 and 2023 versions, so the absolute numbers say little about today's agents.
- The study is about completion and chat tools on single functions, not agents with tools, files or a loop. Its direct use for agentic coding is the prompt-detail ablation (F4, F5) and the version drift (F6, F7).
- The generation is by hand and by the authors, so the person who writes the prompt and picks among suggestions ("the top of the list", §6.2) is a variable the paper does not control.

## Discrepancies

- The abstract says Copilot and CodeWhisperer improved by "18%" and "7%"; §5.6 and the box after it say 62% and 28% passed unit tests. The first pair are percentage points of 46.3 against 28.7 and 31.1 against 24.4 (17.6 and 6.7, reader's arithmetic); the second pair are relative changes. The abstract does not say which.
- §4.3 gives ChatGPT "13 problems containing a single, and 1 problem containing two code smells" (14 problems), while Table 2 has 13, 1 and 1 for one, two and three smells (15 problems). A total of 134 minutes with 8.9 minutes each fits 15 problems (reader's arithmetic).
- §4.3 gives CodeWhisperer 24 problems with a smell, 5.6 minutes on average and 117 minutes in total; 24 times 5.6 is about 134 (reader's arithmetic), and 117 divided by 24 is 4.9. The totals 117 and 134 may be swapped between CodeWhisperer and ChatGPT.
- §5.3 lists "the three most common issues" and names two: improper naming and high cognitive complexity.
- §5.6 gives Copilot average correctness 59.9% against 59.85% in §4.2 and CodeWhisperer 52% against 51.95%; rounding only.
- §5.6 says CodeWhisperer's "earlier version offered entirely correct suggestions" while the new one gave "partial or incorrect answers for 16 of the 40 problems"; it means the 40 problems that were fully correct before (24.4% of 164, reader's arithmetic), not all earlier answers.
