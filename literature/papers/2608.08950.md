## Question

Can a post-generation check that rebuilds the problem a patch solves, without seeing the original
issue, and compares it with the issue, give a coding agent a verification signal that raises the
share of issues resolved (Abstract, Introduction)?

## Findings

### F1 · practice · reconstruct-problem-from-patch-and-reconcile · E4
- practice: after the agent submits a candidate patch, run three further model stages on the same backbone: reconstruct the repair rationale from issue and trajectory (patch hidden), reconstruct the problem the patch addresses from patch and trajectory (issue hidden), compare it with the issue and the rationale, and append a verification note with a revision plan to the agent's context until the check passes or a revision budget ends (Method; Experimental Settings). Compared with the same agent without it. The revision budget is not stated.
- claim: Pass@1 rises on both backbones, "without test execution or ground-truth patches" (Abstract, Introduction).
- evidence: SWE-bench Verified, 500 issues, mini-SWE-agent. GPT-5 mini 281/500 (56.2%) to 316/500 (63.2%), +7.0 points. MiniMax M2.5 379/500 (75.8%) to 397/500 (79.4%), +3.6 points (Table 1).
- effect: helps
- reader: an A/B on equal tasks against the same agent, so E4. One greedy run per configuration, no confidence interval or test; the gain is 35 and 18 issues (reader's arithmetic). The authors built and evaluated their own system, and the paper gives no code link or prompts in the parts read.

### F2 · practice · self-review-prompts · E4
- practice: Self-Refine as baseline: the same model reviews the candidate patch against the original issue and returns revision feedback, up to three iterations, "with a comparable inference budget" (Baselines). Compared with the same mini-SWE-agent without it.
- claim: "iterative review alone is insufficient"; Self-Refine "does not improve either baseline" (Experiment and Results).
- evidence: SWE-bench Verified, 500 issues, mini-SWE-agent. GPT-5 mini 281/500 to 274/500 (56.2% to 54.8%, -1.4 points). MiniMax M2.5 379/500 to 370/500 (75.8% to 74.0%, -1.8 points) (Table 1).
- effect: hurts
- reader: equal-task comparison, E4. The losses are 7 and 9 issues on one greedy run each, within what run-to-run noise could produce; "none" would be as defensible. The Self-Refine prompts and implementation are the authors' own and are not shown, and Self-Refine's token cost is not reported, so "comparable budget" cannot be checked.

### F3 · practice · reconstruct-problem-from-patch-and-reconcile · E4
- practice: as F1, added to OpenHands (CodeAct scaffold) around its existing edit loop without changing its tools (Experimental Settings). Compared with plain OpenHands on a random 120-issue subset.
- claim: the gain "is not tied to a specific agent framework"; RETRACE outperforms OpenHands and Self-Refine on both models (Generalizability to other scaffolds).
- evidence: 120-issue subset, OpenHands. GPT-5 mini 45/120 (37.5%) to 68/120 (56.7%), +19.2 points. MiniMax M2.5 75/120 (62.5%) to 84/120 (70.0%), +7.5 points. Self-Refine on the same scaffold: 64/120 (53.3%) and 77/120 (64.2%) (Table 3).
- effect: helps
- reader: E4, the same A/B on a second scaffold; it removes a scaffold-specific explanation. The subset is 120 issues with one run each, so +7.5 points on MiniMax is 9 issues. The GPT-5 mini OpenHands baseline (37.5%) is far below the same model in mini-SWE-agent (50.0% on the same subset, Table 2), which leaves much room to gain. The Table 3 caption's line "mini-SWE-agent results use GPT-5-mini" belongs to no row of that table.

### F4 · practice · self-review-prompts · E4
- practice: Self-Refine as in F2, added to OpenHands (Table 3).
- claim: "OpenHands benefits from additional post-edit reasoning in general", unlike mini-SWE-agent (Generalizability to other scaffolds).
- evidence: 120-issue subset, OpenHands. GPT-5 mini 45/120 (37.5%) to 64/120 (53.3%), +15.8 points. MiniMax M2.5 75/120 (62.5%) to 77/120 (64.2%), +1.7 points (Table 3).
- effect: helps
- reader: E4 on equal tasks, one run each. Together with F2 the same practice hurts on one scaffold and helps on the other, so the sign depends on the scaffold or its baseline strength; the paper offers an explanation and no test of it. +1.7 points is 2 issues.

### F5 · practice · forward-rationale-reconstruction-from-trajectory · E4
- practice: run only the forward stage: rebuild evidence, reasoning chain and intended repair from issue and trajectory with the patch hidden, and feed the result back before the patch is final (Ablation Studies, "Forward only"). Compared with the baseline agent.
- claim: "each stage contributes"; "forward reasoning corrects flawed editing decisions by reorganizing context before the patch is produced" (Ablation Studies).
- evidence: random 120-issue subset, GPT-5-mini, mini-SWE-agent. Baseline 60/120 (50.0%), forward-only 68/120 (56.7%) (Table 2). Forward-only resolves 6 issues that backward-only misses (Figure 2 text).
- effect: helps
- reader: E4 on equal tasks, but one backbone, one scaffold, 120 issues, one run: 8 more issues. The text does not say whether the single-stage variants include reconciliation or the revision loop, so what "forward only" isolates is unclear.

### F6 · practice · backward-problem-reconstruction-from-patch · E4
- practice: run only the backward stage: infer from the patch and trajectory, with the issue withheld, a description of the problem the patch addresses, and compare it with the issue (Ablation Studies, "Backward only"). Compared with the baseline agent.
- claim: "backward specification inference catches patches whose effect diverges from the reported problem after the fact" (Ablation Studies).
- evidence: random 120-issue subset, GPT-5-mini, mini-SWE-agent. Baseline 60/120 (50.0%), backward-only 68/120 (56.7%) (Table 2). Backward-only resolves 6 issues that forward-only misses (Figure 2 text).
- effect: helps
- reader: E4 on equal tasks with the same limits as F5: one backbone, 120 issues, one run. The two single-stage variants have the same total, 68, so Table 2 gives no ranking between them.

### F7 · practice · forward-backward-reconciliation · E4
- practice: combine the forward and backward stages and let a reconciliation step attribute the mismatch to reasoning, implementation or both and write the revision plan (Ablation Studies, "RETRACE (full)"). Compared with each single-stage variant.
- claim: reconciliation "consolidates the gains of both paths" and "exposes errors that neither direction detects in isolation" (Ablation Studies).
- evidence: random 120-issue subset, GPT-5-mini, mini-SWE-agent. Full 73/120 (60.8%) against 68/120 (56.7%) for either single-stage variant and 60/120 (50.0%) for the baseline (Table 2). Full retains 66 issues resolved by each single-stage variant and resolves 7 that neither resolves alone (Figure 2 text).
- effect: helps
- reader: E4 as an ablation, but it removes a stage pair, not reconciliation alone, so the abstract's "adding reconciliation yields further gains" is not isolated. 5 more issues than a single-stage variant (reader's arithmetic) on one run of 120 issues. By the paper's own counts the two variants share 62 resolved issues (68 minus 6, reader's arithmetic), so "retains 66 issues resolved by each" does not describe their overlap.

### F8 · practice · reconstruct-problem-from-patch-and-reconcile · E4
- practice: as F1, measured on tokens and cost per issue against the same agent without it (Cost analysis).
- claim: "per-issue cost remains comparable to or below the baseline"; "bidirectional validation does not impose a practical cost overhead" (Cost analysis).
- evidence: SWE-bench Verified, average per issue (Table 4). GPT-5 mini input 26.3K tokens to 60.6K, cache hit 45.6% to 90.8%, cost $0.07 to $0.06. MiniMax M2.5 input 123.3K to 78.0K, cache hit 94.6% to 96.7%, cost $0.07 to $0.05. Output tokens with GPT-5-mini 4.2K to 1.2K (text).
- effect: helps
- reader: the comparison is on equal tasks, so E4, but costs are rounded to the cent, there is no variance, and whether the cost includes the RETRACE stages' own calls is not stated. The low cost rests on provider prompt-cache pricing; the input tokens with GPT-5 mini more than double. The explanation that targeted feedback cuts exploration is not tested. The text's "cost ratio below 1.0x" is not in the table.

### F9 · practice · issue-withheld-from-verifier · E0
- practice: hide the original issue from the backward stage so the patch's problem is rebuilt from the patch and the trajectory alone (Method; Conclusion).
- claim: withholding the issue gives "an independent verification signal that self-review methods lack" (Related Work); "ensure independence" (Conclusion).
- evidence: no experiment varies whether the issue is withheld. The only related comparison is Self-Refine against the issue, which differs in more than that one choice (Table 1).
- effect: helps
- reader: E0 for the mechanism; the effect is a claim from design. F6 and F2 together are suggestive at most, because Self-Refine differs from backward-only in its prompts, its output and its lack of a reconstruction step.

## Limits stated by the authors

- SWE-bench Verified is human-validated and mostly Python, which "may restrict generalization to other languages or domains" (Limitations).
- The backward check compares against the issue, so vague or underspecified reports weaken the verdict (Limitations).
- Forward and backward stages use the same backbone as the agent that wrote the patch; a different verifier model is left as an extension (Limitations).

## Reader's notes

- One greedy run per configuration and no significance test: the gains on the 500 issues (35 and 18) are single paired runs, and every 120-issue result differs by a handful of issues.
- The ablation and scaffold results use a "random" 120-issue subset whose draw is not described; the baseline there (50.0%, 60/120) is below the full-set baseline (56.2%).
- Table 1 scores the full set with mini-SWE-agent only. OpenHands and the ablations use the subset, so the scaffold comparison is on less data.
- The verifier is the same model as the agent. Failures the model cannot see in its own reasoning may be missed, which the paper lists as future work.
- Patches are scored by SWE-bench tests, which the authors elsewhere call insufficient ("plausible but incorrect", Introduction); the paper does not measure patches that pass the tests and are wrong.
- The revision budget and the number of revision rounds actually used are not reported, so the extra computation per issue is only visible through Table 4.
- All findings are from authors evaluating their own system.

## Discrepancies

- The text gives cache hit rates of 90.88% and 96.73% (Cost analysis); Table 4 prints 90.8% and 96.7%.
- The Table 3 caption says "mini-SWE-agent results use GPT-5-mini", but Table 3 lists OpenHands rows only.
- The abstract says "adding reconciliation yields further gains", while Table 2 has no configuration that removes reconciliation and keeps both stages.
- The text says full RETRACE "retains 66 issues resolved by each single-stage variant" while each variant's 68 resolved issues contain 6 not resolved by the other, so the shared set is 62 (reader's arithmetic).
- The Table 4 MiniMax baseline row is labelled "Baseline" and its cost prints without a dollar sign; the GPT-5 mini row is labelled "mini-SWE-agent".
