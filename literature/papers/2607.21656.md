## Question

When one coding agent writes a draft and a second agent reviews it once without running code, does
the pass raise the pass rate, does it matter which model writes and which reviews, and is the gain
worth the cost and latency (§1, RQ1 to RQ4)?

## Findings

### F1 · practice · self-review-prompts · E4
- practice: Codex GPT-5.5 reviews its own draft once, statically, and must emit a final program (condition OO); compared with the same drafts submitted unreviewed (condition O) on the same 116 tasks (§3.2, Table 1).
- claim: same-model review of Codex drafts "is broadly positive"; it raises the pass rate to 84.5% (§4.1, §4.3, abstract).
- evidence: pass 98 of 116 (.845) against 83 (.716), +12.9 pp (Table 2, Table 3). 21 fixes and 6 regressions (§4.3). McNemar 21 against 6, p = .0059, p_BH = .0222 (Table 4). Cost $.312 against $.190 per task, latency 67.9s against 38.5s (Table 2).
- effect: helps
- reader: a paired ablation on equal tasks, so E4. One run per task and condition, 116 tasks, one model pair. The reviewer prompt asks for a final program with no separate decision to intervene (§5.5).

### F2 · practice · self-review-prompts · E4
- practice: Claude Opus 4.7 reviews its own draft once, statically (condition AA); compared with the same drafts unreviewed (condition A) (§3.2).
- claim: "same-model review is ineffective" for Claude drafts; AA "is at the noise floor" (§4.2, §4.3).
- evidence: pass 106 of 116 (.914) in both A and AA, +.000 (Table 2). 3 fixes and 3 regressions, McNemar p = 1.0000 (§4.3, Table 4). Cost $.389 against $.226, latency 135.8s against 86.2s (Table 2).
- effect: none
- reader: same design as F1, so E4. The writer already passes 91.4%, so there are 10 failing tasks to fix; a ceiling limits what any reviewer can show. The authors' explanation, that Claude verifies more in its first pass, is a hypothesis (§5.1); latency is their only support.

### F3 · practice · cross-model-review-of-draft · E4
- practice: Claude Opus 4.7 statically reviews Codex GPT-5.5 drafts (condition OA); compared with the same Codex drafts unreviewed (O) (§3.2).
- claim: the gain is large; "OA fixes 26 of Codex GPT-5.5's failures while regressing only 5 of its successes (net +21)" (§4.3).
- evidence: pass 104 of 116 (.897) against 83 (.716), +18.1 pp (Table 2, Table 3). McNemar 26 against 5, p = .0002, p_BH = .0010 (Table 4). Regression rate .043 (Table 2). Cost $.443 against $.190, latency 112.4s against 38.5s (Table 2). About $1.40 per net fix (§5.4).
- effect: helps
- reader: E4 by the paired design. The reviewer is also the stronger writer here; the authors say the design "cannot fully separate the effect of review direction from the effect of that baseline gap" (§5.2). OA is within two passing tasks of Claude solo (§4.1).

### F4 · practice · cross-model-review-of-draft · E4
- practice: Codex GPT-5.5 statically reviews Claude Opus 4.7 drafts (condition AO); compared with the same Claude drafts unreviewed (A) (§3.2).
- claim: "Codex GPT-5.5 reviewing Claude Opus 4.7 drafts makes the pipeline worse" (§1).
- evidence: pass 96 of 116 (.828) against 106 (.914), −8.6 pp (Table 2). 3 fixes and 13 regressions, net −10 (§4.3). McNemar 3 against 13, p = .0213, p_BH = .0456 (Table 4). Regression rate .112, the highest of the four reviewed conditions (Table 2). AA against AO: 12 against 2, p_BH = .0323 (Table 4). Cost $.382 against $.226, latency 118.0s against 86.2s (Table 2).
- effect: hurts
- reader: E4 by the paired design. The significance is thin: p_BH = .0456 among all pairwise contrasts, 16 discordant tasks in total. The weaker model is the reviewer here, so the result mixes model identity with relative strength (§5.2).

### F5 · practice · cross-model-review-of-draft · E4
- practice: compare the two cross-model orderings directly, Claude writes and Codex reviews (AO) against Codex writes and Claude reviews (OA), on the same 116 tasks (§3.4, §4.2).
- claim: the two orderings are not shown to be statistically separable as standalone conditions: "we do not claim" it (§4.2).
- evidence: AO only 5 tasks, OA only 13 tasks, p = .0963, p_BH = .1444 (Table 4).
- effect: none
- reader: this contrast is a comparison of two pipelines, each with a different writer, so it is not an ablation of review alone; graded E4 only because the tasks are paired. The abstract and §5.2 headings ("helps whereas hurts") rest on the per-writer contrasts F3 and F4, not on this one.

### F6 · practice · single-review-pass-after-draft · E3
- practice: add a second model call as reviewer and measure cost and latency per task against the solo baseline (§4.4, Table 2).
- claim: the pass "doubles the API call count and adds tens of seconds of wall-clock latency"; it pays off only for the Codex writer, and Claude solo "sits on the Pareto frontier" (§4.4).
- evidence: OO +12.9 pp for +$0.12 and 29 s; OA +18.1 pp for +$0.25 and 74 s; A to AA +$0.16 and 50 s for no gain; A to AO +$0.16 and 32 s for −8.6 pp (§4.4). AA adds 72% cost and 58% latency (§4.4). About $0.95 per net fix for OO and $1.40 for OA (§5.4, authors' arithmetic). Reproducing all six conditions costs about $225, $1.94 per task (§5.5).
- effect: mixed
- reader: costs are computed from token counts and a pricing configuration "pulled from the official websites" (§3.3), so they are list-price estimates, and the authors call them point-in-time. No test is run on cost or latency. Gains came only for the writer with the lower baseline, so the cost-benefit conclusion is limited to this pair.

### F7 · observation · reviewer-rewrite-regressions · E1
- practice: the authors read fixes and regressions by hand in the artifact records, 6 cases in Table 5 (§4.3, §5.3).
- claim: "Helpful review edits whereas harmful review rewrites": Codex as reviewer, when uncertain, discards the writer's data structure and starts over; Claude as reviewer keeps the interface and repairs one local invariant (§5.3).
- evidence: Table 5 cases: Problem 3717 (AO, heap rewrite of a passing sorted-list median window fails), abc389_f (OO, deletes a segment-tree range guard), arc191_a (AA, changes optional digit accounting); fixes in 3562, abc394_f, 3688. "We did not measure rewrite frequency directly" (§5.3).
- effect: hurts
- reader: a handful of hand-picked cases whose labels the authors call "interpretive and might not be reproducible" (§4.3). It supports a hypothesis about how regressions happen and nothing about how often.

## Limits stated by the authors

- 116 paired tasks: "sufficient for a first diagnostic but not for settling stable rankings"; one model pair, so generalisation to Gemini, DeepSeek, Qwen or Grok is untested (§5.5).
- Self-contained Python competitive-programming problems; no repository-scale bug fixing, build systems or multi-file review (§5.5).
- The reviewer cannot execute tests, which "likely understates what a tool-using agent with a sandbox could achieve" (§5.5).
- Prompts are handwritten and may favour a model; results are sensitive to prompt wording; the reviewer always emits a final program, with no "intervene?" decision (§5.5).
- Only "high" reasoning effort tested; newer model versions may differ (§5.5).
- The design cannot fully separate review direction from the baseline gap between the two models (§5.2).
- Review is scored only by final-program correctness, not by design, readability or security feedback (§5.5).
- Cost figures are point-in-time estimates (§5.5).

## Reader's notes

- Each condition has one run per task. The writer drafts for AO and OA are the same artifacts as in the solo baselines (§3.2), which makes the paired tests sound but gives no estimate of run-to-run variation of the writer.
- Complete-case selection keeps only the 116 tasks where all six conditions produced a valid artifact (§3.4). The number of dropped tasks is not stated in the parts read.
- The pass rate is the hidden-test result of the final program. Because the reviewer rewrites the whole program, a regression can come from a rewrite that has nothing to do with the writer's defect; the paper does not separate those.
- The "hard" and "medium" slices were run separately and pooled; no per-difficulty result is given (§3.4).
- The paper's practical advice ("skip review for Claude drafts") rests on one pair at one reasoning setting; the review prompt itself was not varied.
- No author is affiliated with either vendor; the evaluation is not of the authors' own system.

## Discrepancies

- §5.4 calls OA's regression rate (4.3%) the "lowest reviewed regression rate"; Table 2 gives AA .026, lower than OA .043 (and OO .052). AA's pass rate does not move, so the sentence holds only among reviewed conditions that gained.
