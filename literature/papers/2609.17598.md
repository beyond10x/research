## Question

Do pull requests that autonomous coding agents open in public repositories (more than 100 stars) differ from matched human PRs in the same repositories on security smells, maintainability, post-merge churn, reverts and human review (RQ1 to RQ5, §1, p. 2)?

## Findings

### F1 · observation · autonomous-agent-pr · E3
- practice: an autonomous agent (one of five products) opens a PR under its own name for a task in a repository with more than 100 stars; the PR is merged; the paper counts revert-style commits, identified by commit message, in the 90 days after merge (§3.1 to §3.2, pp. 2-3).
- claim: reverts split by vendor. Codex PRs were reverted about half as often as human PRs, Devin PRs about 1.3 times as often. "Vendor identity is the variable that matters" (abstract; §5, p. 7).
- evidence: Table 2, p. 5. Human 11.5%. Codex 6.1%, n 17,756, OR 0.50 [0.44, 0.57], p < .001. Devin 14.5%, n 2,185, OR 1.31 [1.11, 1.54], p = .004. Copilot 12.5%, n 2,094, OR 1.10 [0.93, 1.31], p = .457. Cursor 11.4%, n 946, OR 1.00 [0.79, 1.25], p = 1.00. Claude Code 10.5%, n 267, OR 0.90 [0.60, 1.36], p = .878. Figure 3, p. 6, shows the same values.
- effect: mixed
- reader: E3, because the comparison is against a matched human group with no randomisation and no ablation. The main confound is task mix: agents are not randomly assigned (§6, p. 8), and the paper never fits vendor together with size or task. The ORs agree with the stated rates to rounding (reader's arithmetic). The n column of Table 2 is not defined (see Reader's notes).

### F2 · observation · autonomous-agent-pr · E3
- practice: as F1. The measurement is a regex catalogue over the added lines of the Python, JavaScript and TypeScript diffs, mapped to eight CWE classes (§3.3, pp. 3-4). Hits are smells, not confirmed vulnerabilities (§3.3, p. 4).
- claim: pooled across vendors, agent PRs were less likely than human PRs to contain any security smell (OR 0.63), driven by hardcoded credentials (CWE-798) and eval/exec (CWE-95). Per-line density is similar across authorship (§4.1, §4.4; abstract).
- evidence: presence 2.9% vs 4.6%, χ²(1) = 8.59, p = .003, OR 0.63 [0.47, 0.85] (§4.1, p. 4). CWE-798 0.9% vs 2.2%, OR 0.39 [0.25, 0.62], p < .001. CWE-95 0.2% vs 0.8%, OR 0.25 [0.11, 0.56], p = .006 (§4.4, p. 6). Density: H(5) = 52.5, ε² = .005; Codex δ -.02, Copilot -.02, Cursor -.03, Devin p = .60, Claude Code +.05 (§4.1, p. 4). Per product, CWE-798 is 3.3% for Claude Code and 0.5% each for Codex and Cursor (§4.4, p. 6).
- effect: helps
- reader: E3, between groups with no control. The pooled rate is mostly Codex: 4,570 of the 7,708 analysed agent PRs (reader's arithmetic from Table 1). The per-product credential rates rest on small counts, about 8 Claude Code PRs and about 23 Codex PRs (reader's arithmetic); the paper gives no test or interval per product. The size check (p. 5) covers density only.

### F3 · observation · autonomous-agent-pr · E3
- practice: as F1. Churn is the number of follow-up commits on the PR's most-changed file within 90 days of merge, reported raw and divided by changed lines (§3.2, p. 3; Eq. 2, §3.3, p. 4).
- claim: "none of the five imposes a higher per-line maintenance burden" than human contributors (§7, p. 8; similar wording in §4.3, pp. 5-6). Claude Code has the lowest churn per changed line of any group.
- evidence: 26,283 merged PRs with a full 90-day window (§4.3, p. 5). Raw follow-up: Copilot δ -.20 vs human (small, p < .001); Cursor and Claude Code below human, both negligible; Codex δ +.03 (p = .020). Per changed line: Claude Code δ -.33 (medium, p < .001), median ci 0.5 vs 5.3 for humans; Copilot δ -.16 (small); Cursor δ -.08; Codex and Devin at human level (§4.3, p. 5).
- effect: none
- reader: E3, between groups with no control. The per-line ratio divides by changed lines, so large PRs get small ratios by construction. Claude Code has the largest median PR (495 changed lines, Table 1, p. 3), and its raw follow-up is only negligibly below human. The per-line ranking may be largely a size effect. The paper's size note (§5, p. 7) does not mention this ratio.

### F4 · observation · autonomous-agent-pr · E3
- practice: as F1. Maintainability and structure counts on added lines: TODO/FIXME-style markers, lines over 120 characters, comment lines, branching keywords, maximum indentation depth (§3.3, pp. 3-4).
- claim: agent code is not one population. No agent dominates the four structural dimensions, and the groups differ on each (§4.2, p. 5).
- evidence: Kruskal-Wallis, all p < .001. Nesting depth H(5) = 118.3, ε² = .013. Branch density H(5) = 104.0, ε² = .011. Comment ratio H(5) = 868.5, ε² = .097. Maintainability density H(5) = 467.7, ε² = .052 (§4.2, p. 5). Comment-ratio medians: Copilot .065, Claude Code .076, Cursor .042; Codex, Devin and human zero (§4.2, p. 5). Claude Code median nesting 4 vs 3 elsewhere (§4.2, p. 5). Maintainability density: Codex δ -.19 (small), Devin δ -.07 (§4.1, p. 5). Dunn: 44 of 60 pairwise tests p < .05 (§4.2, p. 5).
- effect: mixed
- reader: E3, between groups with no control. The omnibus effect sizes are small (ε² .011 to .097); the p-values reflect the sample size. "Not one population" rests on the spread across groups, not on a test of heterogeneity. Claude Code's structure co-occurs with its size (§5, p. 7).

### F5 · observation · human-review-of-agent-pr · E3
- practice: maintainers review an agent-opened PR. The paper counts human reviews, change requests, issue comments and bot reviews, and measures hours from PR creation to the first human review (§3.4, p. 4).
- claim: review effort is uneven across agents. Copilot PRs draw the most human reviews and change requests; Claude Code PRs wait longest for a first human review, median 12.6 hours (abstract; §4.5, pp. 6-7).
- evidence: review data cover 5.4% (Codex) to 51.2% (Copilot) of each group's PRs (§4.5, p. 6). Per PR, Copilot has 3.6 human reviews, 0.43 change requests and 4.0 bot reviews (§4.5, p. 7). Claude Code median 12.6 hours vs 1-4 hours elsewhere (§4.5, p. 7). Kruskal-Wallis, agents only: hours to first human review H(4) = 88.9, ε² = .014; human reviews per PR H(4) = 700.6, ε² = .116; change requests H(4) = 293.0, ε² = .048; issue comments H(4) = 243.0, ε² = .049; bot reviews H(4) = 541.0, ε² = .119 (§4.5, pp. 6-7).
- effect: mixed
- reader: E3, between agents only, because the review tables hold no human PRs (§3.4, p. 4). The text gives numbers for Copilot only; "most" for the other groups is read from Figure 5 (p. 7). The covered share differs by group and the paper does not say which PRs are covered, so coverage may drive part of the spread. Claude Code's latency sits with its size (§5, p. 7). Review counts do not show whether the reviews were scrutiny or rework.

### F6 · observation · review-capacity-bottleneck · E0
- practice: none. This is an observation about the review loop as agent volume grows, not a practice that was done. The slug is used because no other slot fits.
- claim: "Review capacity is becoming the bottleneck." As agent volume grows, human attention is the scarce resource, and research should study routing and prioritising agent PRs (§5, p. 7).
- evidence: none over time. The text gives Copilot's 3.6 human reviews per PR and states that bot reviews outnumber human ones for some agents; the numbers in the text are for Copilot only (4.0 bot vs 3.6 human, p. 7).
- effect: hurts
- reader: E0. The claim is about a trend. The data are one cross-sectional window, and the paper measures neither reviewer capacity nor the growth of agent volume.

## Limits stated by the authors

- Regex detection flags patterns, not confirmed vulnerabilities; counts are an upper bound on pattern presence (§6, p. 7).
- An early path-traversal pattern inflated that class about 150-fold and was tightened (§6, p. 7).
- Churn on the most-changed file is a proxy for whole-PR churn; revert detection by commit message misses silent rewrites (§6, p. 8).
- Agents are not randomly assigned; self-selection mixes code quality with task mix (§6, p. 8).
- Public repositories with more than 100 stars, three languages, December 2024 to July 2025; Codex is 58% of agent PRs and Claude Code 459 PRs (§6, p. 8).
- Conclusions may not transfer to private codebases, other languages or later agent versions (§6, p. 8).
- Static coverage is 23.7% of PRs; review coverage is 5-51% by group (§6, p. 8).
- The 90-day window is a limit; longer windows are listed as future work (§7, p. 8).

## Reader's notes

- controlled: false. The human group is a matched comparison group, which the grade table places at E3. The field definition says "control or baseline"; read literally, that would make it true here. See misfit M1 in the report.
- independent: true. No tie between the authors and any vendor is stated. The text has no funding or competing-interests statement. Vendors appear only as study subjects.
- Vendor and size are entangled. Claude Code has the largest PRs (median 495 changed lines, Table 1, p. 3), the highest smell presence (9.5%, Figure 2, p. 5), the deepest structure (F4) and the slowest first review (F5). §5 (p. 7) calls vendor identity "the variable that matters", but no model includes vendor and size together. The one size check (p. 5) covers pooled security density only; its bucket limits are not stated, and its XL result (δ -.08) is negligible by the paper's own bands (§3.5, p. 4).
- "far wider than any pooled agent-human gap" (§5, p. 7) has no computation behind it. The paper reports no pooled revert rate or OR; Table 2 has vendor rows only.
- Reverts are called "the costliest failure mode" (§4.3, p. 5). The §5 sentence that agent PRs "need no more per-line follow-up work" (p. 7) does not mention the Devin revert OR of 1.31 in that sentence; §7 (p. 8) does report it.
- The per-line churn ranking (F3) is a ratio, and the paper's size note does not cover it.
- The analysed share of each group's PRs differs (reader's arithmetic from Table 1): Codex 21.0% (4,570 of 21,799), Devin 25.4% (1,224 of 4,827), Copilot 22.2% (1,102 of 4,970), Cursor 37.0% (571 of 1,541), Claude Code 52.5% (241 of 459), human 30.4% (1,225 of 4,027). The static comparisons are therefore on different language subsets of each group's PRs. The paper does not discuss this.
- Review coverage (5.4% to 51.2%, p. 6): the covered subset is not described and the denominators of the percentages are not given.
- The planted-defect validation of the catalogue (§6, p. 7) is mentioned but no result is reported. The catalogue's precision and recall are unknown.
- The human baseline is capped per repository, but the cap is not stated (§3.1, p. 3). The matched sample is 4,027 human PRs against 9,750 agent PRs in the same 810 repositories (p. 3).
- Omnibus ε² values run from .005 to .116. The text leans on p-values, and p < .001 is common at this sample size. The paper gives no bands for ε².
- No model or agent version, and no date for the API queries, appears in the text. The paper says later agent versions may differ (§6, p. 8).
- Artifacts: the abstract (p. 1), §1 (p. 2) and §3 (p. 2) say the code is released. The text contains no URL, so artifacts is recorded as not stated.
- Unexplained counts (reader's arithmetic). 26,283 merged PRs in the 90-day analysis (§4.3, p. 5) against 27,090 merged in Table 1 (p. 3): 807 apart, not explained. 37,623 minus the 30,721 submitted to enrichment (§3.2, p. 3) leaves 6,902 PRs not submitted, not explained. The n column of Table 2 matches a Table 1 column only for Cursor (946, Enrich.): Codex 17,756 against 17,761 enriched and 18,004 merged; Claude Code 267 against 271 merged; no human n is given.

## Discrepancies

- D1 · §3.2 (p. 3) and Figure 1 give 29,730 PRs enriched (96.8% of 30,721 submitted). The Enrich. column of Table 1 (p. 3) totals 27,846 (reader's arithmetic). Both cannot be the enriched set.
- D2 · §6 (p. 8) says "Codex contributes 58% of agent PRs". Table 1 gives 21,799 of 33,596 agent PRs, which is 64.9% (reader's arithmetic). The 58% is 21,799 of all 37,623 PRs, which includes the human PRs (57.9%, reader's arithmetic).
- D3 · §4.4 (p. 6) and §5 (p. 7) say "a fourfold spread" between products on hardcoded credentials. The values on p. 6 are 3.3% (Claude Code) and 0.5% (Codex, Cursor), a ratio of 6.6 (reader's arithmetic).
- D4 · §5 (p. 7) says the same far-wider-than-pooled pattern "holds for ... review latency". §3.4 (p. 4) says the review tables do not cover the human sample, and §4.5 (p. 6) compares agents only. The paper reports no human review latency, so no agent-human latency gap exists to compare.
- D5 · §4.5 (p. 7) says Claude Code PRs are "an order of magnitude larger". Table 1 medians are 495 against 52 to 96 for the other groups, a ratio of 5.2 to 9.5 (reader's arithmetic). §5 (p. 7) says "about eight times", which sits inside that range.
